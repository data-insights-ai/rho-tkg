# SPEC: Token Internment, Snowflake IDs & Pure Data Structs

## Final Technical Specification

**Date:** 2026-02-16
**Version:** 1.2 (Final)
**Status:** Approved for Implementation
**Breaking Change:** Yes — Major version bump required
**Migration:** None — existing data will be regenerated

---

## 1. Overview

This specification replaces string-based entity IDs, labels, and relationship types with compact internal representations: snowflake `int64` for entity IDs and `uint16` tokens for labels and relationship types. All internal types are unexported. Users interact exclusively through string-based public APIs.

A core architectural decision: **Node and Relationship are pure data structs with no back-references to the graph.** String resolution for labels and types is performed exclusively by the Graph layer or Cypher engine, which own the registries.

**Goals:**
- Reduce per-node structural overhead from ~73B to ~18B (75% reduction)
- Reduce per-relationship structural overhead from ~102B to ~26B (75% reduction)
- Achieve fixed-width Badger keys for all indexes (byte-comparable, no string parsing)
- Globally unique, time-ordered IDs without coordination (distributed-safe)
- Entities are self-contained, safely serializable, cacheable, and testable without mock infrastructure
- Align with industry standard (Neo4j, Memgraph, Dgraph) for internal ID/token patterns
- Strengthen paper numbers: non-temporal node 0.47x Neo4j on disk (was 0.60x)
- Stable enterprise API: no breaking changes after v1.0

**Non-Goals:**
- Backward compatibility with existing Badger data (data will be regenerated)
- Exposing internal IDs to users in any form

## 2. Internal Types

Four unexported types in `pkg/types`:

```go
type nodeID       int64   // snowflake-generated, globally unique, time-ordered
type relID        int64   // snowflake-generated, globally unique, time-ordered
type labelToken   uint16  // interned label string, max 65,535 distinct labels
type relTypeToken uint16  // interned type string, max 65,535 distinct types
```

**Constraints:**
- All four types are unexported — no public API accepts or returns them
- `nodeID` and `relID` are generated by snowflake nodes, globally unique without coordination
- `labelToken` and `relTypeToken` are assigned by their respective registries on first occurrence
- Token value 0 is reserved as "unset/invalid" — registries start assignment at 1

## 3. Snowflake IDs

### 3.1 Why Snowflake Instead of Atomic Counters

| Property | Atomic counter | Snowflake |
|----------|---------------|-----------|
| Globally unique | No (per-process only) | Yes (node ID embedded) |
| Distributed-safe | No (collision on multi-instance) | Yes (no coordination) |
| Time-ordered | No (arbitrary sequence) | Yes (41-bit ms timestamp) |
| Crash recovery | Required (scan max key) | Not needed (stateless generation) |
| Counter persistence | Required (`meta/next_node_id`) | Not needed |
| Temporal locality in LSM | No (random distribution) | Yes (recent IDs cluster — better Badger compaction) |
| Decomposable | No | Yes (extract creation time, node, sequence) |

### 3.2 Configuration

```go
import snowflake "github.com/bds421/rho-snowflake-2026"

// Graph holds two snowflake generators — one for nodes, one for relationships.
// Separate generators avoid ID collisions between entity types.
type Graph struct {
    nodeIDGen *snowflake.Node
    relIDGen  *snowflake.Node
    // ...
}

func NewGraph(config Config) (*Graph, error) {
    nodeGen, err := snowflake.NewNode(config.SnowflakeNodeID,
        snowflake.WithEpoch(time.Date(2026, 1, 1, 0, 0, 0, 0, time.UTC)),
        snowflake.WithNodeBits(10),  // 1024 nodes (default)
        snowflake.WithStepBits(12),  // 4096 IDs/ms/node (default)
    )
    if err != nil {
        return nil, fmt.Errorf("node ID generator: %w", err)
    }

    relGen, err := snowflake.NewNode(config.SnowflakeNodeID,
        snowflake.WithEpoch(time.Date(2026, 1, 1, 0, 0, 0, 0, time.UTC)),
    )
    if err != nil {
        return nil, fmt.Errorf("rel ID generator: %w", err)
    }

    return &Graph{
        nodeIDGen: nodeGen,
        relIDGen:  relGen,
        // ...
    }, nil
}
```

### 3.3 ID Generation

```go
func (g *Graph) nextNodeID() nodeID {
    return nodeID(g.nodeIDGen.Generate().Int64())
}

func (g *Graph) nextRelID() relID {
    return relID(g.relIDGen.Generate().Int64())
}
```

- Thread-safe: snowflake.Node handles internal synchronization
- 4096 IDs per millisecond per generator (default)
- ~69 years of range from epoch (2026-01-01 -> ~2095)
- No persistence of counters needed — each generated ID is unique by construction

### 3.4 What Gets Eliminated

The following are **removed** compared to the atomic counter design:

```
meta/next_node_id  -> REMOVED (no counter to persist)
meta/next_rel_id   -> REMOVED (no counter to persist)
```

No crash recovery logic for counters. No max-key scan on startup. The startup sequence is simpler (see section 13).

### 3.5 Badger Key Ordering

Snowflake IDs are roughly time-ordered (41-bit timestamp in the high bits). When stored as big-endian int64 in Badger keys, this means:

- Recently created entities cluster together in the LSM tree
- Prefix scans over recent data hit fewer SSTables
- Compaction is more efficient (temporal locality)

This is a free performance benefit from the ID structure — no additional work needed.

### 3.6 Graph Configuration

```go
type Config struct {
    // SnowflakeNodeID identifies this graph instance (0-1023 with default 10-bit node).
    // Each concurrent graph instance MUST use a different SnowflakeNodeID to
    // guarantee globally unique IDs. For single-instance embedded use, 0 is fine.
    SnowflakeNodeID int64

    // ... other config fields
}
```

## 4. Core Architectural Principle: Pure Data Structs

### 4.1 The Rule

**Node and Relationship never hold references to the Graph, registries, or any external resolver.** They are pure data containers that hold tokens internally and never resolve them to strings themselves.

String resolution is **always** the responsibility of the layer that owns the registry: the Graph layer, the Cypher engine, or the REST/gRPC serialization layer.

### 4.2 Rationale

For an enterprise application with no future breaking changes, entities must be:

| Property | Requirement | Pure data struct? |
|----------|-------------|-------------------|
| Self-contained | No hidden initialization state | Yes |
| Safely serializable | Serialize/deserialize without losing capability | Yes |
| Safely cacheable | Can outlive any graph reference | Yes |
| Safe across goroutines | No hidden shared state | Yes |
| Testable standalone | Token-level methods work without mock graph | Yes |
| Plugin/extension safe | Third-party code doesn't need injection ceremony | Yes |

An injected resolver (e.g., `SetGraph()`) violates all six properties. A node that looks complete but silently returns empty strings when the resolver is missing is a latent bug that surfaces when someone deserializes, caches, or passes nodes across package boundaries.

### 4.3 Resolution Ownership

There are exactly three consumers that need string labels/types. All three already have registry access:

| Consumer | Has registry? | Resolution method |
|----------|--------------|-------------------|
| **Graph layer** | Yes (owns registries) | `graph.NodeLabels(n)`, `graph.RelType(r)` |
| **Cypher engine** | Yes (holds graph ref) | `graph.ResolveNodeProperty(n, key)` |
| **REST/gRPC API** | Yes (holds graph ref) | `graph.NodeLabels(n)` before JSON encoding |

All internal operations — index lookups, label matching, adjacency traversal, hash computation — work with tokens directly. String resolution is a **presentation concern**, not a data concern.

## 5. Entity Structs

### 5.1 Node

```go
type Node struct {
    id           nodeID           // snowflake int64, unexported
    primaryLabel labelToken       // unexported, always set (nodes require >=1 label)
    extraLabels  []labelToken     // unexported, nil for single-label nodes (99% case)
    Properties   PropertySlice    // sorted []Property
    Temporal     *TemporalMetadata
    Integrity    *NodeIntegrity   // SHA-256 hash chain
    Version      int              // monotonic version counter
    // NO graph field — pure data struct
}
```

**Token-level methods (always work, no resolver needed):**

```go
func (n *Node) PrimaryLabelToken() labelToken
func (n *Node) ExtraLabelTokens() []labelToken
func (n *Node) HasLabelToken(tok labelToken) bool
func (n *Node) LabelTokenCount() int
func (n *Node) AllLabelTokens() []labelToken
func (n *Node) InternalID() nodeID
```

**Property methods:**

```go
func (n *Node) GetProperty(key string) (any, bool)        // linear scan
func (n *Node) SetProperty(key string, value any) error    // binary search insert, rejects tkg_ prefix
func (n *Node) Properties() PropertySlice                  // zero-alloc direct access
func (n *Node) PropertiesMap() map[string]any
```

**No string-level label methods on Node.** String resolution is on the Graph layer (see section 7).

### 5.2 Relationship

```go
type Relationship struct {
    id         relID            // snowflake int64, unexported
    relType    relTypeToken     // unexported, exactly one type
    startID    nodeID           // unexported
    endID      nodeID           // unexported
    Properties PropertySlice
    Temporal   *TemporalMetadata
    Integrity  *RelIntegrity
    Version    int
    // NO graph field — pure data struct
}
```

**Token-level methods:**

```go
func (r *Relationship) TypeToken() relTypeToken
func (r *Relationship) HasTypeToken(tok relTypeToken) bool
func (r *Relationship) StartNodeID() nodeID
func (r *Relationship) EndNodeID() nodeID
func (r *Relationship) InternalID() relID
```

**Property methods:** Same as Node — `GetProperty`, `SetProperty` (with `tkg_` rejection), `Properties`, `PropertiesMap`.

## 6. Registries

Two independent registries with independent token namespaces. A label `"KNOWS"` and a relationship type `"KNOWS"` receive independent tokens in their respective registries.

### 6.1 Label Registry

```go
type labelRegistry struct {
    mu        sync.RWMutex
    toToken   map[string]labelToken  // "Person" -> 1
    toLabel   []string               // [0]="" (reserved), [1]="Person", ...
    nextToken labelToken             // starts at 1
}
```

| Method | Lock | Description |
|--------|------|-------------|
| `GetOrCreate(string) labelToken` | Write (on miss only) | Returns existing or creates new |
| `Resolve(labelToken) string` | Read | Token -> string |
| `ResolveAll([]labelToken) []string` | Read | Batch resolve |
| `Lookup(string) (labelToken, bool)` | Read | Check existence without creating |

### 6.2 Relationship Type Registry

```go
type relTypeRegistry struct {
    mu        sync.RWMutex
    toToken   map[string]relTypeToken  // "KNOWS" -> 1
    toName    []string                  // [0]="" (reserved), [1]="KNOWS", ...
    nextToken relTypeToken             // starts at 1
}
```

Same method signatures as label registry, with `relTypeToken`.

### 6.3 Thread Safety

- `GetOrCreate`: Read lock first. On miss, upgrade to write lock with double-check.
- `Resolve`, `ResolveAll`, `Lookup`: Read lock only.

### 6.4 Growth Warning

Both registries log a warning via `slog.Logger` when token count exceeds 60,000 (92% of uint16):

```
[tkg] WARN | Label registry approaching capacity: 60001/65535 tokens
[tkg] WARN | Relationship type registry approaching capacity: 60001/65535 tokens
```

Informational only. `GetOrCreate` returns an error at the uint16 limit.

### 6.5 Persistence (Badger)

```
meta/label_tokens    -> msgpack([]string)    // index = labelToken value
meta/reltype_tokens  -> msgpack([]string)    // index = relTypeToken value
```

Updated atomically when a new token is registered.

## 7. Graph Layer: String Resolution

The Graph layer is the **sole owner** of string resolution.

### 7.1 Label Resolution

```go
func (g *Graph) NodeLabels(n *Node) []string
func (g *Graph) NodePrimaryLabel(n *Node) string
func (g *Graph) NodeHasLabel(n *Node, label string) bool
```

### 7.2 Type Resolution

```go
func (g *Graph) RelationshipType(r *Relationship) string
func (g *Graph) RelationshipHasType(r *Relationship, typ string) bool
```

### 7.3 Property Resolution (Shadow Properties)

```go
func (g *Graph) ResolveNodeProperty(n *Node, key string) (any, bool)
func (g *Graph) ResolveRelProperty(r *Relationship, key string) (any, bool)
```

Both dispatch on `tkg_` prefix: shadow keys resolve via the appropriate switch statement; user keys delegate to `PropertySlice.Get()`.

## 9. Serialization

### 9.1 Msgpack Wire Formats

```go
type nodeWire struct {
    ID           int64 `msgpack:"id"`            // snowflake, fixed 8B
    PrimaryLabel int   `msgpack:"pl"`            // varint (1-3B)
    ExtraLabels  []int `msgpack:"el,omitempty"`  // omitted when nil
    Properties   []propertyWire `msgpack:"p,omitempty"`
    Version      int   `msgpack:"v"`
    // temporal fields (omitted when no temporal metadata):
    HasTemporal  bool    `msgpack:"ht,omitempty"`
    ValidFrom    int64   `msgpack:"vf,omitempty"`
    ValidTo      int64   `msgpack:"vt,omitempty"`
    TxFrom       int64   `msgpack:"tf,omitempty"`
    TxTo         int64   `msgpack:"tt,omitempty"`
    CreatedAt    int64   `msgpack:"ca,omitempty"`
    UpdatedAt    int64   `msgpack:"ua,omitempty"`
    DeletedAt    int64   `msgpack:"da,omitempty"`
    CreatedBy    string  `msgpack:"cb,omitempty"`
    UpdatedBy    string  `msgpack:"ub,omitempty"`
    BaseEntityID int64   `msgpack:"be,omitempty"`
    // integrity fields (omitted when no integrity):
    Hash         string  `msgpack:"h,omitempty"`
    PrevHash     string  `msgpack:"ph,omitempty"`
}

type relWire struct {
    ID      int64 `msgpack:"id"`    // snowflake, fixed 8B
    RelType int   `msgpack:"rt"`    // varint (1-3B)
    StartID int64 `msgpack:"s"`     // snowflake, fixed 8B
    EndID   int64 `msgpack:"e"`     // snowflake, fixed 8B
    Properties []propertyWire `msgpack:"p,omitempty"`
    Version    int `msgpack:"v"`
    // same temporal + integrity fields as nodeWire...
}

type propertyWire struct {
    Key   string `msgpack:"k"`
    Value any    `msgpack:"v"`
}
```

### 9.2 Varint Behavior (Tokens Only)

| Token range | Bytes | Covers |
|-------------|-------|--------|
| 0-127 | 1B | First 127 labels/types |
| 128-255 | 2B | Up to 255 |
| 256-65535 | 3B | Full uint16 range |
| 65536+ | 5B | Future uint32 expansion |

IDs are always full int64 (8B in msgpack) — snowflake values use the full 63-bit range.

## 10. Badger Key Layout

All keys use fixed-width binary encoding. Snowflake IDs are stored as big-endian int64 (8 bytes) for correct sort order — which also provides temporal clustering since snowflake high bits are timestamps.

### 10.1 Primary Entities

| Key | Value | Key size |
|-----|-------|----------|
| `n/<8B nodeID>` | `msgpack(nodeWire)` | 9B |
| `r/<8B relID>` | `msgpack(relWire)` | 9B |

### 10.2 Label Index

```
l/<2B labelToken>/<8B nodeID>  -> empty     (10B key)
```

### 10.3 Relationship Type Index

```
rt/<2B relTypeToken>/<8B relID>  -> empty   (10B key)
```

### 10.4 Adjacency Indexes

```
out/<8B startNodeID>/<2B relTypeToken>/<8B endNodeID>/<8B relID>  -> empty  (26B)
in/<8B endNodeID>/<2B relTypeToken>/<8B startNodeID>/<8B relID>   -> empty  (26B)
```

Enables prefix scans:
- All outgoing from node X: `out/<X>/`
- All outgoing of type T from X: `out/<X>/<T>/`
- All incoming to node Y: `in/<Y>/`

### 10.5 History

```
h/n/<8B nodeID>/<8B version>  -> msgpack(nodeWire)
h/r/<8B relID>/<8B version>   -> msgpack(relWire)
```

### 10.6 Temporal Index

```
tv/n/<8B validFrom sortkey>/<8B nodeID>  -> empty
tv/r/<8B validFrom sortkey>/<8B relID>   -> empty
```

### 10.7 Metadata

```
meta/label_tokens    -> msgpack([]string)
meta/reltype_tokens  -> msgpack([]string)
```

**Note:** No `meta/next_node_id` or `meta/next_rel_id` — snowflake generation is stateless.

## 11. Cypher Engine Integration

### 11.1 Label Matching (resolve once per query)

```go
tok, exists := graph.labels.Lookup("Person")
if !exists {
    return emptyResult  // label never registered -> skip scan
}
// Per candidate: node.HasLabelToken(tok) — integer comparison
```

### 11.2 Label Disjunction (`:Person|Company`)

```go
toks := make([]labelToken, 0, 2)
for _, label := range []string{"Person", "Company"} {
    if tok, ok := graph.labels.Lookup(label); ok {
        toks = append(toks, tok)
    }
}
```

### 11.3 Type Matching

```go
tok, exists := graph.relTypes.Lookup("KNOWS")
if !exists { return emptyResult }
// Per candidate: rel.HasTypeToken(tok)
```

### 11.4 Property Access

```go
val, ok := graph.ResolveNodeProperty(node, "name")        // user property
val, ok := graph.ResolveNodeProperty(node, "tkg_labels")   // shadow property
```

### 11.5 Cypher `id()` Function

**Removed.** No user-accessible entity ID. Use property-based lookups:

```cypher
// REMOVED
WHERE id(n) = "user:alice"

// REPLACEMENT
WHERE n.external_id = "user:alice"
```

## 12. Public API

### 12.1 Node Creation

```go
// BEFORE (v0.9.x)
node := api.CreateNode("user:1", []string{"User"}, map[string]any{"name": "Alice"})
tkg.AddNode(node)

// AFTER (v1.0)
node, err := tkg.AddNode([]string{"User"}, map[string]any{"name": "Alice"})
// Snowflake ID assigned automatically, never exposed
```

### 12.2 Relationship Creation

```go
// BEFORE
rel := api.CreateRelationship("rel:1", "KNOWS", "user:1", "user:2", nil)

// AFTER — via Cypher
result, _ := tkg.ExecuteCypher(ctx, `
    MATCH (a:User {name: "Alice"}), (b:User {name: "Bob"})
    CREATE (a)-[:KNOWS]->(b)
`)
```

### 12.3 Node Retrieval

```go
// BEFORE
node, found := tkg.GetNode("user:1")

// AFTER — via Cypher or Graph API
result, _ := tkg.ExecuteCypher(ctx, `MATCH (n:User {name: "Alice"}) RETURN n`)

// Or programmatic:
nodes := graph.FindNodes("User", "name", "Alice")
```

## 13. Startup Sequence

```
1. Open Badger
2. Load meta/label_tokens    -> rebuild labelRegistry.toToken map
3. Load meta/reltype_tokens  -> rebuild relTypeRegistry.toToken map
4. Initialize snowflake generators (nodeIDGen, relIDGen)
5. Load entities into RAM cache (warm boot)
   - Deserialize nodeWire/relWire
   - Entities are complete after deserialization (no injection needed)
6. Ready
```

**Compared to atomic counter design:** Steps 4-5 of the old sequence (load counters, crash recovery scan) are eliminated. Snowflake generators are stateless — they start generating unique IDs immediately.

| All existing tests use string IDs | Every test file rewritten | Phase 4 dedicated to this |
| Cypher `id()` function removed | Queries using `id()` fail | Document, suggest property-based lookup |
| External tools reading Badger directly | Binary keys not human-readable | Provide debug dump utility |
| Registry corruption on crash | Tokens unresolvable | Append-only, persisted atomically |
| Snowflake clock skew | Potential ordering anomalies | Snowflake handles this internally (waits for clock catchup) |
| Two graph instances with same SnowflakeNodeID | ID collision | Document: each instance needs unique node ID |
| Third-party code calling node.Labels() | Method doesn't exist | Compile error (caught at build time) |

## 17. Decisions Log

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | `nodeID` = snowflake int64, unexported | Globally unique, time-ordered, no counter persistence, distributed-safe |
| 2 | `relID` = snowflake int64, unexported | Same as nodeID |
| 3 | `labelToken uint16`, unexported | 65K labels sufficient, 1-3B varint on disk |
| 4 | `relTypeToken uint16`, unexported | Same as labelToken |
| 5 | Separate label and type registries | Independent namespaces, no semantic confusion |
| 6 | Msgpack varint serialization for tokens | Future-proof to uint32+ without migration |
| 7 | Remove `tkg_id`, `tkg_start_id`, `tkg_end_id` shadow keys | Internal IDs not user-meaningful |
| 8 | 15 shadow keys | All resolve to user-meaningful metadata (structural, temporal, provenance, integrity, version chain) |
| 9 | No backward migration | Data regenerated, avoids migration complexity |
| 10 | Breaking API change accepted | Major version bump, clean API |
| 11 | Registry growth warning at 60K | Logged via slog, informational |
| 12 | `primaryLabel` + `extraLabels` split | Avoids allocation for 99% single-label case |
| 13 | Token 0 reserved as invalid | Zero-value detection without Option types |
| 14 | Snowflake replaces atomic counters | Eliminates counter persistence, crash recovery, enables distributed deployment |
| 15 | **Node and Relationship are pure data structs with no back-references** | Entities are self-contained, serializable, cacheable, testable. String resolution is a presentation concern owned by the Graph layer. |
| 16 | Snowflake epoch = 2026-01-01 | Matches project timeline, maximizes 69-year range |
| 17 | Separate snowflake generators for nodes and rels | Independent ID spaces, no cross-entity collision concern |
