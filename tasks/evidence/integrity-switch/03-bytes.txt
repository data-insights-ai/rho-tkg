# RHO_INTEGRITY_BYTES=1 go test ./pkg/graph -run 'TestIntegrityBytesPerEdge$' -count=1 -v
# Shape: 2,000 nodes (two properties), 20,000 relationships of four properties (pkg/graph/integrity_bytes_test.go).
# badger: every badger row read back after Flush; "snappy" compresses consecutive rel rows in 4 KiB blocks as an
# SST block is (ai-soc runs Snappy). memory: heap growth of the memory store per edge (GC'd HeapAlloc).

## Where the bytes go (traced in code, main 490e29c1)
- computed: core relationship_create_kernel.go:153 (rel content hash), the endpoint hashes copied from the endpoint
  node rows at create (relationship_create_kernel.go:168-169, spec.fromHash/toHash), node_add.go:186 (node hash);
- written: storeutil/wire_encode.go:172-178 (node h, ph) and :382-399 (rel h, ph, fnh, tnh), each a 64-hex string:
  1 B fixstr key + 2 B str8 header + 64 B = 66-68 B a hash; a first-version relationship row carries three
  (h, fnh, tnh) = 208 B raw. Hex does not compress except where nearby rows share an endpoint hash.
- resident (memory store): first versions are compact (types/compact.go): the rel hash already 32 raw bytes, the
  endpoint hashes shared strings with the node rows; updated/history versions keep RelIntegrity with hex strings.
  badger keeps no row hash resident beyond its row cache.
- ai-soc's 232 B/edge (tasks/edge-data-profile.md, ai-soc) is the disk row: h + fnh + tnh after Snappy.
