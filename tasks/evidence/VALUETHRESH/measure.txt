VALUETHRESH step 1 (ai-soc R3): ReplaceVersion of 100 KB page rows, badger's default ValueThreshold (1 MB,
options.go:170 in badger v4.9.2) against 64 KB. Measured 2026-11-03 on the shared machine (32 cores, /tmp ext4 NVMe),
runs alternated, load average printed before each pair.

Probe: probe_test.go.txt (pkg/graph, build tag valuethreshprobe) with probe_hook.go.txt and probe_hook.diff.txt (an unexported
valueThresholdProbe in buildBadgerOptions, set from RHO_VALUETHRESH under the tag; not committed as code).
Shape: 64 Page rows (a reference label on tiered), each 4 properties of 25 KB of JSON-like text (2,048-word
dictionary, compressible about 2.6x by badger's Snappy/s2) plus ov_k, ov_h3 (on-disk property indexes, ov_h* valid
end, sigma's shape) and pages; change log on; 150 rounds of ReplaceVersion over all 64 = 9,600 replaces, about
940 MB of rows, each replace writing current row + history row + change-log record (~2.8 GB to badger).
CPU = getrusage over the write phase, a 10 s settle (compactors keep running) and Close; the CPU profile covers
the same window. Reads after Close + reopen: "cold" = rho caches and badger block cache empty (OS page cache warm,
no root to drop it), "warm" = the same reads again. Get's warm read is rho's node cache; NodeAsOf reads history
from badger every time.

Findings
- Clear gain: compaction CPU 18.9 s -> 0 and s2 encode 31.3 s -> 0; process CPU 88-104 s -> 7-9 s (-90 %);
  write throughput 1.1-2.3x (wall is noisy at load 10-20; CPU is not). No read regression: cold Get 4-20x faster,
  NodeAsOf 1.5-5x faster.
- Cost: disk. The value log is not compressed: 2,972 MB against 1,068-1,105 MB of Snappy tables for this
  2.6x-compressible text (2.7x the space). For incompressible blobs the two would be about equal.
- The value-log GC reclaims nothing on this shape: of the three values a replace writes, the history row and the
  change-log record stay live for good (docs/badger.md rule 9: a value kept by history is never garbage), so at
  most a third of a file is garbage, below the 0.5 discard ratio; and the LSM of 24-byte pointers rarely compacts,
  so the replaced current rows reach the discard statistics late. Space grows with every replace either way; with
  the threshold it grows uncompressed.
