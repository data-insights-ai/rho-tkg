## Do the existing *OnDisk modes fix it? No.

Same store, LabelIndexOnDisk + AdjacencyIndexOnDisk + PropertyIndexOnDisk (second open, backfill done):
open 13.6 s (node decode 2.8, rel decode+stats 6.4, property index 3.1 s: disk mode still loads and
decodes every labelled node and discards it). Plus DisablePlannerStats: 11.0 s.
Every mode decodes every current row at open, so a default change cannot make the open
O(index state); a default change would also be caller-visible (deprecation ritual).

## Conclusion for the design

Everything except planner stats and property-index values is already in persisted keys
(entity keys, 0x03..0x06). The open can read keys only when it can trust that keys and rows
agree, i.e. after a clean Close; property-index values need persisting; planner stats can be
built from the rows on first use instead of at open.
