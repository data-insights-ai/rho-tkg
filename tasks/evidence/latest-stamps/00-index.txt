Backlog 30 — Nodes().LatestStamps / Rels().LatestStamps (evidence index, 2026-10-10)

Decisions
- txFrom = max TxFrom over all rows (current row + every history row).
- txTo = max over all rows of max(TxTo, DeletedAt); 0 when no row was ended
  (a tombstone's DeletedAt counts even where TxTo is unset; core-written
  tombstones carry TxTo == DeletedAt).
- deleted = the entity has rows but no current row. A re-imported ID whose
  newest life is live reads false; an ID without any row is
  ErrNodeNotFound / ErrRelNotFound.
- Semantics = the fold of Get + History at every moment (compaction, purge and
  erasure remove rows from both).
- Structure: the current row is lent (O(1), new zero-alloc TxStamps accessor);
  only the history half is a sidecar (store.HistoryStampsCapability). A mirror
  of the current row in the sidecar was not built: a plain ReplaceNode
  (UpdateInPlace, rollback restore, replica apply) can LOWER the current
  row's stamps, which a running max cannot express (lesson 57), while the row
  itself is an exact O(1) source on every backend.
  memory: per-ID cache keyed to the ID's history row count, kept at the one
  history-row seam (putNodeHistoryRowLocked / putRelHistoryRowLocked);
  removals need no hook (the count falls).
  badger: sidecar beside the presence set, its protocol (lazy build reading
  each history value's temporal fields, tracking under wbMu, maintained at
  noteHistoryKey, per-ID unknown + stamp guard, Clear reset under buildMu).
  tiered: the History shard walk (generic, shared with HasHistory), cold
  shards per ID; two or more shards with rows -> fold GetNodeHistory itself
  (it keeps one copy per version; exact, paid only by multi-shard history);
  sharded: slot.
