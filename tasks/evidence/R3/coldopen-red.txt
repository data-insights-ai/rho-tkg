== 2a. Tried and rejected: the lazy label map of LabelIndexOnDisk for a transient read-only handle
The only lazy label map in the code is LabelIndexOnDisk's (a trusted image with the per-label counts opens without the label-key
walk). Setting it on the read-only cold handle at MaxOpenColdShards 0 (cfg.LabelIndexOnDisk = true in the cold read config) builds no
map at open, but every door gated on `!bs.labelOnDisk` declines on such a handle (ForEachDocValues, DocValuesSnapshot, the multi-label
columns, the columnar scan: "membership not materialized in RAM -> fall back"), and tiered's ForEachDocValues declines as a whole when
one shard declines, so one cold shard took the fast path from every hot shard of the query. go test -short ./pkg/graph/store/tiered/
with that setting:
--- FAIL: TestTieredDocValues_ColdShardParticipation (0.91s)
    tieredstore_docvalues_test.go:389: ForEachDocValues declined; want usable
Not used. Instead 2b: the same lazy open (no walk, counters from the image) with the maps kept in RAM mode and built per label on first
use (badger.Config.TransientRead), so every door that reads the maps keeps working.
