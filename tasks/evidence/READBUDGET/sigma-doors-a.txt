READBUDGET / R2 Sigma budgeted read doors, group A (13 Nov): red evidence, what is counted, results

Red method: each new Ctx door first existed as a thin wrapper that checks ctx, counts the candidates (one per ID, or the
matches the core can count) and calls the plain door, with no metering below it. Under that form the new tests were red;
every failure is the plain door doing the work the budget should have bounded. The metering was then added.
Counts only: never MemStats or time.

What is counted (green):
  Candidates   RAM adjacency: len of the node's out (or in) set before the list is built (a typed read examines the whole
               set: 40 for 30 typed + 10 other); on-disk adjacency (AdjacencyIndexOnDisk): each iterator entry and each
               pending add, before it is collected; sharded: the same per shard before its rows are read, every shard asked;
               tiered: the node's shard, and for a reference node each event shard's mint legs; memory and wrappers: the
               node's degree before the read (DegreeCapability), else the rows after.
  DecodedBytes each row decoded on a cache miss (badger prefetchRelTallied; sharded GetRelationshipsByIDsMetered per shard;
               tiered: the node's shard, the mint rows through a metered shard read, an incoming read's cross-shard
               resolver getUniqueRelationshipsByIDs under the tally).
  ShardOpens   tiered: the node's shard (shardForNodeIDReadCharged), each mint event shard (forEachMintShardCharged, which
               stops once the meter refused) and the cross-shard row resolver, before the open.
GREEN: same command, all pass. Budget 1 over 96 entries on the on-disk adjacency visits 2 entries (outgoing and incoming); a
budget of 1 on candidates or decoded bytes over hubs of 8, 32 and 128 (flushed, badger sharded tiered) refuses with the typed
