R2 budgeted read doors for Sigma, group C (ai-soc RH list R2, 13 Nov): Nodes().HistoryCtx, Rels().HistoryCtx,
Nodes().GetCtx, Temporal().NodeAtCtx, Temporal().RelsLowestAnsweredPinsCtx.
Counts only (rows decoded, history looked at, shard opens, rows the plain door read): never MemStats or time.
Backends: badger, sharded, tiered (rbdBackends; pending and flushed) and, through the public API, memory.
Red method as groups A and B: each Ctx door first existed as a thin wrapper that checks ctx, counts the candidate
and calls the plain door, with nothing counted below it; the new tests were red on that form, then the metering was added.

=== GROUP 3: Temporal().RelsLowestAnsweredPinsCtx (and the correction of NodesLowestAnsweredPinsCtx) ===

Finding first. The group B note says NodesLowestAnsweredPinsCtx "reads no row (the compaction boundaries and retention
watermarks are in memory)", so a ShardOpens or DecodedBytes budget never bounds it. Read from the source it is true only
without a retention watermark: with one, nodeRetentionFloor reads the node's current row for its labels and, for a deleted
node, its whole history (retention.go nodeLabelTokensForRetention); relTypeRetentionFloor does the same for a
relationship's type (retention_rel.go). ai-soc runs with AllowRetentionPurge. The twin could not honestly be built on the
node door's form, so both were tested against the form "candidates and buffer bytes, then the plain door".

Red (RelsLowestAnsweredPinsCtx stubbed to exactly NodesLowestAnsweredPinsCtx's form, which the Nodes door still had),
`go test -run 'TestReadBudget_SigmaC_LowestAnsweredPins' ./pkg/graph/internal/core`, 14 failing subtests, the nodes door
as red as the rels door:

Still open (found while checking, not fixed here): the retention gate's own row reads in the other budgeted point doors
(checkNodePointRetention and checkRelTypePointRetention, taken when the pin is below the retention maximum) go through the
store uncounted. Reproduced with a throwaway test (kept outside the repo; flushed badger, node of label L with watermark
at the pin and a second label's watermark above it, node row evicted):
  NodeAtTxCtx(node, pin, pin) under ReadBudget{DecodedBytes: 1} = row returned, error nil,
  work {Candidates:1 DecodedBytes:0 HistoryExamined:0}, and the node's row in the entity cache afterwards
(the gate decoded the row uncounted and the point read was then served from the cache). NodeAtCtx reads at pin 0, which
skips the gate, so the new door is not affected. The fix is the Rd form used here applied at those call sites
(nodeAtLockedTxRd, batched_attx.go, effective_timeline.go, effective_timelines.go, read_budget_timelines.go, txtime.go).
