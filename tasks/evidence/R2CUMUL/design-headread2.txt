### H1 fix now: the tiered token read opens no shard (R1)
Decision: avoid, not charge. A token is useful only while the handle that issued it stays open. If the shard
that holds the entity's history is closed when the token is asked, no kept entry can be valid, so the answer
"no token" (0) is exact and free.
Where: tiered routing gets a read mode that never opens (routeNodeShard, routeRelShardFor:
tieredstore_routing.go:455, :211; the candidate and probe checkouts use EventShard.checkoutStoreIfOpen,
tieredstore_lifecycle.go:479, which exists; a closed archive that the catalog lists counts as closed;
historyWalkWithArchive and historyWalkAnywhere take the same mode). A row not found on any open shard, or a
walked shard that is closed: nodeHistoryEpochCharged / relHistoryEpochCharged return (0, nil).
The presence read runs before the token on every head path and walks the same shards, so a shard that the cap
lets stay open is open by then: under the cap nothing changes.
Then remove what 6233da27 added for the charge: store.HistoryEpochMeteredCapability (capabilities.go:798-809),
the two Metered methods, Core.historyEpochsMetered (core.go:177-181, :2365-2367), nodeHistoryEpochRd and
relHistoryEpochRd; the four sites call nodeHistoryEpoch / relHistoryEpoch again. One token path.
store.HistoryEpochCapability's comment: 0 means no token now; the caller folds and keeps nothing (core already
reads 0 so: headLookup, effective_head.go:392; no facts, no fill).
Lifecycle rule: the new mode only skips opens; it adds no close and no state. Keep the pin, scope, late-write,
failed-replacement, close-fault and reopen tests green. If they cannot stay green, stop and keep 6233da27's
capability: it is correct, only dearer.

### First HasNodeHistory after open: list in "Not yet bounded"
