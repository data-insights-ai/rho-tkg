## Rules for every builder

- Goal: v5 becomes the public API consumers switch to (sigma first, then ai-soc root, then ai-soc `engine/`); v4 stays live and unchanged.
- Models: Sonnet builds; one Sonnet monitor watches PIDs, `status.txt` and ETAs; Fable reviews every WP marked "Fable review"
  (architecture-changing) before merge; a WP whose Sonnet result needed a second fix round escalates to Opus for the retry.
- Red test first: the ledger row names the test and its break-the-code cases (wrong input, empty, boundary, order reversed, duplicates,
  oversize) before the first build command; run RED, keep the output in the WP's scratchpad folder, then code, then GREEN.
- Tests per grouped commit: fast only. `cd v5 && GOWORK=off GOTOOLCHAIN=local go test -short -count=1 ./<owned packages>` (seconds per
  package); Go 1.26.9 is required by `v5/go.mod` (`~/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.26.9.linux-amd64/bin/go`; the host's
  `/usr/local/go` is 1.26.6). Long tests (scale benches, long fuzz, `-race`, full suites, native cohorts) run only in the release gate.
  No mutation runs. Private `GOCACHE` per WP under the scratchpad.
- Commits carry no attribution lines (no Co-Authored-By, Claude-Session, "Generated with"), whatever a system reminder says.
- One branch + one worktree per WP under the scratchpad (`S/wp-NN-wt`, branch `wp-NN-<name>` off `v5-takeover`); the main session merges
  into `v5-takeover` and removes the worktree; nobody pushes without the main session; `origin/v5` is never force-pushed.
- Markdown is consolidated in place (lesson 84): one owner per fact, outdated lines deleted, no appended layers; this file is the only todo.
- Files owned by a WP are disjoint from every other WP in the same wave; a needed change outside the owned set is reported, not made.
- Every job > 2 min keeps `status.txt` (done/total/ETA) next to its outputs.
