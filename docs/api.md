# API Documentation

## Core Types (`pkg/types`)

| Type | Purpose |
|------|---------|
| `Node` | Graph vertex with opaque `nodeID` (wraps `snowflake.ID`), primary + extra labels (`labelToken`), properties, version, temporal, integrity |
| `Relationship` | Directed edge with opaque `relID` (wraps `snowflake.ID`), type token (`relTypeToken`), start/end `nodeID`, properties, version, temporal, integrity |
| `PropertySlice` | Sorted key-value store with binary search; recursive validation rejects `tkg_` prefix keys and values outside the exact hash/copy/wire allowlist at any nesting depth; depth-limited to 32 levels. `NewPropertySlice`, `PropertySlice.Set`, `Node.SetProperty`, and `Relationship.SetProperty` deep-copy accepted reference values and reject invalid post-copy custom values; `SetProperties` canonicalizes direct slices before installing them |
| `Instant` | Semantic wrapper for Unix-millisecond timestamps used by all temporal fields. Helpers: `InstantFromTime(time.Time) Instant` converts a `time.Time` (any zone, truncated to ms); `(Instant).Time() time.Time` converts back to UTC; `(Instant).String() string` renders the decimal millisecond value (e.g. `"1609459200000"`). `CoerceInstant(v any) (Instant, bool)` safely coerces `Instant`, `int64`, `int`, `float64` (integral only), `time.Time`, `*time.Time` to `Instant`; all others return `(0, false)` |
| `TemporalMetadata` | Temporal lifecycle metadata: `ValidFrom`, `ValidTo`, `TxFrom`, `TxTo`, `CreatedAt`, `UpdatedAt`, `DeletedAt` (all `Instant`), `CreatedBy`, `UpdatedBy` (`string`), `BaseEntityID` (`snowflake.ID`) |
| `NodeIntegrity` / `RelIntegrity` | Hash-chain integrity: `Hash`, `PrevHash` (`string`); `AuthorID` (`string`), `Signature` (`[]byte`) for caller-supplied provenance. `RelIntegrity` also carries `FromNodeHash` / `ToNodeHash` — hashes of the endpoint nodes at write time (not fed into `ComputeRelHash`) |
| `TimeGranularity` | 8-level granularity enum: `GranMillisecond`, `GranSecond`, `GranMinute`, `GranHour`, `GranDay`, `GranWeek`, `GranMonth`, `GranYear`. Functions: `TruncateInstant(t, gran)`, `RoundInstant(t, gran)`, `CeilInstant(t, gran)` |
| `AllenRelation` | Full 13-relation Allen's interval algebra: `Relate(aStart, aEnd, bStart, bEnd) (AllenRelation, error)`, `ComposeSets(rs1, rs2 AllenRelationSet) AllenRelationSet`. Constants: `Before`, `After`, `Meets`, `MetBy`, `Overlaps`, `OverlappedBy`, `Starts`, `StartedBy`, `During`, `Contains`, `Finishes`, `FinishedBy`, `Equals`. `AllenRelationSet` helpers mask out invalid relation bits |
| `RecurrencePattern` | Recurring time pattern: `Frequency` (`Daily`/`Weekly`/`Monthly`/`Yearly`), `Days` (`WeekdayMask`, bits Monday through Sunday only), `DayOfMonth` (1–28; 0 = last), `Month` (Yearly only; 0 defaults to January), `DayStart`/`DayEnd` (whole-millisecond durations from UTC midnight). `Validate()` rejects impossible calendar selectors and fractional-millisecond offsets; `Expand(from, to Instant) []Interval` emits concrete intervals within the window. Returns `types.ErrInvalidTimeRange` if `from >= to` |
| `HashableValue` | Interface (`HashBytes() []byte`) that custom property struct types implement to participate in node/relationship integrity hashing. Register the type via `RegisterPropertyStructType(v any)` with a zero value or typed pointer; untyped nil returns `ErrUnsupportedValueType` because it carries no type to register. Registered custom values persist/export as a registered type name plus MsgPack payload, value-vs-pointer shape is preserved across `DeepCopyValue`, and the wire path rejects MsgPack round-trips that change `HashBytes`. Treat `HashBytes` like a wire format — once any property of the type has been written, you cannot change the encoding without breaking every existing hash chain that contains the value. List registered types via `RegisteredPropertyStructTypes() []string`. |
| `NodeID` / `RelID` / `EntityID` | Typed wrappers around `snowflake.ID` (`type NodeID snowflake.ID`, etc.). Boundary accessor: `(NodeID).SnowflakeID() snowflake.ID`. `EntityID` is the type-agnostic wrapper used by `Event.EntityID`, `BatchError.ID`, `QueryOpts.After`, and `TemporalMetadata.BaseEntityID`. Zero-value semantics: literal `0` is the universal sentinel for "unset" across the API. |

Nil `*Node` and `*Relationship` accessors return zero values, no-error mutators no-op, and error-returning mutators return `ErrNilNode` / `ErrNilRelationship`. Nil `*PropertySlice` pointer mutators return `ErrNilPropertySlice`; nil `*TemporalMetadata` helpers and nil integrity `DeepCopy` calls return zero/nil.

Property equality helpers (`types.PropertyValueEqual`, `(*Node).PropertyValueEqual`, and `(*Relationship).PropertyValueEqual`) use exact-type property equality with NaN float values treated as equal, including inside supported nested property containers. The entity methods report existence plus equality without returning or copying the stored value. Scalar property-query keys use the same signed-zero and NaN equality for `float32` and `float64` values while keeping those concrete types separate.

Provenance and authorization shadow inputs accepted through props/updates are strict: `tkg_author_id` and `tkg_authorized_by` accept `string`, `tkg_signature` accepts `[]byte`, and `tkg_auth_level` accepts bounded signed/unsigned integer values plus whole-number `float32`/`float64` values. Non-nil values of the wrong type return an error before mutation. **Update-map provenance contract:** absence of a `tkg_author_id` / `tkg_signature` / `tkg_authorized_by` / `tkg_auth_level` key in an `Update` map preserves the corresponding stored value; presence overwrites it. A `nil` or zero-valued (`""`, `[]byte{}`, `0`) provenance value passed under a present key clears the stored field. There is no "absent" sentinel for these scalar fields — to leave provenance untouched, omit the key entirely. `UpdateInPlace`, label add/remove, property CAS, and `CloseVersion` do NOT accept provenance shadow keys (they reject every `tkg_` key via `ErrReservedPrefix`); existing provenance is always preserved on those paths.

Temporal shadow inputs accepted through props (`tkg_valid_from`, `tkg_valid_to`, `tkg_created_at`) accept `types.Instant`, signed integer milliseconds, unsigned integer milliseconds that fit in `int64`, and whole-number `float32`/`float64` milliseconds inside each float type's contiguous exact integer range.

## Graph Layer (`pkg/graph`) — v4.2 sub-API surface

`*graph.Graph` is a thin façade. Its only direct methods are `New(Config) (*Graph, error)`, `Close() error`, and 15 nil-safe sub-API accessor methods. Every sub-API is reached through its accessor method (v4.2.0 converted these from exported fields to methods):

Nil or zero-value graph façade entry points return nil for the sub-API (no panic). Calling a sub-API method on that nil receiver returns `ErrNilGraph` from error-returning methods and zero values from no-error helpers. Construct operational graphs with `graph.New`.

**Consumer-ergonomics aliases (v4.2.1/v4.2.2)**: `graph.QueryOpts = store.QueryOpts`, `graph.ShardDepth = store.ShardDepth`, `graph.DistanceMetric = store.DistanceMetric`; the entity-conflict sentinels `graph.ErrNodeExists` / `graph.ErrRelExists` and the index-existence sentinels `graph.ErrIndexExists` / `graph.ErrIndexNotFound` / `graph.ErrTemporalIndexExists` / `graph.ErrTemporalIndexNotFound` are all aliased on `pkg/graph` so consumers can avoid a dual `pkg/graph/store` import for `QueryOpts` configuration and `errors.Is` checks on the conflict and existence sentinels.

`Store` / `memory.Store` / `badger.Store` / `tiered.Store` types live in `pkg/graph/store{,/memory,/badger,/tiered}`. The Store interface is composed from capability sub-interfaces in `pkg/graph/store/capabilities.go` — the graph layer depends on `MandatoryStore` (Lifecycle, NodeCRUD, RelCRUD, Adjacency, BulkRead, Batch, History, Stats, Iteration). Delete batch methods coalesce duplicate IDs before validation and mutation. Lifecycle calls on nil concrete in-tree store receivers return `ErrNilStore` from `Close` and `Clear`; `graph.ErrNilStore` aliases the same store-layer sentinel. Iteration callbacks must be non-nil; open stores return `ErrInvalidStoreMutation` for nil `ForEach*ID` callbacks, while closed stores return `ErrStoreClosed` first. Non-nil `ForEach*ID` callbacks run outside backend locks and Tiered shard checkouts, so callbacks may call Store methods; Badger history iterators page IDs, overlay pending truncation deletes before async flush, and stop at the start high-water mark so callback-created higher history IDs do not extend the active iterator. Badger/Tiered registry save/load APIs reject nil registry pointers with `ErrInvalidStoreMutation` on open stores, while closed stores still return `ErrStoreClosed` first; `tiered.Store.SetLabelRegistry(nil)` is a no-op. Tiered `registry.msgpack` loads validate label and relationship-type slices before returning metadata, so deprecated single-registry save APIs cannot preserve a corrupt other half. Successful graph operations that allocate label or relationship-type tokens persist the updated registries to Badger/Tiered stores before returning, and import/transaction rollback persists restored registry snapshots. Batch post-write registry checkpoint failures surface through `BatchResult.Errors`; rows that were already written keep their finalized caller-visible node/relationship state. Transaction create/import methods record any row that already committed for rollback even when the method returns the checkpoint error, and `GraphTx.Commit` retries the registry checkpoint before making the transaction irreversible. `tiered.MigrateFromBadger(src, dst)` loads source registries itself, requires an empty destination, preflights migrated entity tokens and relationship endpoints, rolls back inserted destination entities and restores the previous destination registry file on failure, rejects nil stores, non-empty destinations, or missing source registry metadata for non-empty data with `ErrInvalidStoreMutation`, and returns `ErrStoreClosed` for closed source or destination stores. Optional capabilities (`DepthHistoryIterationCapability`, `DeletedIterationCapability`, `DepthDeletedIterationCapability`, `PropertyIndexCapability`, `TemporalIndexCapability`, `VectorIndexCapability`, `HighFrequencyIndexCapability`, `FilteredVectorSearchCapability`) are type-asserted at the call sites that need them. The graph layer falls back to label-scan + property filter for `g.Nodes().ByLabelAndProperty` when `PropertyIndexCapability` is absent (correctness, not just acceleration). `DeletedIterationCapability` (visit only IDs with history rows but no current row) is used by the adjacency-at-t fold inside `g.Temporal().OutgoingRelsAt`/`IncomingRelsAt`/`NeighborsAt`: implementations cap the fold at `O(deleted_count)` instead of `O(total history)`; stores that omit the capability transparently fall back to the wider history scan (correctness identical).

`Config.Store` may be omitted to select the default memory or configured Badger backend. If supplied, it must be a non-nil concrete Store value; typed nil Store interfaces are rejected by `graph.New` with `ErrNilStore`.

Store explicit entity IDs must be positive. Write methods reject non-positive entity identities with `ErrInvalidStoreMutation`: `PutNode`, `ReplaceNode`, and `PutNodesBatch` reject zero or negative node IDs; `PutRelationship`, `ReplaceRelationship`, and `PutRelationshipsBatch` reject zero or negative relationship IDs and zero or negative start/end node IDs before endpoint lookup or partial mutation. Direct read methods that take caller-provided entity IDs (`GetNode`, `GetRelationship`, `Get*ByIDs`, adjacency reads, `Get*Version`, `Get*History`, and `Truncate*History`) also reject zero or negative IDs with `ErrInvalidStoreMutation` before not-found, empty-history, or successful no-op handling; adjacency `typeToken == 0` is reserved only for "all relationship types". Badger split relationship helpers validate the same positive relationship ID/type/endpoint tuple before partial writes or deletes, and repair-only helpers (`PurgeOrphanRelationshipIndexes`, `DeleteIncomingByRelID`, `ScanAndDeleteIncoming`) reject zero or negative IDs before scanning or no-op cleanup. Atomic history replacements reject nil current/history payloads before dereference or marshaling. Store replacement methods preserve indexed identity. Changing a node's label tokens through `ReplaceNode` or `ReplaceNodeWithHistory` returns `ErrInvalidStoreMutation`; use label-token mutation methods for label changes. Plain Store `DeleteNode` and `DeleteNodesBatch` remove only unconnected node rows and return `ErrInvalidStoreMutation` without changing rows when any target node still has connected relationships; `DeleteNodeCascade` and `DeleteNodeWithHistory` are the connected-delete surfaces. Tiered `DeleteNodeCascade`, `DeleteNodesBatch`, and `DeleteRelationshipsBatch` restore earlier accepted relationship or node deletes when a later connected relationship delete, node bucket, same-shard relationship bucket, or cross-shard relationship split delete fails while the node row still exists. Tiered `DeleteNodeCascade` also purges stale adjacency entries whose relationship row is already missing while deleting the node. Label-token mutation methods validate that the supplied current node adds or removes exactly the requested token before changing label indexes or history. Changing a relationship's type token, start node, or end node through `ReplaceRelationship`, `ReplaceRelWithHistory`, `DeleteRelWithHistory`, or cascade tombstones returns `ErrInvalidStoreMutation`; relationship tombstones supplied to `DeleteNodeWithHistory` must cover every live connected relationship exactly once and must not include unrelated relationships. History snapshots must also carry the same entity ID as their storage key.

`memory.Store` has a usable zero value. Direct callers may use `var ms memory.Store`; reads return empty/not-found results, and writes, index creation, and history writes lazily initialize the internal maps before mutation. Zero-value `badger.Store` and `tiered.Store` are not operational backends, but lifecycle and checked read/write entry points return `ErrStoreClosed` instead of panicking on nil internal handles.

Badger fixed-width key scans are exact-length only. Restart rebuild, history ID scans, pending history overlays, per-entity history reads, and history truncation ignore overlong entity, index, adjacency, or history keys with valid prefixes instead of parsing the fixed prefix bytes into live IDs or history entries.

Badger delete methods prefetch cache-miss rows before taking the global index write lock, then re-read the current cached row under the lock before cleaning label, type, property, temporal, high-frequency, vector, and adjacency indexes. This keeps ordinary disk reads outside `idxMu.Lock` without using stale indexed metadata for cleanup.

In `SyncWrites` mode, Badger metadata and split relationship helper writeOps are part of the synchronous durability contract. Property, temporal, high-frequency, and vector index create/drop methods flush their queued definition update after releasing `idxMu`, and split relationship entity/out plus incoming-index helper methods flush before returning too.

Store index methods reject reserved label token 0 with `ErrInvalidStoreMutation`. This applies to property, temporal, high-frequency, and vector index create/drop/search operations, plus persisted Badger/Tiered index definitions loaded on open. Property/vector index targets and `NodesByLabelAndProperty` also reject reserved `tkg_` property keys with `types.ErrReservedPrefix`, because shadow properties are resolved by the graph layer and are not stored in `PropertySlice`. Tiered vector definition files are map-shaped by `(label, property)`: identical duplicate records are deduplicated, while conflicting duplicates return `ErrVectorIndexExists`. During phased Badger/Tiered index creates, the in-memory placeholder is visible only to concurrent write maintenance: Badger property, temporal, and high-frequency query fast paths ignore building placeholders and fall back to complete scans, while Badger/Tiered vector search returns `ErrVectorIndexNotFound` until vector create finalization. On `memory.Store`, public read/write/history/index/count/iteration operations return `ErrStoreClosed` after `Store.Close`, including empty fast paths; exported test-only tampering helpers return no data or no-op. On `badger.Store`, public read/write/history/index/metadata operations return `ErrStoreClosed` after `Store.Close`, including cache-hit reads, counters, empty fast paths, public `Flush`, and split relationship helpers. On `tiered.Store`, valid index create/drop/search calls, direct read/count/bulk/history APIs, empty batch/history write edges, and public admin/metadata operations return `ErrStoreClosed` after `Store.Close` starts before touching shard handles, store-level vector metadata, reference-shard read state, catalog metadata, or registry files. In-tree vector search paths also re-check close state after vector index scans/filter callbacks before returning empty or raw-ID results.

Tiered catalog loads validate persisted topology before reopening shard handles. Duplicate shard names, multiple hot event shards, invalid kind/tier combinations, unsafe relative paths, negative stats, and zero or inverted event windows are load errors.

Internal no-error index helpers are defensive at their own boundary: zero-value property indexes and high-frequency indexes lazily initialize their maps on first `Add`, zero-value LRU caches lazily initialize as minimum-capacity caches, and nil property, temporal, high-frequency, and vector cleanup/read helpers no-op or return zero/nil values. Nil vector writes/searches return `ErrInvalidVectorIndexConfig` because those paths have an error channel.

### Entity management

- `g.Nodes().Add(ctx, labels, props)` / `g.Nodes().Import(ctx, id, labels, props)` (caller-supplied ID; `0` returns `ErrZeroID`, negative IDs return `ErrInvalidID`). API 4.0: the previous separate `Add(labels, props)` and `Add(ctx, …)` collapsed into a single context-aware method.
- `g.Rels().Add(ctx, typeName, start, end, props)` / `AddByID(ctx, typeName, startID, endID, props)` / `AddByIDIfAbsent(ctx, typeName, startID, endID, props)` / `Import(ctx, id, typeName, start, end, props)`. Same `*WithContext` collapse applies (caller-supplied relationship import IDs use the same `ErrZeroID`/`ErrInvalidID` split).
- `g.Nodes().AddWithTx(ctx, labels, props, txFrom)` / `g.Rels().AddWithTx(ctx, typeName, start, end, props, txFrom)` (§4.1 transaction-time backfill). Creates the entity exactly like `Add` but stamps the caller-supplied `txFrom` as its `TxFrom` (Erkenntniszeit / knowledge time) instead of the system clock, so a re-ingest reproduces a documented historical state addressable via `AS OF SYSTEM TIME`. Requires the graph to be opened with `Config.AllowTxBackfill` — otherwise `ErrTxBackfillDisabled`; `txFrom` must be a positive instant not in the future (`ErrInvalidTxFrom` — a knowledge time cannot exceed wall-clock at write). Equivalent to passing the reserved `tkg_tx_from` property to any create door (node/rel `Add`/`Import`, batch create) under the gate. Backfill is CREATE-only — updates/deletes keep the monotonic system `TxFrom`; `TxFrom` is not hashed, so a backfilled row still passes `Verify*Chain` and replicates verbatim.
- `g.Nodes().Update(ctx, id, updates)` / `g.Rels().Update(ctx, …)`. Update maps accept provenance/authorization shadow keys, reject other `tkg_` keys, and validate malformed keys/values before entity locks or transaction rollback snapshots.
- `g.Nodes().UpdateInPlace(ctx, id, updates)` and rel mirror. In-place updates mutate without a version bump or history entry — for correcting metadata.
- `g.Nodes().Delete(ctx, id)` (cascade). Node delete uses a two-phase lock: it reads adjacency, locks the node and connected relationships, re-reads the node plus adjacency under that full lock, then writes tombstone history through `DeleteNodeWithHistory`. Cascaded relationship rows count toward relationship delete stats and emit `EventRelDelete` before the final `EventNodeDelete`. `g.Rels().Delete(ctx, id)`.
- `g.Nodes().AddLabel(id, label)` / `RemoveLabel(id, label)` (`ErrLastLabel` if it is the only label, `ErrLabelNotFound` if not present). Empty, whitespace-only, or overlong label names return `ErrEmptyName`/`ErrNameTooLong` before node lookup, registry lookup, or transaction snapshots. `AddLabel` checks `MaxLabelsPerNode` before creating a token for a previously unseen label. Node create/import/add-label paths restore newly allocated label tokens when the final Store write fails.
- Relationship creation (`g.Rels().Add`, `AddByID`, and `AddByIDIfAbsent`) rejects empty, whitespace-only, or overlong type names before endpoint lookup or property validation. Direct create paths fetch live endpoints under endpoint locks, capture `FromNodeHash`/`ToNodeHash`, run temporal constraints before allocating a token for a previously unseen relationship type, and restore newly allocated type tokens when the final Store write fails. `g.Rels().AddByID*` only changes the endpoint input form; it does not weaken endpoint verification or integrity metadata.
- Batch creation validates at queue time but defers new label/type token allocation until `Execute`. Returned node/relationship pointers use non-zero probe tokens for unseen names and are retokenized in place before persistence. Batch update queues deep-copy caller update maps. Failed or panicking node/relationship writes restore newly allocated registry entries and queue-time pointer state.
- Versioned mutation overflow: node/relationship updates, node label add/remove, node/relationship property CAS, transaction updates, and batch updates return `ErrVersionOverflow` if the current entity version is already `math.MaxUint32`; no history entry or wrapped version is written.

### Properties

- `g.Nodes().SetProperty(id, key, value)` / `DeleteProperty(id, key)` / `g.Rels().SetProperty(...)` / `DeleteProperty`. Setters deep-copy accepted reference values before storing them.
- `g.Nodes().CompareAndSetProperty(id, key, expected, newVal)` / `CompareAndSetProperty(...)` and `g.Rels().CompareAndSetProperty(...)` / `CompareAndSetProperty(...)` — atomic CAS. Returns `(true, nil)` on match+update, `(false, nil)` on mismatch, `(false, error)` on real error. `expected == nil` means "must not exist"; `newVal == nil` means "delete". Comparison uses exact-type property equality (`int(42) != int64(42)`) with NaN float values matching NaN, without returning or copying stored reference values. Matched mutations recheck `MaxPropertiesPerEntity` before persistence; successful CAS bumps version, writes history, updates temporal metadata.

### Resolution

- Label/type helpers: `g.Nodes().Labels(n)`, `g.Nodes().PrimaryLabel(n)`, `g.Nodes().HasLabel(n, label)`, `g.Rels().Type(r)`, `g.Rels().HasType(r, typ)`.
- Shadow-property resolution (21 `tkg_*` keys): `g.Resolve().NodeProperty(n, key)`, `g.Resolve().RelProperty(r, key)`.
- Registry token helpers (`LabelToken`, `RelTypeToken`, `LookupLabel`, `LookupRelType`) were removed in v4 — they leaked the internal `uint16` token representation. Use the name-based helpers above (`HasLabel`, `HasType`) and shadow-property resolution for read access. Boolean name helpers acquire the graph read lock before reading registry state, wait behind active transactions and import replay, and return zero values after `Close`.
- Internal label and relationship-type registries have usable zero values: they lazily reserve token 0, report length 0 before allocation, export `[]string{""}`, import persisted names, and allocate token 1 first. Graph-level users still go through `g.Resolve` / `g.Nodes` / `g.Rels`.

### Reads

- Single-entity: `g.Nodes().Get(id)` / `Get(ctx, id)` / `g.Rels().Get(id)` / `Get`.
- Bulk: `g.Nodes().GetByIDs(ids)` / `g.Rels().GetByIDs(ids)` (sorted ascending; zero/negative IDs return `ErrInvalidStoreMutation`; any missing positive explicit ID returns `ErrNodeNotFound` / `ErrRelNotFound`).
- Label/type: `g.Nodes().ByLabel(label, opts)` / `g.Rels().ByType(typeName, opts)`. Empty, whitespace-only, or overlong names return `ErrEmptyName`/`ErrNameTooLong`; unknown valid names return an empty result.
- Adjacency: `g.Rels().Outgoing(nodeID, typeName)` / `Incoming(...)` / `OutgoingForNodes(nodeIDs, typeName)` / `IncomingForNodes(...)`. Empty `typeName` matches all types. Zero/negative node IDs return `ErrInvalidStoreMutation`; any missing positive requested node ID returns `ErrNodeNotFound`; existing nodes with zero matching relationships return empty results or are absent from the batch map.
- All: `g.Nodes().All(opts)` / `g.Rels().All(opts)`.
- Property: `g.Nodes().ByLabelAndProperty(label, key, value, opts)` — rejects reserved `tkg_` keys, then uses the property index when present (R2-F4 graph-layer fallback scans label set + filters property when `PropertyIndexCapability` is absent). Scalar float matching canonicalizes signed zero and NaN payload variants within the same concrete float type.
- Counts: `g.Nodes().Count()` / `g.Rels().Count()` / `g.Nodes().CountByLabel(label)` / `g.Rels().CountByType(typeName)`. Label/type count targets use the same name validation as label/type queries. Statistics surface: `g.Stats().NodeCount()`, `RelCount()`, `NodeCountByLabel`, `RelCountByType`, `AllLabelCounts()`, `AllRelTypeCounts()`, full `g.Stats().Get()` snapshot (counters + Badger cache metrics). Direct read counters include scalar `Get`, transaction `Get*`, and bulk `GetByIDs` rows returned. Mutation counters include successful batch creates and successful temporal `CloseVersion` writes.
- `QueryOpts{Limit, After, ValidAt, ValidStart, ValidEnd, TxAt, TxPin, Depth}`: cursor pagination, temporal push-down, and shard-depth filtering. Zero values mean "all". `TxAt` is the combined bitemporal transaction-time filter (pair it with a valid-time coordinate; on its own it valid-filters at wall-now — see the RT-2 footgun warning in the `TxAt` godoc). `TxPin` is the pure knowledge-time belief-state pin (identical to `NodesAsOf`, NO valid-time filter) and is mutually exclusive with the valid-time filters and with `TxAt` (`ErrConflictingTemporalOpts`). `Limit` must be non-negative; negative values return `ErrInvalidQueryLimit`. `After` accepts `0` for the first page or a non-negative `types.EntityID` cursor; negative cursors return `ErrInvalidQueryCursor`. `ValidAt != 0` is a point-in-time temporal filter; `ValidStart`/`ValidEnd` form an interval filter only when both are greater than zero, and active intervals must satisfy `ValidStart < ValidEnd` or return `ErrInvalidTimeRange`. `Depth` must be `DepthAll`/`DepthHot`/`DepthWarm`; unknown values return `ErrInvalidShardDepth` from MemoryStore, BadgerStore, TieredStore, and graph-level query methods before empty label/type/index shortcuts. Valid non-default depth selectors are equivalent to all data on single-shard stores. Node, relationship, ID-only, property, type, and vector queries compose temporal filters with `Depth` before pagination. Badger temporal entity-returning pages apply `After` by sorted ID first but consume `Limit` only after cache-miss rows have been fetched and verified against temporal metadata.
- Store history cursor scans (`AllNodeHistoryIDsFrom`, `AllRelHistoryIDsFrom`) use the same pagination sentinels: cursor `0` starts at the first ID, `limit == 0` returns all remaining IDs, negative cursors return `ErrInvalidQueryCursor`, and negative limits return `ErrInvalidQueryLimit`.
- `g.Nodes().ForEach(opts, fn)` / `g.Rels().ForEach(opts, fn)` stream current-state unpaginated scans one row at a time (O(1) peak memory); temporal or paginated (`Limit`/`After`) opts fall back to `All`. `g.Rels().ForEach` was added alongside the iterators below to close a standing Node/Rel parity gap (v4.9.4 had added only the node side).

### Iterators (Go 1.23+ range-over-func)

`g.Nodes().Iter(ctx, opts)` / `g.Rels().Iter(ctx, opts)` return `iter.Seq2[*types.Node, error]` / `iter.Seq2[*types.Relationship, error]` for `for n, err := range g.Nodes().Iter(ctx, opts)` — a thin wrapper over `ForEach` (no new scan machinery): same row set, same order, and the same temporal/paginated fallback to `All` that `ForEach` itself takes for the given `opts`. `g.Rels().OutgoingIter(ctx, nodeID, typeName)` / `IncomingIter(...)` are the adjacency counterparts, wrapping `ForEachOutgoing`/`ForEachIncoming`. Differences from `ForEach`: `ctx` is checked once per row (non-blocking) — on cancellation the iterator yields `(nil, ctx.Err())` exactly once and stops; an internal scan error yields `(nil, err)` exactly once and stops; breaking out of the range loop stops the underlying scan immediately (no further rows are fetched). Row ownership mirrors `ForEach` exactly and is **not uniform across `opts`**: a plain current-state, unpaginated scan (`ForEach`'s fast path) hands back an independent, already-mutable copy per row, while a temporal filter or `Limit`/`After` pagination (the fallback to `All`) hands back shared FROZEN rows on a trusted backend — call `DeepCopy` before mutating in that case (`OutgoingIter`/`IncomingIter` always yield the frozen-row contract, matching `ForEachOutgoing`/`ForEachIncoming`). A nil/zero-value API yields a single `(nil, ErrNilGraph)`.

### Batch operations

`g.Batch().New()` returns a `*BatchBuilder` that queues operations with eager validation. Queue methods: `AddNode(labels, props)`, `AddRelationship(typeName, start, end, props)`, `UpdateNode(id, updates)`, `UpdateRelationship(id, updates)`, `DeleteNode(id)`, `DeleteRelationship(id)`. Batch update queues share standalone update-map validation, including provenance/authorization shadow-key extraction, and snapshot the caller's update map so later caller mutations do not affect `Execute`. Empty queued updates check entity existence at execute time, but successful empty updates do not increment `Updated` or publish update events. Successful batch creates increment `g.Stats().Get().NodesAdded`/`RelsAdded` in the same units as `BatchResult.Created`; `BatchResult.Deleted` counts removed rows, so a queued cascade node delete includes the node plus any cascaded relationships. New relationship-type tokens are allocated during `Execute` after endpoint and temporal constraint checks pass; the relationship pointer returned from `AddRelationship` is updated in place before persistence and restored to queue-time `TxFrom`, endpoint hashes, and type token if the create fails. Call `Execute()` to persist all queued operations in order (creates → updates → deletes). Mutation events are buffered during replay and dispatched after graph and builder locks are released with one `Publisher.PublishBatch` call, preserving async priority ordering across the full batch. Queue methods are serialized internally. `Execute` is one-shot: once replay begins, later queue calls or repeat `Execute` calls return `ErrBatchDone`.

`Execute()` is **per-operation reporting, not all-or-nothing**: it returns `*BatchResult{Created, Updated, Deleted, Failed, Errors []BatchError}`. If any queued operation fails, `Execute` returns that result plus an error wrapping `ErrBatchFailed`; `result.Errors` carries per-operation detail. The endpoint-lock window for relationship creation is panic-safe via a defer-backed UnlockTwo (R2-F3).

### Temporal queries (`g.Temporal`)

- Point-in-time: `g.Temporal().NodeAt(id, t)`, `RelAt(id, t)`, `NodesAt(t)`, `RelsAt(t)`, `NodesByLabelAt(label, t)`, `RelsByTypeAt(relType, t)`, `NeighborsAt(nodeID, t)`, `NodesByLabelPropertyAt(label, key, value, t)`, `RelsByTypePropertyAt(relType, key, value, t)`.
- Interval: `NodesDuring(start, end)`, `RelsDuring(start, end)`, `NodesByLabelPropertyDuring(label, key, value, start, end)`, `RelsByTypePropertyDuring(relType, key, value, start, end)`. `end == 0` is open-ended; otherwise `start < end` is required.
- Current transaction-time pin: `NowTx() (types.Instant, error)`. Returns the graph's current transaction instant — the pin for the AS-OF reads (`QueryOpts.TxAt` / `NodeAtTx` / `NodesAsOf`) or to name via `TagAsOf`, snapshotting everything committed so far: every committed entity has `TxFrom <= NowTx()` and every later mutation is stamped strictly greater. Reading it ADVANCES the commit clock by one tick (reserving the instant) via the wall-dominated `Core.now()`, so it is correct across a `Close`/reopen — a session-local high-water mark resets to 0 on reopen, and `TxAt == 0` means "no filter", which would silently include future writes. Errors on a nil/closed graph.
- Bitemporal (transaction time): `NodeAsOf(id, txTime)`, `RelAsOf(id, txTime)`, `NodesAsOf(txTime)`, `RelsAsOf(txTime)`. Returns `ErrNoVersionAsOf` if no version was committed at or before `txTime`.
- Belief-state pin through the generic door: `QueryOpts.TxPin` makes the generic scan doors (`g.Nodes().ByLabel`/`All`, `g.Rels().ByType`/`All`) resolve each candidate through the SAME as-of resolver as `NodesAsOf`/`RelsAsOf` — pure knowledge-time, NO valid-time filtering. `ByLabel{TxPin:T}` equals `NodesAsOf(T)` filtered by label; `ByType{TxPin:T}` equals `RelsAsOf(T)` filtered by type. This is the fix for the `TxAt`-alone footgun: setting only `QueryOpts.TxAt` still applies an implicit valid-at-wall-now filter and silently drops past-valid facts, so use `TxPin` when you want "everything believed at T". `TxPin` is mutually exclusive with `ValidAt`/`ValidStart`/`ValidEnd` and with `TxAt` — combining them returns `ErrConflictingTemporalOpts`. `TxPin == 0` is disabled (a plain current-state scan).
- Snapshot/Diff: `Snapshot(t) (*GraphSnapshot, error)` (full graph state at `t`, endpoints-filtered; holds the graph write lock while composing node and relationship reads). `tx.Snapshot(t)` is the transaction-scoped variant for code already running under `g.Tx`. `Diff(t1, t2) (*SnapshotDiff, error)` returns `NodesCreated`, `NodesUpdated [{Before, After}]`, `NodesDeleted`, `RelsCreated`, `RelsUpdated`, `RelsDeleted`. `DiffCallback(t1, t2, handlers)` streams the same diff via `DiffHandlers` (each handler optional). Handler callbacks run outside the graph lock and may call graph read APIs.
- Allen relations: `NodeInterval(n)`, `RelInterval(r)`, `RelateNodes(a, b)`, `RelateRels(a, b)` — return `(start, end Instant, err error)` for the interval helpers and `AllenRelation` for the relation helpers. Allen relations require finite intervals (ValidTo != 0). Nil node inputs return `ErrNilNode`; nil relationship inputs return `ErrNilRelationship`.
- Named knowledge-time (Erkenntniszeit) marks (§4.2): `TagAsOf(name, at)`, `ResolveAsOf(name) (Instant, bool, error)`, `AsOfTags() (map[string]Instant, error)`, `RemoveAsOfTag(name)`. A durable alias registry mapping a documented name to a transaction-time instant, so a consumer can run `AS OF SYSTEM TIME $tag` against a named, stable state (`at` feeds `TxAt` / the `txAt` argument of `NodeAtTx`). Stored under the `asof_tags` MetaKV key (durable across restart, reaped by `Admin().Reset()`, decoded via `SafeUnmarshal` so a corrupt blob fails closed). `name` must be non-blank and ≤256 bytes, `at` must be positive (`ErrInvalidAsOfTag`); the registry is bounded at 4096 marks (`ErrTooManyAsOfTags`); `ResolveAsOf`/`AsOfTags` return `ErrCapabilityNotSupported` on a backend without MetaKV; writes are rejected on a read-only replica. `RemoveAsOfTag` is idempotent.

All temporal queries are history-aware (include deleted entities via lazy ForEach iterators). Nodes without explicit temporal metadata derive valid-from from their snowflake ID timestamp. Explicit finite validity ranges are half-open and must satisfy `ValidFrom < ValidTo`; graph create/import/batch inputs and direct Store write boundaries reject equal or reversed finite ranges. `g.Temporal().NeighborsAt` validates the target node at the queried instant, but still traverses relationship history when that node has no current row. `g.Temporal().NodesByLabelAt` and temporal stored-property helpers reject malformed labels/types before treating a target as unregistered. Temporal stored-property queries reject reserved `tkg_` keys with `types.ErrReservedPrefix`; use `g.Resolve` for shadow metadata.

### Version chain navigation

- `g.Nodes().History(id)` / `g.Rels().History(id)` — full version chain; zero/negative IDs return `ErrInvalidStoreMutation`.
- `g.Nodes().VersionBefore(id, version)` / `VersionAfter(id, version)` and rel mirrors. Missing explicit IDs return `ErrNodeNotFound` / `ErrRelNotFound`. Known entities return `nil, nil` when the neighboring version does not exist. `VersionAfter(id, math.MaxUint32)` returns `nil, nil` for known entities; successor lookup never wraps to genesis version `0`.
- `g.Nodes().CloseVersion(id, t)` / `g.Rels().CloseVersion(id, t)` — set `ValidTo` on the current entity in-place without incrementing its version or creating a history entry. The hash-chain fields are recomputed while existing provenance, signature, authorization, and relationship endpoint-hash metadata are preserved. Returns `ErrInvalidTimeRange` for `t == 0` and `ErrAlreadyClosed` if `ValidTo` is already set.
- Store history truncation (`TruncateNodeHistory`, `TruncateRelHistory`) keeps the N most recent versions. `keepVersions == 0` is the explicit clear-all request; negative retention returns `ErrInvalidStoreMutation` and leaves existing history untouched.

Direct Store history writes validate history/tombstone payload shape before
accepting snapshots: node labels, relationship type/endpoints, payload ID/key
agreement, and explicit temporal ranges must all be valid. Readable node delete
tombstones must preserve the stored node's labels.

Direct Store label/type query and count methods reject token `0` with
`ErrInvalidStoreMutation`; the zero token is the registry sentinel, not an empty
label or relationship type.

Node label add/remove, node/relationship property CAS, and node/relationship in-place updates also recompute hash-chain fields without accepting provenance shadow keys; those paths preserve existing non-hash integrity metadata instead of clearing it.

### Events (`g.Events`)

- Sync bus: `bus := events.NewEventBus()` or `var bus events.EventBus` with `g.Events().SetSync(&bus) error`, `g.Events().GetSync()`. `SetSync(nil)` detaches on open graphs. Post-close `SetSync` returns `ErrGraphClosed` and leaves the installed publisher unchanged. `bus.Subscribe(handler)` returns an idempotent unsubscribe. Nil handlers and nil bus receivers are ignored with no-op behavior. Handlers run synchronously after each successful store write, outside the bus lock.
- Async bus: `bus := events.NewAsyncEventBus(AsyncEventBusConfig{Workers, QueueSize, Backpressure})` or `var bus events.AsyncEventBus` with default lazy-start config, `g.Events().SetAsync(&bus) error`, `g.Events().GetAsync()`. `SetAsync(nil)` detaches on open graphs. Post-close `SetAsync` returns `ErrGraphClosed` and leaves the installed publisher unchanged. Nil handlers are ignored with a no-op unsubscribe and do not start a zero-value async bus; nil bus receivers no-op for `Subscribe`, `Publish`, `PublishBatch`, and `Close`. Three backpressure strategies: `BackpressureBlock`, `BackpressureDropOldest`, `BackpressureDropLatest`; unknown strategy values normalize to `BackpressureBlock`. `Workers` is accepted for compatibility but capped at one dispatcher so `PublishBatch` drains in Critical→High→Normal→Low→Deferred priority order, including during `Close`. `bus.Close()` marks the bus closing, closes the stop signal to unblock `BackpressureBlock` publishers waiting on full queues, waits for active publishers, drains accepted events, then stops the dispatcher. `Subscribe` after close returns a no-op unsubscribe.
- Six event types: `EventNodeCreate`, `EventNodeUpdate`, `EventNodeDelete`, `EventRelCreate`, `EventRelUpdate`, `EventRelDelete`. Internal priorities: creates → `PriorityHigh`, deletes → `PriorityCritical`, updates → `PriorityNormal`. Cascade node deletes publish one `EventRelDelete` per removed relationship before the `EventNodeDelete`. Five priority levels (zero value = `PriorityNormal`).

### Hash chain verification (`g.Hash`)

- `g.Hash().VerifyNodeChain(id) (bool, error)` / `VerifyRelChain(id) (bool, error)`. Tolerates deleted entities (verifies history alone when current entity is gone).

### Transactions (`g.Tx`) and the imperative tx surface

- Functional form: `g.Tx().Run(func(tx *graph.GraphTx) error { ... })` / `g.Tx().RunContext(ctx, fn)`. Panic-safe — a panic inside fn rolls the tx back via defer and propagates the panic; rollback errors are joined with the caller's error via `errors.Join`. Nil callbacks return `ErrNilTxCallback` before opening a transaction; nil contexts return `ErrNilContext`.
- Imperative form: `tx := g.Tx().Begin()`. Methods on `*GraphTx`:
  - Mutations: `AddNode`, `AddRelationship`, `AddRelationshipByID`, `AddRelationshipByIDIfAbsent` (returns `(rel, created, err)`), `UpdateNode`, `UpdateRelationship`, `SetNodeProperty`, `DeleteNodeProperty`, `SetRelationshipProperty`, `DeleteRelationshipProperty`, `AddNodeLabel`, `RemoveNodeLabel`, `DeleteNode` (cascade), `DeleteRelationship`.
  - Reads: `GetNode(id)`, `GetRelationship(id)` (safe inside tx — tx holds the write lock). Successful tx-scoped reads increment the same read counters as standalone reads; rollback restores the `BeginTx` counter snapshot.
  - Lifecycle: `Commit()` releases the lock and dispatches buffered events. `Rollback()` restores deleted node rows before deleted relationships, restores pre-transaction version history, restores multi-step node label changes and label indexes to the pre-transaction label sequence, then reverts other updates and deletes created entities; node and relationship snapshots are tracked separately even when caller-supplied IDs share the same underlying snowflake value. Buffered events are discarded and the operation-counter snapshot from `BeginTx` is restored after successful rollback. Sentinel: `ErrTxDone`.
  - Inspection: `CreatedNodeIDs()`, `CreatedRelIDs()`.

### Indexes (`g.Index`)

- Property: `g.Index().CreateProperty(label, propertyKey)` / `DeleteProperty(label, propertyKey)`. Create validates the label/property key, rejects reserved `tkg_` keys, creates the label token when needed, and installs an index that also covers future matching nodes. Delete validates the same label/key inputs and returns `ErrIndexNotFound` if the label or index is absent. `g.Nodes().ByLabelAndProperty(label, key, value, opts)` rejects reserved `tkg_` keys, uses the index when present, and falls back to label scan + property filter otherwise (R2-F4).
- Temporal interval: `g.Index().CreateTemporal(label)` / `DeleteTemporal(label)`. Create validates the label and creates the label token when needed. Delete validates the label and returns `ErrTemporalIndexNotFound` if the label or index is absent. Accelerates `g.Nodes().ByLabel(label, opts)` when a temporal filter is set.
- High-frequency temporal: `g.Index().CreateHighFrequency(label, bucketSize)` / `DeleteHighFrequency(label)`. Create validates the label, requires `bucketSize` to be a positive whole millisecond, creates the label token when needed, and returns `ErrInvalidTemporalIndexConfig` otherwise. Delete validates the label and returns `ErrTemporalIndexNotFound` if the label or index is absent. Time-bucketed alternative for high-write-rate event labels. Only one temporal index type per label at a time. MemoryStore and BadgerStore backfill matching current nodes when the index is created and maintain buckets on later node writes. Badger persists HFI definitions and rebuilds buckets on open; creation fails closed on corrupt existing node rows. In `tiered.Store`, persisted tracked HFI definitions are restored on restart, applied to rotated hot shards and lazily opened archives, and later-shard backfill or metadata persistence failures roll back earlier shard-local creates.
- Vector: `g.Index().CreateVector(label, propertyKey, dims, metric)` / `DeleteVector(label, propertyKey)`. Create validates the label/property key, rejects reserved `tkg_` keys, creates the label token when needed, and installs an index that also covers future matching nodes. Delete validates the same label/key inputs and returns `ErrVectorIndexNotFound` if the label or index is absent. `dims` must be greater than zero and `metric` must be `DistanceCosine` or `DistanceEuclidean`; invalid config returns `ErrInvalidVectorIndexConfig`. `CreateVector` returns `ErrDimensionMismatch` if an existing matching vector property has a length different from `dims`; creation removes only its own placeholder index on that failure. Once the index exists, node writes touching a matching vector property also return `ErrDimensionMismatch` before changing store state when the value length differs from `dims`. `g.Index().SearchNearest(label, propertyKey, query []float32, k int, opts)` validates the label/property key, rejects reserved `tkg_` keys, reports unknown labels before the `k <= 0` empty-result shortcut, returns `ErrVectorIndexNotFound` for absent labels or indexes on positive-k searches, and otherwise returns the top-k nearest nodes. The in-memory heap capacity is capped by the number of indexed entries, so an oversized `k` returns available entries without allocating proportional to `k`. Under temporal filters, the graph pre-filters when the backend implements `FilteredVectorSearchCapability`; otherwise iterative over-fetch escalates k until k eligible results are accumulated or the backend is exhausted (R2-F5), with the graph-level resolved-candidate buffer capped by the same over-fetch ceiling. Direct Store-level `SearchNearestNodes` applies temporal `QueryOpts` before heap selection and applies `After`/`Limit` over distance-ranked order; graph-level search strips cursor opts from the backend call and paginates the final current/history-resolved slice once. On `tiered.Store`, `DepthHot`/`DepthWarm` are applied before vector heap selection: live reference nodes remain eligible, `refArchive` is excluded, and event-shard candidates must belong to an included tier. Errors: `ErrEmptyName`, `ErrKeyTooLong`, `types.ErrReservedPrefix`, `ErrInvalidVectorIndexConfig`, `ErrVectorIndexExists`, `ErrVectorIndexNotFound`, `ErrDimensionMismatch`; vector sentinels are canonical in `pkg/graph/store` and aliased by `pkg/graph` and `pkg/graph/index`.
- **Engine choice**: every vector index now runs an approximate pure-Go HNSW graph by default (M=16, EfConstruction=200, EfSearch=64) instead of brute-force linear scan; see CLAUDE.md "Vector Indexes" for the recall target, determinism, and tombstone/rebuild contract. `g.Index().CreateVectorWithOptions(label, propertyKey, dims, metric, storepkg.VectorIndexOptions{...})` is `CreateVector` plus the engine/tuning choice: `UseBruteForce bool` (the exact-recall escape hatch — reverts that one index to the pre-existing linear scan) and `M`/`EfConstruction`/`EfSearch` (zero = documented default). `CreateVector` is unchanged in signature and is now equivalent to `CreateVectorWithOptions(..., storepkg.VectorIndexOptions{})` (all-default HNSW). A backend implementing the new optional `store.VectorIndexOptionsCapability` (memory/badger/tiered all do) applies the options at creation; a backend that only implements the mandatory `VectorIndexCapability` silently falls back to plain `CreateVectorIndex` (opts unavailable) — the same "optional acceleration, correctness-preserving fallback" contract as `FilteredVectorSearchCapability`. `SearchNearest`'s existing signature and behavior (temporal pre-filter/over-fetch, pagination, `tiered.Store` depth gating) are unchanged regardless of engine — the engine choice only affects which internal search the store's `SearchNearestNodes`/`SearchNearestFiltered` doors delegate to.
- All graph-level index create variants restore a newly allocated label token if the backend create call fails; successful creates still materialize future-label indexes. Registry rollback guards use deferred cleanup so backend panics do not strand later registry writes. Multi-label node allocation restores partial suffixes if capacity is hit after an earlier label was created.
- IndexProvider plugin: `g.Index().RegisterProvider(p)` / `UnregisterProvider(name)` / `Providers() []string`. Nil and typed nil providers are rejected before `Name()` is called; empty and whitespace-only provider names are rejected before registration or unregistration lookup. `Providers()` returns an empty list once graph close is visible, including callers that waited behind the lifecycle lock. Auto-creates a sync `events.EventBus` if none is attached; existing sync or async buses are both supported. If a provider implements `index.Initializable`, unregister and graph close wait for its in-flight `Init` callback before calling provider `Close()`. `OnEvent` errors are logged with provider/event context and do not abort already-committed mutations. Sentinels: `ErrIndexProviderExists`, `ErrIndexProviderNotFound`, `ErrIndexProviderEmptyName`.

### Constraints (`g.Constraints`)

- `g.Constraints().Add(c) error`, `Set(cs) error`, `Get()`. `TemporalConstraint{Kind: ConstraintRelWithinEndpoints}` enforces that a relationship's validity is contained within both endpoint nodes' validity. Checked during relationship creation and import. Unknown constraint kinds, including the zero-value `TemporalConstraint{}`, are rejected by `Add`/`Set` with wrapped `ErrTemporalConstraint` and `ErrInvalidTemporalConstraint` before the configured set changes. Post-close `Add`/`Set` return `ErrGraphClosed`. `temporal.ConstraintSet.ForEach(nil)` returns `ErrInvalidTemporalConstraint` consistently. Other enforcement errors wrap `ErrTemporalConstraint` (sub-sentinels: `ErrRelBeforeStartNode`, `ErrRelAfterEndNode`, `ErrRelExceedsStartNodeValidity`, etc.).

#### Unique property constraints (ADR-0002)

- `g.Constraints().CreateUnique(ctx, label, propertyKey) error`, `CreateUniqueForever(ctx, label, propertyKey) error`, `DropUnique(ctx, label, propertyKey) error`, `ReleaseOwnership(ctx, label, propertyKey, value) error`, `UniqueConstraints() []constraints.UniqueConstraint`. A unique constraint forbids two CURRENT nodes carrying the same value for the constrained `(label, propertyKey)` (`UniqueCurrent`, the default scope). `CreateUniqueForever` installs a `UniqueForever` value-ownership constraint: the first entity to hold a value owns it permanently — only that entity (any later version) may ever hold it, and every other node is barred forever, across supersession, hard delete, and reopen (`UniqueValidOverlap` remains reserved and returns a not-yet-supported error). For `UniqueCurrent`, history may hold duplicates and a value freed by supersession or delete is immediately reusable; for `UniqueForever`, a released value is reusable only via `ReleaseOwnership`.
- `CreateUnique`/`CreateUniqueForever` validate existing data first (auto-ensuring a property index on `(label, propertyKey)`): if two current nodes already share a value the constraint is NOT installed and `ErrUniqueViolationExisting` is returned (up to five offender IDs). Float-typed keys/values are rejected with `ErrUniqueUnsupportedType` (int64/string/bool/temporal supported). A duplicate constraint returns `ErrUniqueConstraintExists`; `DropUnique` of an absent one returns `ErrUniqueConstraintNotFound`. `ReleaseOwnership` frees an owned `UniqueForever` value so a different entity may reclaim it (idempotent; `ErrUniqueConstraintNotFound` if no forever constraint on the pair).
- Persisted in MetaKV (durable across reopen, reaped by `Admin().Reset`, declines without MetaKV via `ErrCapabilityNotSupported`, rejected on a read-only replica; the `UniqueForever` ownership registry is a separate self-hashed MetaKV blob). **Enforcement covers the standalone node doors, batch, and tx** — `Add` / `AddWithTx` / `AddByIDIfAbsent` / `Update` / `UpdateInPlace` / `CompareAndSetProperty` / `AddLabel` (the label-add door binds a constraint without touching the property), `BatchBuilder.AddNode`/`UpdateNode` (a same-value create inside one batch/tx fails at op time; the batch pre-check also consults the `UniqueForever` ownership registry, so a batch create claiming a value owned forever by another entity is barred even with no current holder, and a fresh batch create claims ownership), and `GraphTx.AddNode`/`UpdateNode`. A violating write returns `ErrUniqueViolation` (wrapped with the label, key, and winning entity ID). `g.IO().Import` validates the replayed current state and rolls back with `ErrUniqueViolation` on a duplicate (default-strict; `ImportOptions.SkipUniqueValidation` opts a trusted restore out). Replica apply reproduces rows verbatim and does NOT enforce. A `UniqueForever` claim made inside a rolled-back tx stays barred (`ReleaseOwnership` is the remedy).
- `g.Nodes().GetOrCreateByKey(ctx, label, propertyKey, value, extraProps) (*types.Node, bool, error)` atomically returns the current node holding `value` for `(label, propertyKey)` or creates one, under a single value lock so a storm of concurrent callers produces exactly one create (the bool reports whether THIS call created it). Works with or without an active constraint on the pair; `value` must be an indexable non-float scalar (else `ErrUniqueUnsupportedType`); `extraProps` seed a freshly created node (the keyed property wins) and are ignored on a hit; the returned node is a mutable copy (Get semantics).

### IO (`g.IO`)

- `g.IO().Export(w io.Writer) error` — length-prefixed msgpack record stream with 1-byte type tags. Unknown tags are rejected on import with `ErrCorruptExport`. Holds the graph write lock while streaming, so standalone mutations, tx/batch, and reset cannot interleave with Export's reads. Nil and typed nil writers return `ErrNilWriter`.
- `tx.Export(w io.Writer) error` — transaction-scoped export for code already running under `g.Tx`. Same wire format as `g.IO().Export`; nil and typed nil writers return `ErrNilWriter`.
- `g.IO().Import(r io.Reader, opts io.ImportOptions) error` — `ImportOptions{StagingDir, MaxStagedBytes}`. Pass `ImportOptions{}` for the previous defaults (platform temp dir, no size cap). Nil and typed nil readers return `ErrNilReader` before staging-file creation. `MaxStagedBytes == 0` means unlimited; negative caps return `ErrImportSizeLimit` before staging-file creation. Phase-1 streaming memory is `O(maxExportRecordSize)` and the staging file is sized to match the export, then removed via defer at exit. Phase 2 tracks rollback snapshots and stream-identity sets for touched rows, so replay memory scales with imported entity IDs and history records. Phase-1 errors (read, staging-disk write, MaxStagedBytes exceeded) leave graph state unchanged. Phase-2 replay errors restore touched current rows, history rows, and registries to their pre-import state unless the underlying store also fails during rollback. Wire validation rejects missing header/registry records, unknown tags, header count mismatches, duplicate singleton/current/history-version records inside one stream, malformed MsgPack bodies, malformed entity IDs, versions, label/type tokens, property-slice invariants, and base-entity IDs with `ErrCorruptExport` before constructing entities. Sentinels: `ErrNilReader`, `ErrNilWriter`, `ErrIncompatibleExport`, `ErrIncompatibleRegistry`, `ErrImportSizeLimit`, `ErrCorruptExport`. Per-record allocations capped at 128 MiB.

**Delta backups (node-level incrementals).** Built on the change-log; require a change-log store (`graph.Config.ChangeLog` on badger, or an injected `memory.WithChangeLog()`; the tiered backend declines). The cursor is the change-log LSN, not valid/transaction time — a temporal diff would silently drop backdated/backfilled writes and cannot reconstruct label-token or cascade-delete primitives.

- `g.IO().Watermark() (io.Cursor, error)` — the graph's current change-log point. `io.Cursor{LSN, Epoch}` is opaque, value-comparable, and msgpack/JSON round-trippable. `Epoch` is a durable per-graph lineage id (`meta/graph_epoch`); a cursor from a different graph is rejected (`ErrCursorUnknown`) rather than producing a wrong delta. Declines with a wrapped `store.ErrCapabilityNotSupported` when no change-log is active.
- `g.IO().ExportSince(w io.Writer, since io.Cursor) error` — writes a DELTA stream (delta header, full token registry, then one verbatim change record per committed mutation after `since`), produced under the export write lock against one consistent point. `ErrCursorUnknown` when `since` is from another graph or ahead of the log (caller falls back to a full `Export`); `ErrNilWriter` on a nil writer.
- `g.IO().ImportMerge(r io.Reader, opts io.MergeOptions) error` — merges a delta onto a base, reproducing the source's rows VERBATIM through the replica-apply doors (per-record hash recompute-and-compare + full hash-chain verification of every touched entity; the registry is append-only merged). Does NOT require an empty target. Idempotent (re-applying the same or an overlapping delta is a no-op). `MergeOptions{StagingDir, MaxStagedBytes, ExpectBase, Strict}`: `ExpectBase` asserts the delta's `From` cursor (`ErrDeltaBaseMismatch` on disorder); `Strict` rejects an update/tombstone for an entity absent from the base (`ErrDeltaBaseMismatch`). Any failure rolls the touched subgraph back to its pre-merge state. Rejects a full (non-delta) stream with `ErrIncompatibleExport` (use `Import`).
- `io.HeaderOf(r io.Reader) (io.DeltaHeader, error)` — decodes only the leading header record (no entity/change records consumed). `DeltaHeader{Version, IsDelta, From, To, ExportedAt, NodeCount, RelCount}`. For a full export, `To = {SnapshotLSN, Epoch}` — the complete, gapless base cursor for the first delta in a chain. `ErrCorruptExport` if the first record is not a header; `ErrIncompatibleExport` on an unknown version.
- Restore-chain pattern: `Import` the base, then `ImportMerge` each delta in order with `ExpectBase` set to the previous stream's `To` cursor. New sentinels: `ErrCursorUnknown`, `ErrDeltaBaseMismatch` (also re-exported from `pkg/graph`).

### Admin & Tier (`g.Admin`, `g.Tier`; the shard-management methods below are `g.Tier()` and `tiered.Store`-only)

- `g.Tier().Archive(id)` / `Restore(id)` — move a reference node between the reference shard and archive, migrating relationship placement for self-loop, ref-ref, and ref-event edges (under `g.mu.Lock`). Destination node and relationship placement collisions are rejected before the temporary destination node is written.
- `g.Tier().ForceRotate()` — transactional hot-shard rotation: opens the new shard + temporal indexes, snapshots the catalog, mutates catalog in-memory, persists; on Save failure, restores the catalog snapshot, closes + removes the new shard, returns the error (R2-F2).
- `g.Tier().ListShards()` — `[]ShardInfo` with live counts (under `g.mu.RLock`).
- `g.Tier().RebuildCatalog()` — reconstruct the shard catalog from live state (under `g.mu.Lock`).
- `g.Tier().Repair()` — scan + fix cross-shard split-write inconsistencies (under `g.mu.Lock`, R2-F1).
- `g.Tier().VerifyShard(name)` — hash chain verification with immutable-shard caching under the graph write lock. `tx.VerifyShard(name)` is the transaction-scoped variant for code already running under `g.Tx`.
- `g.Admin().Reset()` — clears all entities, indexes, history, counters, named as-of tags, unique constraints, and the history-compaction watermark; preserves registries and checkpoints the preserved registry snapshot after the backing `store.Clear`. Works on every backend.
- `g.Admin().DecomposeNodeID(id types.NodeID)` / `g.Admin().DecomposeRelID(id types.RelID)` → `IDComponents{CreatedAt, NodeID, Sequence}` — works with any store type.

#### History retention & compaction (ADR-0001)

- `g.Admin().CompactHistoryNodes(ctx, policy RetentionPolicy) (CompactReport, error)` / `g.Admin().CompactHistoryRels(ctx, policy)` — trim an entity's OLDEST version-history rows, keeping the newest belief, and record a per-entity detached-anchor stub. `RetentionPolicy{KeepVersions int, KeepSince types.Instant}`: a history version is trimmable only when it fails BOTH bounds (neither among the newest `KeepVersions` nor recorded at/after `KeepSince`). The current row and the newest history version are never trimmable. `CompactReport{EntitiesCompacted, VersionsTrimmed, Watermark}`.
  - **Chain integrity**: the stub is a virtual predecessor — `VerifyNodeChain` / `VerifyRelChain` require the oldest kept version's `PrevHash` to equal the stub's `LastTrimmedHash`. The stub carries a self-hash (`SafeUnmarshal` on read, fail-closed on corruption or self-hash mismatch), so a forged truncation is caught. No stored row is ever mutated (append-only).
  - **Answerability**: a temporal read whose transaction-time pin falls before compacted knowledge returns `ErrHistoryCompacted`, never a silently-incomplete result. Point doors (`NodeAsOf` / `NodeAtTx` / rel mirrors) check per entity; scan doors (`NodesAsOf` / `ByLabel` / `ByType` with `TxAt` / `TxPin`) check the graph watermark (`CompactedThroughTx` = max over stubs, durable in MetaKV, reloaded at open) and fail the whole scan.
  - **Refusals** (no history trimmed): `ErrInvalidRetentionPolicy` (empty/negative policy), `ErrCompactionProtectedTag` (a registered as-of tag pins knowledge the policy would trim — remove the tag first), `ErrCompactionChangeLogEnabled` (compaction records / replica apply / delta interplay land later, so compaction is refused while the change-log is on). Rejected on a read-only replica; declines with `ErrCapabilityNotSupported` on the tiered backend (memory + badger only).

Non-tiered backends return `ErrNotTieredStore` from the seven tiered-only methods.

### Migration

- `tiered.MigrateFromBadger(src *badger.Store, dst *tiered.Store) error` — copy all entities from a single badger.Store to an empty tiered.Store with automatic ontology-based routing. Source label and relationship-type registries are loaded from `src`; migrated entity tokens and relationship endpoints are preflighted against the source data; registries are saved to `dst` after a successful copy. Failures roll back inserted destination entities, restore the previous ontology registry, and restore or remove the destination registry file to match its pre-migration state. Nil stores, non-empty destinations, and missing source registry metadata for non-empty data return `ErrInvalidStoreMutation`; closed stores return `ErrStoreClosed`.
- `ontology.OntologyMapping` — nil receivers behave like an empty mapping: `ClassifyByName` / `ClassifyByToken` return `ClassEvent`, `SetLabelRegistry` returns nil, and `RefLabels` returns nil.

### Validation limits

- `Config.Validation` accepts `ValidationLimits{MaxLabelsPerNode, MaxPropertiesPerEntity, MaxPropertyKeyLength, MaxPropertyValueSize, MaxNameLength, AllowSelfLoops}`. Defaults: 50 / 1000 / 256 / 65536 / 256 / false. `MaxNameLength` is enforced by graph mutation/query/index/temporal target validation, by internal registry allocation on first use of a label or relationship type, and by `IO.Import` / graph construction before accepting registry mappings from serialized or persisted data; boolean lookup helpers (`Nodes.HasLabel`, `Rels.HasType`) fail closed for malformed names. `MaxPropertyValueSize` applies to every string nested inside supported property values. `MaxPropertiesPerEntity` is enforced by create, update, import, and node/relationship property CAS paths after the final mutation shape is known. `AllowSelfLoops=false` causes `g.Rels().Add` and `g.Rels().Import` to reject self-loops with `ErrSelfLoop`. Zero values use defaults.

### Lifecycle

- `g.Close() error` — saves registries again (badger.Store / tiered.Store), then calls `store.Close()`. Successful token-creating operations already persist registries before returning; the close-time save is a final idempotent checkpoint. `tiered.Store.Close()` saves catalog and closes all event shards plus the reference shard and archive. Idempotent — safe to call multiple times. Nil concrete in-tree Store receivers return `ErrNilStore` from `Close` and `Clear`.
- After `Close`, error-returning sub-APIs that touch store, registry, index, IO, admin, stats, hash, tx, or batch state return `ErrGraphClosed`. No-error state mutators are no-ops after close; `Nodes.NextID` and `Rels.NextID` return `0`.
