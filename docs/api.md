# API Documentation

How to call each door. Error sentinels and their meaning: [errors.md](errors.md). Planner statistics: [query-planners.md](query-planners.md). Stability promise: "Stability and deprecation" at the end of this file. The complete method list is `go doc -all` on each `pkg/graph` sub-package.

## Core Types (`pkg/types`)

| Type | Purpose |
|------|---------|
| `Node` | Vertex: opaque `NodeID`, primary + extra labels, properties, version, temporal, integrity. `TxStamps() (txFrom, txTo, deletedAt Instant)` and `ValidRange() (from, to Instant, ok bool)` read stamps and bounds without the copy `Temporal()` makes on a frozen row (`ok=false`: no temporal metadata; `to` 0: open). `Ordinal()`: see Reads |
| `Relationship` | Directed edge: opaque `RelID`, type, start/end `NodeID`, properties, version, temporal, integrity; `TxStamps()`, `ValidRange()`, `Ordinal()`, `StartOrdinal()` / `EndOrdinal()` |
| `PropertySlice` | Sorted key-value store. Validation rejects `tkg_` keys and values outside the hash/copy/wire allowlist at any depth (max 32 levels); setters deep-copy reference values |
| `Instant` | Unix milliseconds. `InstantFromTime(time.Time)`, `(Instant).Time()` (UTC), `CoerceInstant(v any) (Instant, bool)` (`Instant`, `int64`, `int`, integral `float64`, `time.Time`, `*time.Time`) |
| `TemporalMetadata` | `ValidFrom`, `ValidTo`, `TxFrom`, `TxTo`, `CreatedAt`, `UpdatedAt`, `DeletedAt` (`Instant`); `CreatedBy`, `UpdatedBy` (`string`); `Retracted` (tombstone of a `Retract` door), `Void` (piece written by an excise), `DeleteKeptValidTo` (tombstone that kept its believed `ValidTo`; read, not yet written); method `BaseEntityID() EntityID` (0: the original) |
| `NodeIntegrity` / `RelIntegrity` | `Hash`, `PrevHash`; caller provenance `AuthorID`, `Signature []byte`, `AuthorizedBy`, `AuthorizationLevel uint8`. `RelIntegrity` also `FromNodeHash` / `ToNodeHash` (endpoint hashes at write time, not hashed into the rel) |
| `TimeGranularity` | `GranMillisecond` … `GranYear`; `TruncateInstant`, `RoundInstant`, `CeilInstant` |
| `AllenRelation` | The 13 Allen relations. `Relate(aStart, aEnd, bStart, bEnd) (AllenRelation, error)` (finite intervals), `RelateOpen` (an end 0 is open), `Compose(r1, r2) AllenRelationSet`, `ComposeSets`; build sets with `types.Before.Set().Add(types.Meets)` or `AllRelations()` |
| `RecurrencePattern` | `Frequency`, `Days` (`WeekdayMask`), `DayOfMonth` (1–28, 0 = last), `Month`, `DayStart` / `DayEnd`. `Validate()`; `Expand(from, to) []Interval` (`types.ErrInvalidTimeRange`, `ErrRecurrenceSpanTooLarge`) |
| `HashableValue` | `HashBytes() []byte` for custom property struct types, registered with `RegisterPropertyStructType(v)`; listed by `RegisteredPropertyStructTypes()`. `HashBytes` is a wire format: never change it once values are stored |
| `NodeID` / `RelID` / `EntityID` | Typed wrappers around `snowflake.ID`. `SnowflakeID()`; `NodeID` and `RelID` also `MintInstant()` (the ID's mint time in ms, 0 for IDs ≤ 0). `EntityID` is the kind-agnostic form (`Event.EntityID`, `BatchError.ID`, `QueryOpts.After`). Literal 0 means "unset" across the API |

Nil `*Node` / `*Relationship` accessors return zero values, no-error mutators no-op, error-returning mutators return `ErrNilNode` / `ErrNilRelationship`; nil `*PropertySlice` mutators return `ErrNilPropertySlice`.

**Property equality** (`types.EqualIndexValues`, `types.PropertyEqual`) is the rule of every equality door: `ByLabelAndProperty` / `ByTypeAndProperty`, the `*At` / `*During` property doors, `ByLabelAndProperties`, the effective pages' `Filter`, `CountByLabelPropertyValue`, CAS's numeric `expected`, unique constraints, `GetOrCreateByKey`, `RangeCardinalityAt`. A number equals every stored number of the same exact value in any width (3 = `int8(3)` = `uint(3)` = 3.0; a `float32` by its `float64` widening, so `float32(0.1)` ≠ 0.1; -0.0 = 0; no rounding past 2^53); NaN and nil equal nothing; strings, booleans and temporal values equal only themselves; kinds never cross. Stored values keep their width. **Value identity** (`types.PropertyValueEqual`, `(*Node).PropertyValueEqual`: exact type, NaN = NaN) decides whether an update is a no-op (writing 3.0 over `int64(3)` stores the `float64`) and compares lists and maps in CAS.

**Provenance shadow keys** in props/updates: `tkg_author_id`, `tkg_authorized_by` (`string`), `tkg_signature` (`[]byte`), `tkg_auth_level` (bounded integers, whole-number floats); a wrong type fails before mutation. In an `Update` map an absent key keeps the stored value, a present key overwrites it, a nil or zero value clears it. `UpdateInPlace`, label changes, CAS and `CloseVersion` reject every `tkg_` key (`ErrReservedPrefix`) and keep provenance.

**Temporal shadow keys** `tkg_valid_from`, `tkg_valid_to`, `tkg_created_at` accept `types.Instant`, integer milliseconds (unsigned only within `int64`) and whole-number floats within their exact range.
- On the legacy axis (`UntimedFromTxFrom` / `UntimedUnbounded`) `tkg_valid_from = 0` is "unset": the same row as omitting the key, valid from its `TxFrom`. `types.ExplicitInstant(0)` as `tkg_valid_from` / `tkg_valid_to` is refused there (`ErrZeroInstantLegacyAxis`); on an `UntimedWholeAxis` store 0 is an ordinary instant. See "The valid axis".

### Entity management

- `g.Nodes().Add(ctx, labels, props)`, `Import(ctx, id, labels, props)` (caller ID; 0 → `ErrZeroID`, negative → `ErrInvalidID`), `AddByIDIfAbsent(ctx, id, labels, props) (*types.Node, created bool, error)` (an existing ID returns that node, no error).
- `g.Rels().Add(ctx, typeName, start, end, props)`, `AddByID(ctx, typeName, startID, endID, props)`, `AddByIDIfAbsent(...)`, `Import(ctx, id, typeName, start, end, props)`. Creation validates the type name, locks and re-reads both endpoints, captures `FromNodeHash` / `ToNodeHash` and runs temporal constraints.
- `g.Nodes().NextID()` / `g.Rels().NextID()` mint and return the next ID; nothing is written (0 on a nil or zero-value graph).
- **Re-importing a deleted ID continues its chain** (`Import`, `AddByIDIfAbsent`, `GraphTx.ImportNodeWithID` / `ImportRelationshipWithID`): the new row's version is one above the ID's highest, its `PrevHash` names that row (`Verify*Chain` verifies across lives), and it is stamped after every `TxFrom` / `TxTo` / `DeletedAt` of the chain; a `tkg_tx_from` at or below one is `ErrTxOrder`, nothing written. Reads see the earlier life end at its delete and the new one start at its own valid start.
- Cross-machine edges (sharded/partitioned stores only, else `ErrForeignEndpointUnsupported`): `g.Rels().AddByIDForeignEnd(ctx, typeName, startID, foreignEnd store.ForeignEndpoint, props)` creates a rel whose END lives on another machine (caller supplies its attested hash; `ErrInvalidForeignEndpoint`, `ErrForeignEndpointConstraint`); `g.Rels().RecordForeignIncoming(ctx, store.ForeignIncomingEdge)` records the incoming half-edge on the END machine.
- **Transaction-time backfill** (gate `Config.AllowTxBackfill`, else `ErrTxBackfillDisabled`): `g.Nodes().AddWithTx(ctx, labels, props, txFrom)` / `g.Rels().AddWithTx(...)` create with the caller's `TxFrom` (= passing `tkg_tx_from` to any create door). `txFrom` must be positive and not in the future (`ErrInvalidTxFrom`). `TxFrom` / `TxTo` are not hashed.
- `g.Nodes().UpdateWithTx(ctx, id, updates, txFrom)` / `DeleteWithTx(ctx, id, txTo)` and `Rels()` mirrors (same gate; on `UntimedWholeAxis` use `EndValidity` for a delete that keeps the past): supersede or end belief at caller instant `t`. Update: old version `TxTo = t`, new `TxFrom = UpdatedAt = t`. Delete: tombstone `TxTo = DeletedAt = t` (open `ValidTo` clamped to `t`), cascaded to every rel of a node at the same `t`. Reads pinned before `t` see the old belief. Refusals, in order, nothing written: `t` ≤ 0 or future `ErrInvalidTxFrom`; gate `ErrTxBackfillDisabled`; then under the entity lock `ErrTxOrder` when `t` is not after every `TxFrom` / `TxTo` of the chain and the current version's start (node and cascaded rels), when a row to tombstone has a recorded close at or after `t`, or when the update changes nothing; `ErrAlreadyClosed` for an update of a closed entity; a second delete `ErrNodeNotFound` / `ErrRelNotFound`. `t` does not advance the commit clock. Replays pass `tkg_valid_from` explicitly. Upgrade replicas before a writer uses these doors. Twins with the same rules: `GraphTx.*WithTx`, `BatchBuilder` / ingest `Session` doors of the same names.
- `g.Nodes().Retract(ctx, id)` / `RetractWithTx(ctx, id, txTo)` and `Rels()` mirrors — "this was never true". `Delete` ends validity (pins after it still see the past); `Retract` at `T` ends belief: at pins ≥ `T` the entity is absent at every valid time from every state door, record door and effective timeline; pins before `T` are unchanged. The tombstone is a delete tombstone with `Retracted == true`; a node retraction cascades like a delete. The retracted life is the rows since the previous delete; an earlier life keeps answering. `RetractWithTx` has `DeleteWithTx`'s checks. An ID already deleted or retracted fails with an error matching both `ErrEntityDeleted` and the not-found sentinel. Twins: `GraphTx.Retract*`, `BatchBuilder` / `Session` doors. Upgrade every reader before a writer retracts: older binaries read a retraction as a delete.
- `g.Nodes().EndValidity(ctx, id)` / `g.Rels().EndValidity` (GraphTx: `EndNodeValidity` / `EndRelValidity`) — the delete that keeps the valid past on every axis (on the legacy axis identical to `Delete`; on `UntimedWholeAxis`, where `Delete` retracts, the delete that keeps history readable). No `*WithTx`, batch or ingest twin.
- `Update(ctx, id, updates)` (versioned; accepts provenance shadow keys, rejects other `tkg_` keys), `UpdateInPlace(ctx, id, updates)` (no new version, no history row; for metadata corrections), `Delete(ctx, id)` (node delete cascades to its rels; rel delete events precede the node's).
- **Whole-row replace** (ADR-0014; listed labels only, `Config.ReplaceVersionLabels`, else `ErrReplaceVersionNotListed`): `g.Nodes().ReplaceVersion(ctx, id, props, validFrom, validTo)` / `GraphTx.ReplaceNodeVersion(id, props, validFrom, validTo)` replace the node's current row whole as a new version: `props` is the complete property set (plain keys only, `ErrReservedPrefix` for a `tkg_` key; a create's limits), `[validFrom, validTo)` its validity (`validTo` the axis's open end, 0 on the legacy axes, for an open row; a closed end must follow the start and `validFrom` must be a claim, else `ErrInvalidTimeRange`). Any relation to the current version is accepted: a closed row, an equal, earlier or later start, a grown, shrunk or opened end, properties alone. The current version moves to history with `TxTo` at the new `TxFrom` (the commit clock); indexes follow in the same write. Record doors (`NodeAsOf`, `TxPin`, index reads at a pin) answer the new version alone at or after it and the old row before; the effective timeline shows an older version only at valid instants the new one does not cover (architecture.md ADR-0014). A call changing nothing writes nothing. No batch, ingest or `WithTx` twin, no relationship mirror.
- `AddLabel(ctx, id, label)` / `RemoveLabel` (`ErrLastLabel`, `ErrLabelNotFound`, `MaxLabelsPerNode`). Names are validated first (`ErrEmptyName`, `ErrNameTooLong`).
- A versioned mutation of an entity at version `math.MaxUint32` returns `ErrVersionOverflow`.

### Properties

- `SetProperty(ctx, id, key, value)` / `DeleteProperty(ctx, id, key)` on `Nodes()` and `Rels()`.
- `CompareAndSetProperty(ctx, id, key, expected, newVal) (bool, error)`: `(true, nil)` on match + write, `(false, nil)` on mismatch. `expected == nil` means "must not exist", `newVal == nil` deletes. A numeric `expected` compares under property equality, others under value identity. A successful CAS writes a new version.

### Resolution

- Names: `g.Nodes().Labels(n)`, `PrimaryLabel(n)`, `HasLabel(n, label)`, `g.Rels().Type(r)`, `HasType(r, typ)`.
- Shadow properties (22 `tkg_*` keys, listed in [architecture.md](architecture.md)): `g.Resolve().NodeProperty(n, key)`, `RelProperty(r, key)`.

### Reads

- Point: `g.Nodes().Get(ctx, id)` / `g.Rels().Get(ctx, id)` return a mutable copy.
- Point without a copy: `Lend(ctx, id)` returns the store's FROZEN current row (memory, badger, tiered: no copy; other stores a frozen copy). A lent row is never written later and may be held and read from any goroutine; it does not follow later writes (check `NodeMutationEpoch` / `RelMutationEpoch`). Error-returning mutators fail with `types.ErrFrozenNode` / `ErrFrozenRelationship`, others panic; `DeepCopy` thaws. Capability `store.EntityLendCapability`.
- Property without a copy: `Node.BorrowProperty(key)` returns the stored value itself, where `GetProperty` deep-copies a slice or map (a 64 KiB `[]byte` read: 0 allocations instead of 64 KiB). Do not modify it. A write to the node stores a new value, so a borrowed one keeps its content after later writes and after the store closes. With `Lend`, a read of a blob copies nothing.
- Many without a copy: `LendByIDs(ctx, ids, fn(i, row) bool) error` lends each ID's current row with its position `i` in `ids`: unknown IDs skipped, ascending ID order, `fn` false stops, `fn` runs without locks; a non-positive ID fails with `ErrInvalidStoreMutation` before any read. Capability `store.EntityLendBatchCapability`.
- Read budgets (since v4.107.0, RH list R2): `ctx, meter := store.WithReadBudget(ctx, store.ReadBudget{Candidates, Segments, ShardOpens, DecodedBytes, HistoryExamined, BufferBytes})` (a zero field is unbounded) bounds the internal work of selective reads, not only their rows. A door that supports budgets counts into the meter and, before the work that would pass a limit, returns `*store.ReadBudgetError{Door, Limit, Budget, Work}` (`errors.Is(err, store.ErrReadBudget)`) and no rows, so an answer is exact or refused. `meter.Work()` gives the counters under or over the limit. The meter is cumulative over every call made with the context, and once one read on it is refused the context is spent: `meter.Exceeded()` keeps the first refusal, and tiered's parallel fan-outs refuse before their next shard on that context, even a shard already open; a budget made inside another adds its work to the outer meter too, and the tighter limit stops first. A context without a budget changes nothing. Doors: `Temporal().RelEffectiveTimelinesByProperties` (each member the index hands on, counted as it is handed on, so a refusal comes at the member that passes the limit, before any timeline is decoded; output segments) and `LendByIDs` (one candidate per ID; on tiered each closed shard about to be opened, refused before it opens: `store.EntityLendBatchMeteredCapability`). Since v4.107.1 also `Nodes().ByLabelAndPropertyCtx`, `ByLabelAndPropertyValuesCtx` and `ByLabelAndPropertiesCtx` (an index's matches; a key without an index, or a key set without a composite definition, falls back to the label's every node, which counts before the scan reads a row; a temporal read counts each membership entry the index hands on, before its pin and intersection filters (since READBUDGET step 4: a dense key intersected with a sparse one counts the dense key's entries), each current match it adds, and on the history fold each candidate before it is resolved), `GetByIDsCtx` (one per ID), `HasHistoryCtx` and `LatestStampsCtx` (one each), and `Rels().LendByIDs` (one per ID; tiered counts the opens of its miss probe over the other shards: `store.RelLendBatchMeteredCapability`). Since R2 (Sigma doors, group A) also `Rels().GetByIDsCtx` (one candidate per ID, then the stored bytes of each row the store decodes and, on tiered, each closed shard it is about to open, refused before the open: `store.RelsByIDsMeteredCapability`; badger, sharded, tiered), `Rels().HasHistoryCtx` and `Rels().LatestStampsCtx` (one candidate each, and on tiered the closed shards the route and the history walk are about to open, counted before they open: `store.RelStampsMeteredCapability`; they decode no row, except the tiered fold over several shards, as for nodes). Also `Rels().ByTypeAndPropertyCtx` (each index match counted inside the store before its row is decoded, a key without an index counting the type's every relationship before the scan reads one, then `DecodedBytes` and, on tiered, `ShardOpens`: `store.RelPropertyQueryCandidatesMeteredCapability`; the on-disk index, `RelPropertyIndexOnDiskTypes`, admits each candidate as its walk produces it; a read at a time coordinate, `TxAt`, `TxPin`, `ValidAt` or the valid interval, counts as the node twin `ByLabelAndPropertyCtx` does (since R2, Sigma doors group D): each membership candidate as the index hands it on, before the pin filter (a membership kept on disk, `RelPropertyIndexOnDiskTypes`, admitted as its fold grows under a `Candidates` limit), the current lookup's matches and decodes, and each candidate's current row, history skeleton and winning version through a metered read snapshot (`DecodedBytes`, `HistoryExamined`, on tiered `ShardOpens` before each open; a `TxPin` read on badger and memory through `store.TransactionTimeQueryMeteredCapability`), with the candidate set and the rows as `BufferBytes`; a type with no usable membership index folds its history and counts each candidate before it is resolved, and on tiered a `ShardOpens` budget refuses before that walk, `Limit` `"unsupported"`) and `Nodes().IDsByLabelAndPropertyValuesCtx` (the ID-only lookup: the index entries counted inside the store as the walk produces them (badger and tiered; the memory store counts them after it answered), before they are collected, from a RAM or an on-disk index, on tiered each closed shard charged before its open; a lookup that falls back to the rows, a key without an index or a time coordinate, reads and counts as `ByLabelAndPropertyValuesCtx`). Also `Rels().OutgoingCtx` and `Rels().IncomingCtx` (the adjacency of one node; `Nodes()` has no adjacency door: its entries counted as candidates before they are collected, a RAM index counting the node's whole set before the list is built, so a type filter costs the whole set, and the on-disk adjacency index, `AdjacencyIndexOnDisk`, each entry as its walk produces it, so a type filter costs only the type's entries; then `DecodedBytes` of each row decoded and, on tiered, each closed shard opened, counted before the open, a reference node's mint-placed rels (`RelsByMint`) included: `store.AdjacencyMeteredCapability` on badger, sharded and tiered; the memory store and a wrapper that cannot count have the node's degree counted before the read, `store.DegreeCapability`, else the rows after). Since R2 (Sigma doors, group D) also `Nodes().ByLabelCtx` (the label's current members: each member counted as a candidate where the store lists it, before its row is read: a RAM label index counts its whole set before the list is built, one kept on disk, `LabelIndexOnDisk`, each entry as its walk produces it and each pending add, so a budget of 1 over many members stops at the listing and a disk label visits two index entries, not the label; then `DecodedBytes` of each row decoded and, on tiered, each closed shard opened, counted before the open: `store.NodesByLabelMeteredCapability` on badger, sharded and tiered; the memory store and a wrapper charge the label's count before the read; a read at a time coordinate is the label's history, which the door does not bound, and is refused under a budget with `Limit` `"unsupported"` before any work: the budgeted time reads of a label's members are the effective scans and the property doors). Since READBUDGET step 3 also `Temporal().NodeAsOfCtx(ctx, id, txTime)` and `RelAsOfCtx`: `NodeAsOf`'s rule and answer at the same pin, with the rows decoded (`DecodedBytes`) and history versions looked at (`HistoryExamined`) counted before they are (badger and memory through `store.TransactionTimeQueryMeteredCapability`, sharded and tiered through a metered read snapshot); an `Ops` given to `temporal.New` without these doors refuses a budgeted context (`Limit` `"unsupported"`). The Ctx doors check `ctx` first and, without a budget, are their plain doors. `DecodedBytes` (`ReadBudget.DecodedBytes`, `ReadWork.DecodedBytes`) bounds the decode work: the stored (wire) bytes the store hands to a row decoder, counted before the decode, so a read past the limit stops before it decodes the row that passes it, with the error naming the door, `"decoded bytes"` and the counters, and no rows. `LendByIDs` streams in chunks of 4,096 IDs, so a refusal hands out no row of the chunk it stops in, while `fn` has seen the earlier chunks' rows: a caller that needs exact-or-refused keeps one call within 4,096 IDs. It counts each current row decoded, each history version decoded (a delta row and its anchor) and each history skeleton decoded, a partial decode at the whole value handed to it, a history row decoded twice (skeleton, then winner) twice. It counts decodes, not data touched: a row the store serves from its entity cache decodes nothing and counts 0 (so a warm read reads 0 and the count depends on the cache), nor does the memory store, which keeps rows decoded; index reads count as Candidates; badger's block decompression and value log reads below the row are not counted. The parallel decode of a large label scan counts badger's `ValueSize` before it copies the row: exact for a value stored in the LSM tree, a few bytes off for one in the value log (at or above `ValueThreshold`). Counted: `RelEffectiveTimelinesByProperties` (current rows, skeletons and winning versions, through the store's read snapshot: badger, sharded and tiered, every shard), `Nodes().LendByIDs` and `Rels().LendByIDs` (badger, sharded, tiered: the rows missing from the cache, `LendNodesSortedMetered`), `GetByIDsCtx` (`store.NodesByIDsMeteredCapability`) and the node property doors (an index's matches, a label scan's rows; with a time coordinate, `TxAt`, `TxPin`, `ValidAt` or the valid interval, each candidate's current row, history skeleton and winning version, read through a metered read snapshot, and on badger `TxPin` through `store.TransactionTimeQueryMeteredCapability`, at the same pin and with the same answer). Not counted: `ValidEndAfter` (Candidates still bound it), a unique key's owner lookup, `HasHistoryCtx` and `LatestStampsCtx` (they read RAM sidecars and at most a row's temporal block, no row), each reads as 0 decoded bytes, except `LatestStampsCtx` on tiered over a history spanning several shards, whose fold counts the rows it decodes. A store that cannot count decodes or shard opens (a wrapper embedding a native store) refuses, before any read, a budget that bounds `DecodedBytes` or `ShardOpens`: `*store.ReadBudgetError` with `Limit` `"unsupported"` (since READBUDGET step 7; it read unbounded and reported 0); budgets bounding only `Candidates`, `Segments`, `HistoryExamined` or `BufferBytes`, which the core counts, still answer. Pending (unflushed) history rows, cache misses, the label-scan fallbacks and the parallel decode of a large label scan (counted in its serial staging pass) obey the same meter; an entity's history rows are copied into a read snapshot before they are decoded and counted, and shards read in parallel each stop at their next row. `HistoryExamined` (since READBUDGET step 2, `ReadBudget.HistoryExamined`, limit `"history examined"`) bounds the history versions the reads look at: each history row the store hands to a reader (a skeleton entry, a temporal peek of badger's as-of walk, a decode), counted before it is looked at, a version read twice (skeleton, then winner) twice; the memory store, which has no read snapshot, counts the versions of an entity's chain when it reads them, before they are resolved. It is counted wherever `DecodedBytes` is, and on memory. `Segments` counts the segments returned, each as it is kept, before it joins the answer (since READBUDGET step 5; it was counted after the whole answer was built). Under a `Segments` or `BufferBytes` bound (`meter.BoundsOutput()`), `RelEffectiveTimelinesByProperties` reads one entity at a time, so a refusal comes before the next entity is decoded (READBUDGET step 8; it decoded up to 256 entities ahead). Since step 8 the node property doors' index and composite lookups on badger, sharded and tiered count each match, and a fallback scan the label's nodes, inside the store before the temporal pre-filter and the decode (`store.PropertyQueryCandidatesMeteredCapability`); before, the matches were decoded and then counted. Since R2 (gap A) the on-disk property index (`PropertyIndexOnDisk`, `PropertyIndexOnDiskLabels`) admits each candidate as its equality walk produces it, so a read past a `Candidates` limit has visited the index entries up to the one that passes it, not the whole key (it collected, sorted and compacted every match before it counted one); an entry a later walk of one lookup visits again, or a node an Elements index lists under two of the looked-up values, counts again (a budget reads high, never low). A temporal property door's current lookup (the current matches it unites with the history candidates) runs under the same meter: its matches and decodes count before the decode, and the history fold does not count them again. One entity per read costs a graph read-lock cycle and a snapshot release per entity, so a key with many members reads slower under a `Segments` or `BufferBytes` bound than without one. `BufferBytes` (limit `"buffer bytes"`) bounds a read's temporary buffers, a logical estimate charged before each entry is added: 24 bytes per candidate-set entry (temporal property doors, the history fold's seen set, current matches added), 8 per ID or row pointer (`RelEffectiveTimelinesByProperties`' member list, the property doors' result rows), a segment's struct size per kept segment. It is not the Go heap; the stores' own buffers are not counted. `ShardOpens` (limit `"shard opens"`) counts, on tiered, each closed shard a budgeted read is about to open (a cold event shard, or the archive before its first open after `New`), under the shard's lock before the open, so a refusal leaves the shard closed; a shard already open counts nothing (an archive opened by a racing read in between still counts: high, never low). Since READBUDGET step 6 every budgeted read charges it: `LendByIDs`, `GetByIDsCtx`, the metered read snapshot (every routed checkout and the whole-chain history search: the node property doors with a time coordinate, `NodeAsOfCtx`, `RelAsOfCtx`, `RelEffectiveTimelinesByProperties`), the node property doors' current index and label-scan fan-outs, and their membership enumeration (`store.PropertyTxMemberMeteredCapability`, optional, badger and tiered: the Keys enumerations with a `window` and a `*ReadTally`). A fan-out's workers check `meter.Exceeded()` (the first refusal) before each shard, so once one refuses the others stop at their next shard; their errors join (`errors.Is(err, store.ErrReadBudget)`). `HasHistoryCtx` and `LatestStampsCtx` charge them too (`store.NodeStampsMeteredCapability`, tiered), and on a wrapper store refuse a `DecodedBytes` or `ShardOpens` budget as the other doors do. The history fold of a temporal property door with no usable index (the history-ID walk and `LabelTxMembersOf`) cannot count its opens: on tiered under a `ShardOpens` budget it refuses before the walk (`Limit` `"unsupported"`). The stores that open no shard (badger, sharded, memory) count 0. Since R2 (gap B) a membership kept on disk (the `0x0C` member entries of `PropertyIndexOnDisk`, `PropertyIndexOnDiskLabels` and `RelPropertyIndexOnDiskTypes`) is bounded before the door counts its first member: on badger and tiered, under a `Candidates` limit the exact (`TxPin`) and window (`ValidAt`, the valid interval, `RelEffectiveTimelinesByProperties`) walks admit their fold as it grows (`store.ReadTally.CandidateRoom` is the room the meter has left, `CandidatesAhead` the refusal) and stop at the member that passes it, on every shard of a tiered fan-out under the same tally, returning `*store.ReadBudgetError` (`Limit` `"candidates"`, the held fold added to `Work.Candidates`) with no member handed on; before, each shard folded, sorted and handed on its whole value first and the door refused at its first callback after all of it. The door still counts each member it hands on, so what a budget answers is unchanged. Not yet bounded: the entries a window walk visits and rejects (late-axis rows whose envelope misses the window, `PropertyMemberWork.IteratorSteps`), a pending-write overlay held before the walk, a label scan fallback's ID snapshot (counted after it is built) and the `ValidEndAfter` pruning door.

### Batch operations

`g.Batch().New() (*BatchBuilder, error)`; `g.Batch().Run(fn)` / `RunContext(ctx, fn)` build, execute and return the `*BatchResult`. Queue methods: `AddNode`, `AddNodes(labels, props, count)`, `AddRelationship`, `UpdateNode`, `UpdateRelationship`, `DeleteNode`, `DeleteRelationship`, the caller-instant `UpdateNodeWithTx`, `UpdateRelationshipWithTx`, `DeleteNodeWithTx`, `DeleteRelationshipWithTx`, the retractions `RetractNode`, `RetractRelationship`, `RetractNodeWithTx`, `RetractRelationshipWithTx`, the corrections `SetNodeVersionInterval` / `SetRelVersionInterval` (+ `WithTx`) and `ExciseNodeValidity` / `ExciseRelValidity` (+ `WithTx`). Inputs are validated at queue time; caller update maps are copied.

`Execute()` applies creates, then updates, then deletes, and is **per-operation, not all-or-nothing**: it returns `*BatchResult{Created, Updated, Deleted, Failed, Errors []BatchError, Duration, CommittedLSN}` and, if any op failed, an error wrapping `ErrBatchFailed`. Exception: caller-instant ops are pre-flighted over the whole unit before any write, so one refused caller-instant op refuses the batch (nothing written); each must be the only op of the unit on its entity (else `ErrTxOrder`). The batch is atomic against readers. Events are published after the locks are released, in one `PublishBatch`. `Execute` is one-shot (`ErrBatchDone`). Under `Config.DurableCommit` it returns after the fsync (`ErrCommitNotDurable`).

### Ingest pipeline (`g.Ingest`)

Prepare-parallel / apply-sequential write door for insert-heavy loads, beside `g.Tx()`. `g.Ingest().NewSession(IngestOptions) (*Session, error)` (`ErrReadOnlyReplica`, `ErrGraphClosed`); prepare methods (`AddNode`, `AddNodes`, `AddRelationship`, `UpdateNode`, `UpdateRelationship`, `DeleteNode`, `DeleteRelationship`, `RetractNode` / `RetractRelationship`, `SetNodeVersionInterval` / `SetRelVersionInterval`, and the caller-instant `*WithTx` doors with the batch rules) validate, hash and mint IDs on the caller thread. `Submit()` hands the group to one applier goroutine, which applies each group atomically against readers with one `TxFrom`, one LSN run and one flush. `Pending()`, `Close()` (submits the rest).

`IngestOptions`:
- `Sync: true` — `Submit` returns after the group is applied and visible, with the group's own error. `Sync: false` — `Submit` returns a `SubmitToken{Lane, Seq}`; `g.Ingest().WaitApplied(token)` returns nil or the group's real apply error (`AppliedSeq() ≥ token.Seq` means processed, not necessarily committed).
- `DeclareLabels` / `DeclareRelTypes` pre-register vocabulary. `QueueBound` bounds the queue; at the bound `Submit` blocks. A `Submit` racing `Close` is applied or refused with `ErrIngestClosed`, never dropped.
- `Concurrent: true` — each session applies its groups itself under per-entity locks, so N sessions write in parallel. `Submit` is synchronous; a group is atomic per entity only, not against readers; `QueueBound` is ignored. Prefer the default mode on fsync-bound (`SyncWrites`) storage.

Use `g.Tx()` for read-modify-write logic. Caveat: with the change-log enabled, every `GraphTx` mutation takes the exclusive graph lock for its call, blocking concurrent standalone writes and concurrent ingest sessions; route bulk writes through `g.Ingest()` then.

### Temporal queries (`g.Temporal`)

All temporal reads are history-aware (deleted entities included). A row without a valid-from starts at its `TxFrom` (see "Valid-time start"); `types.NodeID.MintInstant()` is only the last fallback for legacy rows. Finite valid ranges are half-open and need `ValidFrom < ValidTo`. Temporal property doors reject `tkg_` keys (`types.ErrReservedPrefix`); use `g.Resolve` for shadow values.

**Record door vs state door.** `NodeAsOf(id, pin)` / `RelAsOf` and `QueryOpts.TxPin` are RECORD doors: the newest row recorded by the pin, whatever valid time it covers. `NodeAtTx(id, t, pin)` and the effective timelines are STATE doors: the state at valid time `t` as recorded at the pin. After a bounded correction `[2000,3000)` the record door answers the correction at every valid time, the state door only inside `[2000,3000)`.

- Point: `NodeAt(id, t)`, `RelAt(id, t)`, `NodesAt(t)`, `RelsAt(t)`, `NodesByLabelAt(label, t)`, `RelsByTypeAt(type, t)`, `NeighborsAt(nodeID, t)`, `NodesByLabelPropertyAt(label, key, value, t)`, `RelsByTypePropertyAt(...)`, `OutgoingRelsAt(nodeID, t)` / `IncomingRelsAt` (deleted rels included).
- Interval: `NodesDuring(start, end)`, `RelsDuring`, `NodesByLabelPropertyDuring(label, key, value, start, end)`, `RelsByTypePropertyDuring`. `end == 0` is open; else `start < end`.
- Allen predicate: `NodesRelating(from, to, rels types.AllenRelationSet)` / `RelsRelating`: entities with ANY version whose valid interval has a relation in `rels` to `[from, to)` (also non-overlapping ones such as `Before`). `to == 0` is open; `from == 0` or `from >= to` is `ErrInvalidTimeRange`; an empty set yields nothing.
- Record pins: `NodeAsOf(id, txTime)`, `RelAsOf`, `NodesAsOf(txTime)`, `RelsAsOf`: the highest version with `TxFrom <= txTime`, absent when superseded or deleted by then; `ErrNoVersionAsOf` when nothing was recorded by then. The answer at a pin never changes after later writes.
- State pins: `NodeAtTx(id, validAt, txAt)` / `RelAtTx`, `NodesAtTx(validAt, txAt)` / `RelsAtTx`, `NodesDuringTx(from, to, txAt)` / `RelsDuringTx`.
- Batched point read: `NodesAtTxByIDs(ids, validAt, txAt)` / `RelsAtTxByIDs` return a slice aligned to `ids` with `NodeAtTx`'s row per ID, nil where it answers not-found or `ErrNoVersionValidAt`. Whole-call errors: `ErrGraphClosed`, `ErrInvalidStoreMutation`, `txAt == 0` (`ErrInvalidTimeRange`; a negative pin answers all nil), `ErrTxPinTooNew`, `ErrHistoryCompacted`, `ErrRetentionExpired`. Not call-level isolation: a writer can land between chunks of 256 IDs. Returned rows are shared: do not mutate.

  ```go
  pin, _ := g.Temporal().NowTx()
  nodes, err := g.Temporal().NodesAtTxByIDs(ids, validAt, pin) // nodes[i] nil: no version at validAt
  ```
- Explicit-presence point doors: `NodeAtOpts(id, opts)` / `RelAtOpts`, `NodesAtOptsByIDs(ids, opts)` / `RelsAtOptsByIDs` take `ValidAt` (+`ValidAtSet`; absent: now) and `TxAt` (+`TxAtSet`) and answer what `ByLabel` with the same opts answers for that entity; a present pin at 0 sees nothing (`ErrNoVersionValidAt`). `TxPin`, a window, `Limit` / `After`, `Depth` or `IncludeEclipsed` is `ErrConflictingTemporalOpts`.
- Clock: `NowTx()` reserves and returns the current transaction instant — the pin for as-of reads and `TagAsOf`; every committed write has `TxFrom <= NowTx()`, every later one is stamped greater. Take read coordinates after a write from `NowTx()` / `CommittedTx()`, never `time.Now()` (the clock runs ahead of wall time under bursts). `CommittedTx()`: the open transaction's `StartInstant` while a `GraphTx` is open, else a fresh `NowTx`; a read pinned there sees no uncommitted transaction write (not covered: privileged backfill, a standalone mutation in flight). `PeekTx()` reads the clock without reserving (metrics only, not a sound pin). `AdvanceClock(to)` raises the clock floor (HLC merge seam; `ErrInvalidClockAdvance` when implausibly far ahead).
- Belief-state pin on the generic doors: `QueryOpts.TxPin` makes `ByLabel` / `ByType` / `All` resolve through the as-of resolver: `ByLabel{TxPin: T}` = `NodesAsOf(T)` filtered by label. `TxAt` alone filters valid time at now and drops past-valid facts.
- Snapshot / diff: `Snapshot(t) (*GraphSnapshot, error)` (holds the graph write lock; `tx.Snapshot(t)` inside a transaction), `Diff(t1, t2) (*SnapshotDiff, error)` (`NodesCreated`, `NodesUpdated [{Before, After}]`, `NodesDeleted`, rel mirrors), `DiffCallback(t1, t2, handlers)` (handlers run outside the graph lock).
- Allen relations of stored entities: `NodeInterval(n)` / `RelInterval(r)` `(start, end, err)`, `RelateNodes(a, b)` / `RelateRels(a, b)` `(types.AllenRelation, error)`; an open-ended version is `types.ErrOpenInterval`, nil inputs `ErrNilNode` / `ErrNilRelationship`.
- Named as-of marks: `TagAsOf(name, at)`, `ResolveAsOf(name) (Instant, bool, error)`, `AsOfTags()`, `RemoveAsOfTag(name)` (idempotent). Durable, cleared by `Admin().Reset()`; `name` non-blank ≤ 256 bytes and `at > 0` (`ErrInvalidAsOfTag`), at most 4096 marks (`ErrTooManyAsOfTags`); needs MetaKV (`ErrCapabilityNotSupported`); refused on a read-only replica.
- Valid-time predicate for a materialized entity: `NodeMatchesValidTime(n, opts)` / `RelMatchesValidTime(r, opts)` apply the store's rule; nil entity or graph not ready → false.

**Effective timelines** (state doors over valid time):
- `NodeEffectiveTimeline(id, pin) ([]temporal.NodeSegment, error)` / `RelEffectiveTimeline` (`NodeSegment{ValidFrom, ValidTo, Node}`). Segments ascend, never overlap, are half-open (`ValidTo` 0 open), omit gaps; for every `t` the segment containing `t` holds `NodeAtTx(id, t, pin)`'s row. Adjacent segments hold different rows; equal content is never merged. `ValidFrom` is the effective start, never 0. A deleted entity's last segment ends at the delete; an entity created after the pin, or pin ≤ 0: nil, nil. Rows are shared frozen pointers. Errors: `ErrTxPinTooNew` (pin above the clock), `ErrHistoryCompacted`, `ErrRetentionExpired`, `ErrNodeNotFound` / `ErrRelNotFound`, `ErrInvalidStoreMutation`, `ErrGraphClosed`, `ErrNilGraph`.
- Tail: `NodeEffectiveTimelineFrom(id, validFrom, pin)`: `NodeEffectiveTimeline(id, pin)`'s segments that end at or after `validFrom` or are open (a segment ending at `validFrom` counts, as in the From scans), each whole; `types.UnboundedValidFrom` is the whole timeline (a segment may end below 0). Errors as the singular door. Cost: from the head-pin entry a `NodeEffectiveTimeline` read keeps, and on badger from the per-version temporal skeletons, only the returned segments' rows are read; otherwise the whole chain, as the singular door. For a writer extending a long timeline (WRITEGROW).
- Many pins: `NodeEffectiveTimelines(id, pins)` / `RelEffectiveTimelines`: result `i` = the singular door at `pins[i]` (unsorted and repeated pins allowed); one chain walk for all pins; one bad pin refuses the whole call with the singular error. Segment rows are frozen and, on memory, badger and tiered, the current row is the store's own row as `Lend` returns it (no copy): read it, `DeepCopy` to change it. On memory a history version is the store's own frozen row too, on every effective timeline door and scan (optional capability `store.VersionLendCapability`, HEADLEND). To read a few columns without a map, range the keys with `ForEachPropertyTypeClass` and read each with `GetProperty`. A history version is decoded beside the current row: its string values equal to the current row's are that row's own (not allocated again), and with every property equal it shares the frozen row's property slice (optional capability `store.NodeVersionSharingCapability`, badger and tiered; through a read snapshot the snapshot's lent row). Cost per call: one badger read per row (current, skeleton, version), each value copied twice by badger, so a listing reads cheaper through `ForEachNodeEffectiveByLabelAndProperties`.
- Lowest answered pin: `NodeLowestAnsweredPin(id)` / `RelLowestAnsweredPin`, plural `NodesLowestAnsweredPins(ids)` / `RelsLowestAnsweredPins`: the lowest pin at which the point reads answer without `ErrHistoryCompacted` / `ErrRetentionExpired` (0: every positive pin). A retention purge removes whole entities, so pins that answered a purged entity now answer not found.
- Scans (`fn` false stops; `fn` runs without graph locks; answers at a pin are stable while writers commit above it; entities deleted before the pin included, created after it excluded; one entity's segments contiguous and ascending; no `context.Context`): `ForEachNodeEffectiveByLabel(label, pin, fn)` / `ForEachRelEffectiveByType(type, pin, fn)` (segments whose row carries the label / type: at every `t` exactly `ByLabel(label, {ValidAt: t, TxAt: pin})`), `ForEachNodeEffectiveByLabels(labels, pin, fn)`, `ForEachNodeEffective(pin, fn)` / `ForEachRelEffective`, `ForEachRelEffectiveAtNodes(nodeIDs, dir, relTypes, pin, fn)` (rels with a seed at the `temporal.Outgoing` / `Incoming` end, each once; cost follows the seeds' ever-degree), `NodesEffectiveByIDs(ids, pin, fn)` / `RelsEffectiveByIDs` (input order, repeats once, unknown skipped). Errors as the point door, plus `ErrInvalidStoreMutation` for a bad ID, `ErrInvalidDirection`, invalid names; nil `fn` is an error. Candidates are read 256 per graph read lock through one store read snapshot where offered; `fn` may see an entity up to 255 entities after it was read.
- Bounded by valid end: `ForEachRelEffectiveByTypeFrom(type, pin, validFrom, fn)` / `ForEachNodeEffectiveByLabelsFrom(labels, pin, validFrom, fn)` stream only entities with a segment ending at or after `validFrom` (or open), each with its whole timeline. Memory and badger keep a RAM valid-end index ([query-planners.md](query-planners.md), the `ForEachRelEffectiveByTypeFrom` row); tiered unions its shards'.
- Windowed: `ForEachNodeEffectiveByLabelsWindow(labels, pin, window, fn)`, `ForEachRelEffectiveByTypeWindow(type, pin, window, fn)`, `ForEachRelEffectiveAtNodesWindow(nodeIDs, dir, relTypes, pin, window, fn)` stream only segments that meet `window` (`temporal.Window`: disjoint ascending half-open `temporal.Interval{From, To}`; `Validate` refuses empty, overlapping or unordered intervals with `ErrInvalidTimeRange`; `Meets(from, to)` / `MeetsOn(axis, from, to)` test one interval). `ScanRelEffectiveColumnsAtNodes(nodeIDs, dir, relTypes, pin, window, props, fn func(*store.RelColumnBatch) bool)` hands the same segments out as typed columns (`ErrMixedNumericColumn` for a mixed column).
- Paged with a property filter: `RelsEffectivePage(ctx, temporal.Pin{Tx, ValidAt, ValidStart, ValidEnd, ValidAtSet, ValidWindowSet}, temporal.Filter{Prop, Eq}, after types.RelID, limit) (segs, next, err)` / `NodesEffectivePage`: one keyset page of the full walk at `pin.Tx`, keeping segments whose row has `Prop` equal to `Eq` and that meet the valid filter (a lone `ValidStart` means `[ValidStart, ∞)`, unlike `QueryOpts`), over every type (label). `next` is the last ID when the page is full, else 0; pages are stable while writers commit above the pin. **Declare a `(type, Prop)` / `(label, Prop)` property index on every type carrying the property** (else that type is gathered and read per page), and **`CreateRelTemporal` on types paged with a valid filter** (envelope pruning). Each paged value keeps an ordered view (~8 B per member) for the life of the sidecar. Errors: the pin gates, `ErrInvalidTimeRange`, `ErrEmptyName` / `types.ErrReservedPrefix`, `types.ErrUnsupportedValueType` (list, map, nil `Eq`), `ErrInvalidQueryLimit` (`limit` < 1 or > `temporal.MaxPageLimit` = 10,000), `ErrInvalidQueryCursor`, `ErrNilContext`, `ctx`'s error, `ErrGraphClosed`.
- Listing page by composite equality: `ForEachNodeEffectiveByLabelAndProperties(ctx, label, props, pin, temporal.EffectivePageOpts{After, Limit, Depth}, fn(id, segs) bool) (next, err)`: `Nodes().ByLabelAndProperties(label, props, {Depth})` paged by ID (ascending above `After`, at most `Limit` matches, 0 = all), `fn` called for every match with `NodeEffectiveTimelines(id, [pin])[0]` (empty when the match has no segment at the pin). `next` = the last match's ID when the page holds `Limit` matches, the ID whose `fn` returned false (stops), else 0. A match is judged on the current row the timeline reads; segment rows are lent frozen (read, never mutate). Cost: declare `Index().CreateComposite(label, keys)` so candidates come from the posting list without decoding a row; each match is read once (current row, history skeleton, winning history row only), a chunk of 256 through one read snapshot (badger, sharded, tiered's reference shard). Errors: `ByLabelAndProperties`' for label, props and depth, the pin gates, `ErrInvalidQueryLimit` (`Limit` < 0), `ErrInvalidQueryCursor`, `ErrNilCallback`, `ErrNilContext`, `ctx`'s error (checked between nodes), `ErrGraphClosed`; an unknown label answers no match.
- Listing page by a value list: `ForEachNodeEffectiveByLabelAndPropertyValues(ctx, label, props, key, values, pin, temporal.EffectivePageOpts{After, Limit, Depth}, fn(id, segs) bool) (next, err)`: the composite page door with `key` IN `values` (`Nodes().ByLabelAndPropertyValues`) beside the fixed equality pairs of `props` (0 or more; a key may not be both), one call per list of probes (sigma's paged-row join level) instead of a lookup and a timeline read per probe. Paging, `fn`, lent rows and the match on the current row as the composite door. Cost: declare `Index().CreateProperty(label, key)`; the candidates are the key's matches, one index walk over every value (on disk one iterator, one seek per numeric magnitude), and the fixed pairs filter while each candidate is read, so lead with the most selective key; per value about 0.8x the unbatched composition on memory and badger, 0.6x with the index on disk, 0.45x on tiered (`TestRowProbeDoorCostLinearInValues`). Errors: `ByLabelAndPropertyValues`' for label, key, values and depth, a fixed pair's key or value as `ByLabelAndProperties` refuses it, `store.ErrInvalidStoreMutation` for `key` in `props`, `store.ErrElementsIndexUnsupported` on an Elements index, and the composite door's; an unknown label or an empty list answers no match.
- By property tuples: `RelEffectiveTimelinesByProperties(ctx, typeName, keys []string, tuples [][]any, pin temporal.Pin) ([][]temporal.RelSegment, error)`: result `i` holds the segments of `typeName`'s rels whose row carries `keys[j] = tuples[i][j]` for every `j` and that meet `pin`'s valid filter (whole segments, grouped by rel). 1–4 distinct keys; **at least one key needs a declared rel property index** (else, or while it builds, `ErrIndexNotFound`: the door never folds the type's history); name the most selective key first on tiered. Errors: the pin gates, `ErrInvalidTimeRange`, `ErrInvalidStoreMutation` (key count, duplicate key, tuple arity), `ErrEmptyName` / `types.ErrReservedPrefix`, `types.ErrUnsupportedValueType`, `ErrNilContext`, `ErrGraphClosed`. Unknown type: nil per tuple.

**Corrections:**
- `SetNodeVersionInterval(ctx, id, validFrom, validTo, props)` / `SetRelVersionInterval` record a valid-time correction over `[validFrom, validTo)` (`validTo` 0 open): `props` is a PATCH (nil deletes a key) applied to the state valid at each instant; returns the appended version covering `validFrom`. Append-only: earlier pins see the old belief. A correction over a gap appends one new piece and leaves the others untouched. Unique constraints judge the patch like an update. A hard-deleted entity is `ErrEntityDeleted` (also matching the not-found sentinel) on every door.
- `SetNodeVersionIntervalWithTx(..., txFrom)` / `SetRelVersionIntervalWithTx`: the same at a caller instant (gate `AllowTxBackfill`; `ErrInvalidTxFrom`, `ErrTxBackfillDisabled`, `ErrEntityDeleted`, `ErrTxOrder` when `txFrom` is not after every stamp of the chain). Twins on `GraphTx`, `BatchBuilder`, ingest `Session` (the only op of its unit on the entity).
- Excise: see "Excise (valid-time)".

### Version chain navigation

- `History(id)` on `Nodes()` / `Rels()`: the full version chain (void pieces marked `Temporal().Void`; skip them when reading raw intervals).
- `HasHistory(id) (bool, error)`: `len(History(id)) > 0` without reading a row (`store.HistoryPresenceCapability`; badger keeps a RAM set built on the first call).
- `LatestStamps(id) (txFrom, txTo, deleted, err)`: the newest `TxFrom`, the newest `TxTo` / `DeletedAt` (0 when none) and "rows but no current row", over all rows, without reading history (`store.CurrentStampsCapability`, `store.HistoryStampsCapability`). An ID without rows: `ErrNodeNotFound` / `ErrRelNotFound`.
- `VersionBefore(id, version)` / `VersionAfter(id, version)`: `nil, nil` when no neighbour exists; never wraps past `math.MaxUint32`.
- Non-positive IDs return `ErrInvalidStoreMutation` on these doors.
- Store-level `TruncateNodeHistory(id, keepVersions)` / `TruncateRelHistory(id, keepVersions)` (store methods): 0 clears all, negative `ErrInvalidStoreMutation`.

### Valid-time start (Config.UntimedValidStart)

A row's start is `storeutil.EntityValidFrom`: explicit `tkg_valid_from`, else its `TxFrom`, else (legacy rows) `UpdatedAt`, else the ID's mint instant. `Config.UntimedValidStart` decides what a create stores for an entity's FIRST version without a valid-from:

| Mode | First version without a valid-from | Later version without a valid-from |
|------|------------------------------------|-------------------------------------|
| `graph.UntimedDefault` (zero value) | an existing store keeps its persisted mode; a new store is `UntimedUnbounded` (announced: a later minor, no target release, makes it `UntimedWholeAxis`; set `UntimedUnbounded` to keep it) | valid from its `TxFrom` |
| `graph.UntimedFromTxFrom` | stores `ValidFrom` 0: valid from its `TxFrom` | valid from its `TxFrom` |
| `graph.UntimedUnbounded` | stores `types.UnboundedValidFrom` (`math.MinInt64`): valid from -inf | valid from its `TxFrom` |
| `graph.UntimedWholeAxis` (opt-in) | `ValidFrom = types.UnboundedValidFrom`, `ValidTo = types.InfiniteValidTo` | no valid-time claim: applies to every valid-time segment |

**The valid axis** (`types.ValidAxis`, fixed per store, answered by `g.Admin().ValidAxis()`): `types.LegacyValidAxis` (`UntimedFromTxFrom`, `UntimedUnbounded`): a stored `ValidFrom` 0 is no claim, a stored `ValidTo` 0 the open end. `types.LiteralValidAxis` (`UntimedWholeAxis`): every stored value is the instant it names; the open end is `types.InfiniteValidTo` (`math.MaxInt64`), the untimed start `types.UnboundedValidFrom`; positional write bounds (`SetNodeVersionInterval`, excise, `CloseVersion`) of 0 are the instant 0. Read raw rows (`History()`, `ValidRange()`, column batches, segments, the shadow resolver) through the axis: `axis.NodeStart(n)` / `RelStart(r)`, `axis.Open(vt)` / `End(vt)`, `axis.ValidToAtTxTime(tm, pin)`, `axis.Relate`. Query parameters keep their conventions on both axes. Rows carry no axis flag.

**`UntimedWholeAxis`** is fixed at store creation: a store with rows of another mode refuses it, a store created under it refuses every other explicit mode (`ErrUntimedModeMismatch`), `SetUntimedValidStart` neither names nor leaves it; it needs `store.ValidAxisCapability` with MetaKV (`ErrCapabilityNotSupported`); exports carry it (export format 4, refused by older releases). A write without a valid time makes no valid-time claim (SQL:2011 UPDATE without `FOR PORTION OF`): an untimed update (or label change) writes a new version per valid-time segment that does not already hold the change, keeping boundaries, and ends the old versions in transaction time only; an untimed delete is a retraction (use `EndValidity` to keep the past). Label refusals are per segment (`ErrTooManyLabels`, `ErrLastLabel`, `ErrLabelNotFound`). `CompareAndSetProperty` on an entity that is not one whole-axis segment is `ErrUntimedModeMismatch`. Timed writes keep their rules.

Every create door applies the mode; every reader takes the start from the row. An explicit `tkg_valid_from = 0` is "unset" (only `g.Resolve()` shows the raw 0). Later versions start at their `TxFrom` in every mode; a close keeps its version's start.

**Persistence and conversion.** The mode is stored with the store (MetaKV `untimed_valid_start`, kept across `Reset`); [persistence.md](persistence.md) "Upgrading a store" has the markers. `New` fails with `ErrUntimedModeMismatch` when an explicit mode differs from the store's; `UntimedDefault` opens a store under its own mode. A store with rows and no key is `UntimedFromTxFrom`; a store without MetaKV stays `UntimedFromTxFrom` under `UntimedDefault`. Out-of-range values: `ErrInvalidUntimedValidStart`.
- `g.Admin().UntimedValidStart() (mode, complete, err)`: the persisted mode (never `UntimedDefault`); `complete=false` during an unfinished conversion. Ask it instead of assuming where an untimed entity starts.
- `g.Admin().SetUntimedValidStart(ctx, graph.UntimedUnbounded)` converts once, one way: rewrites every untimed first version to `UnboundedValidFrom` under the graph lock, then persists the mode. Interrupted, the store stays marked "converting": exports, imports and untimed creates fail with `ErrUntimedModeMismatch` until a reopen under `UntimedUnbounded` / `UntimedDefault` or a second call finishes it. Idempotent on an unbounded store; `UntimedFromTxFrom` is a no-op on a `TxFrom` store.
- Replication: a conversion emits a `ChangeMeta` record; upgrade replicas, readers and importers first. After the primary converts, a replica configured `UntimedFromTxFrom` fails its restart with `ErrUntimedModeMismatch` (switch it). A `UntimedFromTxFrom` primary emits no mode record: configure its replicas `UntimedFromTxFrom` explicitly. A full export carries the mode; `Import` into an empty store adopts it, into a store of the other mode fails; `ImportMerge` refuses a delta of the other mode.
- Constraints: under `ConstraintRelWithinEndpoints` a rel is bounded by the start of its endpoint's current life (`ErrRelBeforeStartNode` / `ErrRelBeforeEndNode`).

```go
g, _ := graph.New(graph.Config{BadgerDir: dir, UntimedValidStart: graph.UntimedUnbounded})
n, _ := g.Nodes().Add(ctx, []string{"Host"}, nil) // valid at every instant until its first change
err := g.Admin().SetUntimedValidStart(ctx, graph.UntimedUnbounded) // convert an existing TxFrom store, once
```

Under `UntimedFromTxFrom`: a read at wall-clock "now" right after a create can miss it (read at `NowTx()` or the write's `TxFrom`); an `Update` whose `tkg_valid_from` is at or before the current version's `TxFrom` is `ErrValidFromBeforePrevious`; detect an untimed create by "first segment `ValidFrom` == first version's `TxFrom`". Under `UntimedUnbounded` the first segment starts at `types.UnboundedValidFrom`.

### Closing a version

`g.Nodes().CloseVersion(ctx, id, t)` / `g.Rels().CloseVersion` end the current version's valid time at `t`: the open row moves to history and a new current version keeps the start, with `ValidTo = t`; counts as an update. Errors (nothing written): `ErrInvalidTimeRange` for `t == 0` or `t` at or before the start, `ErrAlreadyClosed`. An `Update` setting only `tkg_valid_to` closes the same way on every update door (`GraphTx` has no `CloseVersion`); a batch or ingest unit with a refused close writes nothing. A closed untimed version stores its start as `ValidFrom`.

### Excise (valid-time)

"The entity was not valid during `[a, b)`" without deleting it.

```go
err := g.Temporal().ExciseNodeValidity(ctx, id, a, b) // a < b, or b the open end
_, err = g.Temporal().NodeAt(id, a)                   // ErrNoVersionValidAt
_, err = g.Temporal().NodeAt(id, b)                   // the version resumes at b
```

`ExciseNodeValidity(ctx, id, a, b)` / `ExciseRelValidity`: reads at a valid instant in `[a, b)` answer `ErrNoVersionValidAt`, interval doors no longer see the entity there, reads outside and pins before the call are unchanged. Append-only: void pieces (`TemporalMetadata.Void`) plus a resumption at `b`; a later `SetNodeVersionInterval` over the hole fills it. Void rows never hold the current slot or answer a record door; `History()` returns them marked, with the voided version's labels (a relationship's type and endpoints) and no properties (v4.90.0 on; older void rows hold a copy of the voided version's, which no read uses). Stores with void rows are refused by releases before v4.54.0 ([persistence.md](persistence.md) "Format versions and markers"). Twins: `Excise*ValidityWithTx(..., txFrom)` (rules of `SetNodeVersionIntervalWithTx`), `GraphTx.Excise*Validity[WithTx]`, `BatchBuilder` doors. `b` at the valid axis's open end (0 on the legacy axis) excises the open tail `[a, open)`: no resumption is written (v4.76.0, store marker 10). Errors, nothing written: `a >= b` with a bounded `b`, or `a == 0` on the legacy axis, `ErrInvalidTimeRange` (negative `a` is a real start; on an `UntimedWholeAxis` store 0 is too); nothing valid in `[a, b)` `ErrNoVersionValidAt`; `ErrNodeNotFound` / `ErrRelNotFound`; `ErrEntityDeleted`.

### Events (`g.Events`)

- Sync bus: `events.NewEventBus()` (or a zero `events.EventBus`), `g.Events().SetSync(&bus)` / `GetSync()`; `SetSync(nil)` detaches; after close `ErrGraphClosed`. `bus.Subscribe(handler)` returns an idempotent unsubscribe. Handlers run synchronously after each successful store write, outside the bus lock.
- Async bus: `events.NewAsyncEventBus(AsyncEventBusConfig{Workers, QueueSize, Backpressure, OnDrop})`, `SetAsync` / `GetAsync`. Backpressure `BackpressureBlock` (default, never drops), `BackpressureDropOldest`, `BackpressureDropLatest`; `OnDrop(Event)` is called outside the bus locks for each shed event. One dispatcher drains in Critical → High → Normal → Low → Deferred order; ordering holds within one `Publish` / `PublishBatch` call. `bus.Close()` drains accepted events. `QueueDepth()` / `QueueDepths()`.
- Events: `EventNodeCreate` / `Update` / `Delete`, `EventRelCreate` / `Update` / `Delete` (deletes `PriorityCritical`, creates `PriorityHigh`, updates `PriorityNormal`). A cascading node delete publishes one `EventRelDelete` per rel before `EventNodeDelete`; retractions publish delete events.

### Hash chain verification (`g.Hash`)

- `g.Hash().VerifyNodeChain(id) (bool, error)` / `VerifyRelChain(id)`; a deleted entity's history is verified alone; a compaction stub is the virtual predecessor.
- `Config.DisableIntegrityHashes` (default false): no hashes are computed or stored, both Verify doors and `g.Tier().VerifyShard` return `ErrIntegrityDisabled`, `Config.RelSegments` with it fails `New`, reopening under the other setting is `ErrIntegrityModeMismatch`. Hashes are handed out as 64-char lowercase hex. Contract: [persistence.md](persistence.md) "Integrity hashes".

### Transactions (`g.Tx`)

Isolation: transactions are serialized against each other and batches but write-through, NOT isolated from standalone reads and writes; see [architecture.md](architecture.md) "Transaction isolation — what v4 actually guarantees".

- Functional: `g.Tx().Run(func(tx *graph.GraphTx) error)`, `RunContext(ctx, fn)`, `RunWithLSN(fn) (lsn uint64, error)` (the commit's change-log LSN; 0 without records). A panic in `fn` rolls back and re-panics; rollback errors are joined. Nil callback `ErrNilTxCallback`, nil context `ErrNilContext`.
- Imperative: `tx, err := g.Tx().Begin()`. `*GraphTx` (`graph.GraphTx`; full method set `go doc -all ./pkg/graph/internal/core`):
  - Mutations: `AddNode`, `AddNodes(labels, props []map[string]any)` (all-or-nothing, one store write), `AddRelationship`, `AddRelationshipByID`, `AddRelationshipByIDIfAbsent`, `AddRelationships(typeName, []graph.RelCreate{StartID, EndID, Props})` (all-or-nothing, except on tiered for cross-shard rels, which are undone by compensating deletes), `UpdateNode`, `UpdateRelationship`, property set/delete, `AddNodeLabel` / `RemoveNodeLabel`, `DeleteNode` (cascade), `DeleteRelationship`, `EndNodeValidity` / `EndRelValidity`, `ImportNodeWithID` / `ImportRelationshipWithID`, `GetOrCreateByKey`, `GetOrCreateByKeyOpts`, `SetNodeVersionInterval` / `SetRelVersionInterval`, `Excise*Validity`, `RetractNode` / `RetractRelationship`, and the caller-instant `*WithTx` doors.
  - Reads: `GetNode`, `GetRelationship`, `GetNodesByIDs` / `GetRelsByIDs`, `NodesByLabel`, `RelsByType`, `NodesByLabelAndProperty`, `AllNodes` / `AllRels`, adjacency, the temporal mirrors, `Snapshot`, `Export`, counts, `Stats()`, `SearchNearest` / `SearchNearestScored`, `VerifyShard`, name and shadow helpers.
  - Lifecycle: `Commit()` dispatches buffered events. `Rollback()` restores pre-transaction rows, history, labels and registries and discards events; it overwrites any standalone write that landed on a touched entity in between. Done handles: `ErrTxDone`.
  - `Config.DurableCommit` (default false): `Commit`, `Batch.Execute` and the strong ingest applier return only after the group is fsynced (`ErrCommitNotDurable`: committed in memory, pending the next flush). Not covered: standalone mutations, concurrent-mode ingest. Refused by `New` with `ErrCapabilityNotSupported` on a store without stable storage.
  - Inspection: `CreatedNodeIDs()`, `CreatedRelIDs()`, `CommittedLSN()`, `StartInstant()` (the instant `Begin` reserved: every write of the transaction is stamped after it, every earlier stamp before it).

### Indexes (`g.Index`)

Every create validates names and keys (`ErrEmptyName`, `ErrKeyTooLong`, `types.ErrReservedPrefix`) and covers future matching entities. `InventoryEpoch() uint64` advances after every index create or drop that reached the store and after `Reset`; read it before reading the inventory and cache while it is unchanged (per Graph, not persisted).

- Property: `CreateProperty(label, key)` / `DeleteProperty` (`ErrIndexNotFound`) / `HasProperty`; relationship mirrors `CreateRelProperty(type, key)` / `DeleteRelProperty` / `HasRelProperty`. Lookups work without an index (scan + filter). Badger keeps rel property values in RAM (definitions persisted, values rebuilt at open), except for the types in `RelPropertyIndexOnDiskTypes` (v4.92.0, kept on disk: [persistence.md](persistence.md)). Tiered builds each index on every shard (the reference shard anchors the definition); a shard whose copy is missing answers by a scan. `store.CapabilitiesOf(s).IndexAcceleration.PropertyIndex` / `.RelPropertyIndex` state support.
- Composite: `CreateComposite(label, keys)` / `DeleteComposite` (2–4 ordered keys); `HasComposite(label, keys)` matches the key SET (the routing rule of `ByLabelAndProperties`), `ListComposites(label)`. Wrapper stores without the capability: `ErrCapabilityNotSupported`.
- Temporal interval: `CreateTemporal(label)` / `DeleteTemporal` (`ErrTemporalIndexNotFound`) / `HasTemporal`, `CreateRelTemporal(type)` / `DeleteRelTemporal` / `HasRelTemporal`, `ListTemporal()` / `ListRelTemporal()`. Accelerates temporal `ByLabel` / `ByType` and prunes effective pages.
- High-frequency: `CreateHighFrequency(label, bucketSize)` (positive whole ms, else `ErrInvalidTemporalIndexConfig`) / `DeleteHighFrequency`. One temporal index kind per label.
- Vector: `CreateVector(label, key, dims, metric)` / `DeleteVector` (`ErrVectorIndexNotFound`); `dims > 0`, `metric` `DistanceCosine` or `DistanceEuclidean` (`ErrInvalidVectorIndexConfig`); an existing or later vector of another length is `ErrDimensionMismatch`. Default engine: approximate HNSW (M=16, EfConstruction=200, EfSearch=64); `CreateVectorWithOptions(..., store.VectorIndexOptions{UseBruteForce, M, EfConstruction, EfSearch})` picks exact search or tuning. `VectorIndexInfo(label, key) (store.VectorIndexInfo, bool, error)` states the configuration. Vector values: `[]float32`, `[]float64`, `[]any` of floats.
  - `SearchNearest(label, key, query []float32, k, opts)` returns the top-k nodes; temporal filters pre-filter or over-fetch; ranking uses each node's CURRENT vector. `SearchNearestScored(...) ([]index.VectorHit{Node, Distance}, error)` adds distances (1 − cosine, or L2). `QueryOpts.TxPin` is refused with `ErrVectorSearchTxPinUnsupported`.
- IndexProvider plugins: `RegisterProvider(p)` / `UnregisterProvider(name)` / `Providers()`; a sync bus is attached if none is; provider `OnEvent` errors are logged, never abort a committed write. Sentinels `ErrIndexProviderExists`, `ErrIndexProviderNotFound`, `ErrIndexProviderEmptyName`.
- Badger-only opt-in work diagnostics: `DiagnoseNodePropertyTxMembersDuring` and `DiagnoseRelPropertyTxMembersDuring` take the same token, property/value key, valid window, transaction pin and callback as their ordinary window membership twins, returning `(store.PropertyMemberWork, error)`. They run the same worker. `Supported` means the disk-membership counters are available; RAM windows still report actual `MembersEmitted`, `Completed` and `CallbackStopped`, but their zero disk counters are **unsupported**, not zero internal work. `IteratorSteps` includes skipped older MVCC versions and a longer-prefix/beyond-range boundary item. `OverlayOpsInspected` counts enumerated flushing/pending operations before range filtering, `OverlayOpsMatched` those applied to the overlay; `OverlaySetsEmitted` and `DiskEntriesEmitted` count entries forwarded to the fold. `OverlaySetsPeak`, `OverlayDeletesPeak` and `FoldMembersPeak` are map cardinalities; `MemberSliceLen/Cap` describe the materialized answer before an empty/reversed window clears it. The callback runs outside store locks; nested/concurrent calls have independent counters, and callback work is excluded. Errors preserve the ordinary error and partial counters with `Completed=false`; a callback stop returns normally (`Completed=true`, `CallbackStopped=true`). All counts are logical work, not physical reads, encoded/decompressed bytes, allocated heap or page pins. No tiered aggregation is supplied by these Badger methods. The diagnostic result is 96 bytes on linux/amd64, constant per call; the internal query carries one additional pointer. No store/entity/history fields or persistent bytes are added. Go 1.26.9 escape analysis keeps the result and inlined callback at the actual worker callsites off the heap; this is compiler evidence, not a measured total allocation or live-heap bound.
- RAM per definition (since v4.93.0): `PropertyIndexStats() ([]store.PropertyIndexStat, error)` gives one row per declared property index, single-key or composite, node or relationship. A row holds its distinct values (a composite's key tuples) and its postings, plus its membership sidecar's postings once a pinned read built it. `RAMBytes` estimates the bytes of both: map slots at average load, Go size classes, posting chunks at capacity, within ±20 % of the measured heap on the calibrated shapes; a sidecar's windowed and numeric views are not counted. `OnDisk` marks a definition kept in badger's `0x0C` keyspace, which holds none of it in RAM. Rows carry label and type names. Tiered gives one row per open shard (`Shard`: `reference`, `archive` or the event shard's name), sharded one per slot (`Shard`: its number; a value on two slots counts on each). `store.PropertyIndexStatsByScope(stats)` sums them per label or relationship type. A diagnostic: it walks every value under the index read lock. `ErrCapabilityNotSupported` without `store.PropertyIndexStatsCapability`. Memory, badger, sharded, tiered.
- Valid-end pruning counts (since v4.94.0): `PropertyIndexValidEndStats() (store.PropertyIndexValidEndStats, error)` gives, since the store opened, the entries a `ValidEndAfter` lookup left out (`Pruned`), the entries it read without a bound (`UnknownRead`), the bounds reads wrote (`Refined`) and the refines skipped because the node was written after the lookup or the store was cleared (`RefineSkipped`). Badger and tiered (its reference shard); other stores `ErrCapabilityNotSupported`.
- Valid-end pruning check (since v4.95.0): `PropertyIndexValidEndListed(label, key) (bool, error)` is true when a `ValidEndAfter` lookup on (label, key) prunes from the index entries without reading rows: the definition is listed in `PropertyIndexValidEnd`, on disk and its bounds trusted (its valid-end marker set); on tiered, a reference label's definition. False, without an error, everywhere else (no listing, no index, an index in RAM, an event label on tiered, a store without pruning, a read-only open over an unmarked definition); errors only for a closed graph and an invalid label or a reserved key. A look at memory under the index read lock, no I/O. A create of the index can turn it true, a drop, `Clear` or `Reset` false; a lookup on a definition no longer trusted reads every match (slower, never an error).

#### Property index options

`CreatePropertyWithOptions(label, key, graph.PropertyIndexOptions{RangeCounts, Elements})` / `CreateRelPropertyWithOptions`, read back by `PropertyOptions` / `RelPropertyOptions`. Zero options = `CreateProperty`. Fixed at creation; persisted with the definition on badger and sharded (memory keeps it per process); not replicated (index DDL never is).
- `RangeCounts`: `RangeCardinality` becomes two prefix sums (cost: ~42 ns per indexed write, 8 B per distinct value). Refused with `ErrCapabilityNotSupported` on tiered, badger `PropertyIndexOnDisk` (or the label in `PropertyIndexOnDiskLabels`, the relationship type in `RelPropertyIndexOnDiskTypes`), wrapper stores.

#### Elements index

`Elements: true` indexes a list-valued property for membership: `ByLabelAndProperty(label, key, x, opts)` means "the list contains x" (each scalar element keyed, duplicates once, non-scalars ignored, a non-list value is a one-element list, a list query value matches nothing), on current and temporal reads. Range, prefix and count doors decline on it. Refused with `ErrElementsIndexUnsupported`: with `RangeCounts`, under a unique constraint, for `CreateUnique` / `GetOrCreateByKey`, in `ByLabelAndProperties` / `CreateComposite`; with `ErrCapabilityNotSupported` for a relationship type in badger `RelPropertyIndexOnDiskTypes`. On badger `PropertyIndexOnDisk` (or the label in `PropertyIndexOnDiskLabels`, tiered's too) a node Elements index keeps one disk entry per distinct element, current and member, and no RAM per element; it answers as the RAM index at every read (ELEMDISK, v4.99.0). A badger store that persisted one is refused by older releases (persistence.md "Format versions and markers"). Memory, badger, sharded, tiered.

```go
g.Index().CreatePropertyWithOptions("Host", "tags", graph.PropertyIndexOptions{Elements: true})
hosts, _ := g.Nodes().ByLabelAndProperty("Host", "tags", "prod", graph.QueryOpts{})
```

### Constraints (`g.Constraints`)

- Temporal: `Add(c)`, `Set(cs)`, `Get() temporal.ConstraintSet` (a value: `temporal.NewConstraintSet(cs...)`, `Add` returns a new set, `Items`, `Len`, `ForEach`, `Validate`). `TemporalConstraint{Kind: ConstraintRelWithinEndpoints}`: a rel's validity must lie within both endpoints' (checked at create and import). Errors wrap `ErrTemporalConstraint` (`ErrRelBeforeStartNode`, `ErrRelAfterEndNode`, …); unknown kinds `ErrInvalidTemporalConstraint`.
- `DryRunValidate(ctx, constraints.DryRunFacts{Nodes, Rels}) ([]constraints.DryRunViolation, error)` checks a proposed fact set against the unique and temporal constraints without writing.
- Unique: `CreateUnique(ctx, label, key)` (`UniqueCurrent`: no two CURRENT nodes share a value; a freed value is reusable), `CreateUniqueForever(ctx, label, key)` (the first holder owns the value forever, across delete and reopen; `ReleaseOwnership(ctx, label, key, value)` frees it), `DropUnique`, `UniqueConstraints()`. Creation auto-creates the property index and checks existing data (`ErrUniqueViolationExisting`); float keys/values `ErrUniqueUnsupportedType`; duplicate `ErrUniqueConstraintExists`; absent `ErrUniqueConstraintNotFound`. Values compare under property equality (integers of every width are one value). Persisted in MetaKV (`ErrCapabilityNotSupported` without it), refused on a read-only replica. On tiered, a reference label's key is checked on the reference shard; since v4.81.0 an event label's `CreateUnique` is kept by the tiered owner index (a badger under `DataDir/index` on the hot volume: value -> the node that claimed it, about 18 B a key), so its unique check, `GetOrCreateByKey` and `ByLabelAndProperty` (current, `DepthAll`) read one key and the owner's row instead of every shard; no per-shard property index is made for it. `CreateUniqueForever` on an event label stays refused (`ErrUniqueEventLabelUnsupported`).
  - Enforced on every node write door (standalone, `GraphTx`, batch, ingest, `SetNodeVersionInterval` — open-ended calls checked for both scopes, bounded ones against `UniqueForever` only) with `ErrUniqueViolation`. `IO().Import` validates too unless `ImportOptions.SkipUniqueValidation`; replica apply does not enforce. A failed call withdraws its own claims; a `UniqueForever` claim made in a rolled-back transaction stays (use `ReleaseOwnership`).
- `g.Nodes().GetOrCreateByKey(ctx, label, key, value, extraProps) (*types.Node, created bool, error)` returns the current holder of `value` or creates it under one value lock (one create among concurrent `GetOrCreateByKey` callers; against a plain `Add` / `Update` of the same value only under an active unique constraint on the key); `value` must be a non-float indexable scalar (`ErrUniqueUnsupportedType`); `extraProps` seed a create. `GetOrCreateByKeyOpts(..., opts)` bounds the lookup by `opts.Depth` (any other `QueryOpts` field `ErrConflictingTemporalOpts`).

### IO (`g.IO`)

Wire format and backup naming: [persistence.md](persistence.md).

- `Export(w)` — length-prefixed msgpack stream; holds the graph write lock while streaming (`tx.Export(w)` inside a transaction). Nil writer `ErrNilWriter`.
- `Import(r, io.ImportOptions{StagingDir, MaxStagedBytes, SkipUniqueValidation, ApplyNodeRetention})` stages the stream to disk, validates it, then replays; a replay error rolls touched rows and registries back. Sentinels: `ErrNilReader`, `ErrIncompatibleExport`, `ErrIncompatibleRegistry`, `ErrImportSizeLimit`, `ErrCorruptExport`.
- Delta backups (need a change-log: `Config.ChangeLog` on badger, `tiered/sharded.Config.ChangeLog`, or `memory.WithChangeLog()`; else a wrapped `store.ErrCapabilityNotSupported`). The cursor is the change-log LSN.
  - `Watermark() (io.Cursor{LSN, Epoch}, error)` (`IsZero()`: the zero cursor); a cursor from another graph is `ErrCursorUnknown`.
  - `ExportSince(w, since)` writes every committed change after `since` (`ErrCursorUnknown`: fall back to `Export`).
  - `ImportMerge(r, io.MergeOptions{StagingDir, MaxStagedBytes, ExpectBase, Strict})` reproduces the source rows verbatim, verifies hashes, is idempotent, rolls back on failure; `ExpectBase` / `Strict` violations `ErrDeltaBaseMismatch`; a full stream `ErrIncompatibleExport`.
  - `io.HeaderOf(r) (io.DeltaHeader{Version, IsDelta, From, To, ExportedAt, NodeCount, RelCount}, error)`; a full export's `To` is the base cursor of the first delta. Restore: `Import` the base, then `ImportMerge` each delta with `ExpectBase` = the previous `To`.
- One-call backups: `BackupTo(dir) (io.Cursor, error)` writes `dir/backup-<LSN>-full.tkg`, `BackupDeltaTo(dir, since)` writes `backup-<since>-to-<to>-delta.tkg` (an empty delta writes nothing and returns `since`); an existing target is `ErrBackupExists`. `graph.RestoreInto(cfg, dir) (*Graph, error)` validates the whole chain from the headers, then replays it; a foreign lineage `ErrCursorUnknown`, a gap `ErrDeltaBaseMismatch`, each naming the file.

### Admin & Tier (`g.Admin`, `g.Tier`)

- `g.Admin().Reset()` clears entities, indexes, history, counters, as-of tags, unique constraints and watermarks; keeps registries. Gated by `Config.AllowReset` (`ErrResetDisabled`).
- `ResolveExactErasure(ctx, admin.ExactErasureRequest{NodeIDs, RelationshipIDs, Bounds}) (admin.ExactErasureResolution, error)` and `ExactErase(ctx, request) (admin.ExactErasureReceipt, error)` — legal erasure, gated by `Config.AllowExactErasure`, memory and badger. Resolve expands the request with every rel that references a declared node (also `EndpointNodeIDs`, `RelationshipBindings`) within explicit bounds; the caller applies its ownership policy and persists `resolution.Request`. Erase recomputes the closure and fails before mutating on an escape (`ErrExactErasureRelationshipEscape`) or exhausted bound (`ErrExactErasureClosureLimit`); it hard-removes rows, histories, index residue, ownership values and stubs, without tombstones or change records, and refuses while change-log records exist (`ErrExactErasureChangeLogRetained`). The receipt hash is stable across retries. Exports, backups, replicas and media sanitization stay the deployment's job.
- `IsReferenceLabel(label) (bool, error)`: whether a `Depth`-bounded read still sees every node of the label (tiered: the `RefLabels`; true on every other backend).
- `IsReferenceType(relType) (bool, error)`: whether the relationship type is reference-class (tiered: the `RefTypes`; true on every other backend).
- `DecomposeNodeID(id)` / `DecomposeRelID(id)` → `IDComponents{CreatedAt, NodeID, Sequence}`.
- `ValidAxis()`, `UntimedValidStart()`, `SetUntimedValidStart(ctx, mode)`: see "Valid-time start". `SealRelSegments`, `RelSegmentStats`: see Columnar reads.
- Stored sizes (a measurement surface): `NodeStoredSizes(id) ([]admin.StoredRow, error)` lists a node's stored rows, the current row first (`Current`, if any), then every history row `History` reads ascending by version, pending writes included: `StoredRow{Version, Current, Bytes, Delta, Void}` with `Bytes` the stored value's length after delta encoding and before the engine's block compression, `Delta` a history row stored against its anchor, `Void` an excise piece. `ForEachNodeStoredSize(ctx, label, depth, fn(id, rows) bool)` does it for every current member of a label, ascending by ID, 256 per hold of the read lock, `fn` without locks. Badger, tiered (every shard the rows live on) and sharded; memory: `ErrCapabilityNotSupported`.

**History compaction** — `CompactHistoryNodes(ctx, RetentionPolicy{KeepVersions, KeepSince}) (CompactReport{EntitiesCompacted, VersionsTrimmed, Watermark}, error)` / `CompactHistoryRels`: trims each entity's oldest history rows that fail BOTH bounds (the current row and newest history row are always kept) and records a self-hashed stub that `Verify*Chain` treats as the predecessor. Reads pinned before compacted knowledge fail with `ErrHistoryCompacted` (point doors per entity, scans against the graph watermark). Refusals: `ErrInvalidRetentionPolicy`, `ErrCompactionProtectedTag` (remove the as-of tag first), `ErrCompactionChangeLogEnabled`; refused on a read-only replica; memory, badger, tiered (sharded `ErrCapabilityNotSupported`).

**Retention purge** (gated by `Config.AllowRetentionPurge`, `ErrRetentionPurgeDisabled`; refused on a read-only replica; memory, badger, tiered, sharded; idempotent and resumable, chunked, waits for an open `GraphTx` per chunk — do not call it while holding one in the same goroutine):
- `PurgeExpiredNodes(ctx, PurgePolicy{Label, Mode, Before}) (PurgeReport{NodesPurged, RelsPurged, Watermark}, error)` hard-removes the label's nodes with their rels and history, no tombstones. `PurgeByAge` (default): snowflake mint time before `Before`; `PurgeByValidTo`: current version ended before `Before`. Bad policy `ErrInvalidPurgePolicy`; with the change-log on it needs a store that emits the purge record (`ErrRetentionPurgeChangeLogEnabled`). Advances the label's retention watermark.
- `PurgeExpiredRels(ctx, RelPurgePolicy{Type, Mode, Before}) (RelPurgeReport{RelsPurged, Watermark}, error)` hard-removes a type's rels minted before `Before`, live and ended, with all history; nodes untouched. `PurgeByAge` only. Advances only that type's watermark. Upgrade replicas first (an older binary stops at the purge record) and do not downgrade afterwards.
- A read pinned below a watermark it covers fails closed with `ErrRetentionExpired` (node watermarks for node reads; a type's watermark for that type's reads; the max over types for all-type rel reads); reads of other types and labels answer. `Reset` clears the watermarks; exports carry them; `Import` applies rel watermarks, node ones only with `ImportOptions.ApplyNodeRetention`.

**Tiered store** (`g.Tier()` methods return `ErrNotTieredStore` on other backends; configuration and semantics in [persistence.md](persistence.md) "Tiered Persistence"):
- `Archive(id)` / `Restore(id)` move a reference node between the reference shard and the archive with its rels.
- `ForceRotate()` rotates the hot shard transactionally. `ListShards()` returns `[]ShardInfo`, each with its volume, directory and bytes on disk (`DiskBytes`: the blocks its files hold, as `du` counts them, so an open shard's sparse 2 GB value log counts only what it holds; -1 when the directory cannot be read; none in memory). An event shard's `ColdOpens` counts how often an access opened it while it was closed and cold since `New`: diffed around a read, it is the cold shards that read opened (each one a badger open on the cold volume; a shard retained open by `MaxOpenColdShards` counts once). `ShardAccessStats()` counts the store's shard checkouts since `New` by the shard's tier at each (`Reference`, `Archive`, `Hot`, `Warm`, `Cold`) plus `ColdOpens` summed over every shard (a retention drop's shard included): every read and write pins the shards it touches, and a read by ID that misses the shard of its ID's time pins every other event shard, cold ones included. Diff two snapshots around a piece of work for an upper bound of the tiers it touched (other callers' accesses count too; zero `Cold` and `ColdOpens` prove it read no cold shard). It also records, for R3, the open badger handles now by the shard's tier at the snapshot (`ReferenceHandles`, `ArchiveHandles`, `HotHandles`, `WarmHandles`, `ColdHandles`, each a `tiered.TierHandles` of `Writable` and `ReadOnly`; a demoted shard still open counts under cold) and the writable checkouts since `New` by tier (`HotWrites`, `WarmWrites`, `ColdWrites`: every write, late write, owner update or backfill, and every caller that may write, which a read-only handle on that tier would have to upgrade for). Atomic counters per shard beside its pin count, no lock but the shard list's, nothing opened or walked: no measurable cost on parallel hot reads; `ErrNotTieredStore` on another store. `EntityCacheStats()` (since v4.97.0) returns a `tiered.ShardCacheStats` row per open shard (the reference shard, the archive when open, each open event shard in no set order; a closed shard has no cache and no row): `Nodes` and `Rels`, each a `store.EntityCacheUsage` of the decoded-entity cache's entries and estimated heap bytes (`ApproxHeapBytes` plus 160 B per entry), clean (evictable) and dirty (written or deleted, not yet flushed, never evicted) apart. Every open shard has its own pair of caches, so the rows sum to the store's decoded-entity heap; `Config.CacheBudgetBytes` bounds each cache's clean part, which is what the rows let a caller size. It walks every cache (O(cached entries): 10,000 per cache at the default capacity), counts no shard access and opens nothing; `ErrNotTieredStore` on another store. `MoveShard(ctx, name, volume)` moves an event shard to the hot, warm or cold volume (`tiered.Store.MoveShard`; refused for the hot shard, an unmapped volume and a non-tiered graph). The reference shard and the archive move only while the store is closed: `tiered.MoveShardOffline(ctx, cfg, name, volume)` (`name` is `reference` or `archive`; the reference shard never to cold; refused while a process has the store open, unix only). `RebuildCatalog()`, `Repair()` (fixes cross-shard split writes), `VerifyShard(name)` (`tx.VerifyShard` inside a transaction).
- `tiered.Config.ShardWindowLocation *time.Location` (v4.82.0, WINDOWZONE): the zone whose calendar days a daily or weekly `ShardWindow` follows; nil keeps the process's zone (`time.Local`), `time.UTC` gives UTC days whatever `TZ` says. `(*tiered.Store).OpenStats() OpenStats` (v4.82.0, RESTART): what `New` spent opening the store (`Duration`; the `Reference`, `Hot` and `Warm` phases; `WarmShards` opened, `ColdShards` left closed, `Demoted`/`Promoted` at open; `WALTruncations` at open and every cold open since); `New` logs the same at Info.
- `tiered.Config.RelsByMint` places a rel between two reference nodes on the event shard of its mint instant (cold mint shard: reference shard, counted by `RelsByMintFallbacks()`), except a type listed in `tiered.Config.RefTypes`, which stays on the reference shard whatever its mint, so its create, its versions and its reads by ID open no event shard; adjacency reads of reference nodes then honour `QueryOpts.Depth` via `ForEachAdjacentRelAt` / `ForEachAdjacentEndpointAt`. `tiered.Config.AdjacencyIndexOnDisk` drops per-node adjacency maps for a pending-write scan per hot-shard read. `tiered.Config.SyncWrites` syncs every writable shard.

### Migration

- `tiered.MigrateFromBadger(src *badger.Store, dst *tiered.Store) error` copies every current node and relationship and both registries into an empty tiered store, routing by ontology; no history, index definitions or MetaKV are copied (hash chains would need re-creation). A failure rolls the destination back. Nil or non-empty stores, missing source registries: `ErrInvalidStoreMutation`; closed: `ErrStoreClosed`.
- `ontology.OntologyMapping`: a nil receiver behaves as an empty mapping (`ClassEvent` for every label).

### Sharded store (experimental, `pkg/graph/store/sharded`)

`sharded.New(sharded.Config{Dir, InMemory, BaseSlot, SlotCount (1..32, BaseSlot+SlotCount ≤ 32), ChangeLog, …badger passthroughs})`: N badger shards, one per snowflake slot, routing by the slot in each ID. Design: [architecture.md](architecture.md) "sharded.Store".
- **Claim every slot the graph mints on.** With `IngestLanes == 0` nodes mint on slot `SnowflakeNodeID*2`, rels on `*2+1` (claim both); with `IngestLanes > 0` also every lane slot (`SnowflakeNodeID=0`, `IngestLanes=4` → `BaseSlot: 0, SlotCount: 6`). An unclaimed slot fails closed with `store.ErrSlotNotLocal`.
- Opens fail closed: `ErrCatalogConflict`, `ErrCatalogCorrupt`. A mid-sequence batch failure is a typed `*sharded.PartialBatchError{Op, CommittedShards, FailedShard, Err}`; `VerifyConsistency() (Report, error)` finds dangling references without repairing.
- Declined (`ErrCapabilityNotSupported`): transaction-time query, history rollback trim, label/type tx membership, depth-iteration accelerators, history compaction.

### Validation limits

`Config.Validation` = `ValidationLimits{MaxLabelsPerNode, MaxPropertiesPerEntity, MaxPropertyKeyLength, MaxPropertyValueSize, MaxPropertyContainerLength, MaxNameLength, AllowSelfLoops}`; defaults 50 / 1000 / 256 / 65536 / 100000 / 256 / false; zero values take defaults. `MaxPropertyValueSize` bounds every string inside a value; `MaxPropertyContainerLength` bounds the element count of slice and map values (and `[]byte` length), not a `[]string`'s count. `MaxNameLength` also applies to imported and persisted registries. `AllowSelfLoops=false` makes rel creates refuse self-loops (`ErrSelfLoop`).

### Badger value threshold

`ValueThreshold` (VALUETHRESH) on `graph.Config` (with `BadgerDir`), `badger.Config`, `tiered.Config` and `sharded.Config` sends every badger value of at least that many bytes (a row, a history row, a change-log record) to the value log instead of the LSM. 0 keeps badger's 1 MB; otherwise [1 KB, 1 MB] and at most 15 % of `MemTableSize`, refused by name at `New`. For rows of about 100 KB rewritten whole (`ReplaceVersion`), 64 KB cut CPU about 90 % with reads as fast or faster, at the price of uncompressed value-log space that the value-log GC rarely frees ([badger.md](badger.md) section 7, rule 9). In memory every value stays in the LSM and the largest value becomes `ValueThreshold` - 1 (`ErrEntryTooLarge`).

### Badger compression

`NoCompression` (NOCOMPRESS) on `graph.Config` (with `BadgerDir` or `BadgerInMemory`), `badger.Config`, `tiered.Config` and `sharded.Config` writes SSTable blocks uncompressed. `Compression` cannot select that: `options.None` is its zero value and keeps badger's Snappy. Uncompressed blocks are read straight from the table's mmap, so block reads and compactions no longer decode every block into a fresh heap buffer; the cost is disk, up to about 2.6x for compressible rows. Existing tables keep their codec until compaction rewrites them, so the setting can change between opens. `NoCompression` with a non-zero `Compression` is refused by name at `New` ([badger.md](badger.md) section 6).

### Other Config fields

- `graph.Config.CacheCapacity`: the per-cache (nodes, rels) soft limit of a badger store built from `BadgerDir` / `BadgerInMemory`; 0 = 10,000. Size it to the scan working set: a label scan over more nodes than the cache holds decodes every miss. `badger.Config.CacheCapacity` is the same on a store built directly.
- `graph.Config.ReplicationSource`: a replica's handle to its primary's token registry (in-process, the primary's `g.Replication()`); with it the apply path extends the registry on a token the primary allocated later instead of failing closed. Also `g.SetReplicationSource`.
- `badger.Config.GCInterval` (value-log GC period, default 5 min, 0 off, ignored in memory) and `GCDiscardRatio` (default 0.5).
- `tiered.Config.WarmMemTableSize` (WARMMEM): the `MemTableSize` of a shard opened writable in a non-hot role: a warm shard at `New`, a window shard made on demand (`MintAtValidFrom`), a cold shard a late write opens, a shard reopened after `MoveShard` or `Clear`. The hot, reference and archive shards and the owner index keep `MemTableSize`. A writable open allocates an arena of about 1.3 x its memtable on the Go heap (83 MB at 64 MB, 10 MB at 8 MB) whatever the shard's role, so an 8 MB `WarmMemTableSize` under a 64 MB `MemTableSize` cut a restart over two warm shards from 346 to 200 MB of live heap, a window shard made on demand from 86 to 13 MB of allocation and a late write into a cold shard from 90 to 17 MB (`tasks/evidence/R3/measure.txt`); it also leaves room to raise `MemTableSize` for the hot shard alone. Valid [8 MB, 1 GB] and at most `MemTableSize` (64 MB when that is 0), refused by name at `New`; 0 keeps `MemTableSize` everywhere. A rotation's hot shard that turns warm is reopened at `WarmMemTableSize` by the handle sweep, off the write path (a swap of 47-61 ms at 5,000 rows a shard, 150-193 ms at 50,000, during which only that shard's readers and writers wait), and a demoted shard still on the handle it had while hot or warm has it closed, whatever its size (a read reopens it read-only, a late write writable at the warm size; a handle a cold read or late write opened is left to `IdleTimeout`); without `WarmMemTableSize` only the close applies. Day 6 of the R3 measure test at 64 MB and 8 MB: 245 MB of live heap against 610. A window shard made on demand that a rotation later makes hot keeps the smaller memtable. Bulk writes into a non-hot shard flush in pieces of that size, and one transaction holds at most 15 % of it ([badger.md](badger.md) section 2).
- `tiered.Config.PromoteColdShardsAtOpen`: at open, promote every cold shard back to the warm volume and persist that, the way back from `ColdAfter`; set it for one start, then unset it.
- Wiring fields that tiered and sharded set on their badger shards, not meant for callers: `badger.Config.DropRelTemporalIndexesAtOpen`, `HistoryPresenceProbeOnly`, `ForeignNodeOrdinal`, `OnCommitFloor`, `OnPropertyKeyGrow`, `SharedFlushHold`, `SharedMutationEpochs`, `SharedOrdinals`, `ValueDictionaryPlan`.

### Lifecycle

- `g.Close() error` saves registries and closes the store; idempotent.
- After `Close`, error-returning sub-API methods return `ErrGraphClosed`; no-error mutators no-op.

## Stability and deprecation

**Promise.** Within v4 the following are stable — no breaking changes, only additive evolution; breaking changes wait for v5.0.0:
- The sub-APIs and their methods (`Nodes`, `Rels`, `Temporal`, `Index`, `Events`, `Constraints`, `IO`, `Admin`, `Stats`, `Hash`, `Resolve`, `Ingest`, `Tx`, `Batch`) and the change-feed reads on `g.Replication()` (`ChangeFeed`, `ForEachChange`, `LastCommittedLSN`).
- The core types in `pkg/types`, the store contract types in `pkg/graph/store` (`Store`, `QueryOpts`, `ShardDepth`, `DistanceMetric`, sentinels), the error sentinels' identities and meaning, the type aliases on `pkg/graph`, and column segments (`Config.RelSegments` / `SegmentDir` / `SegmentMemoryBudget`, `ScanRelSegments`, `SealRelSegments`, `RelSegmentStats`).
- The sub-packages' `Ops` interfaces are wiring seams, not for external implementation: they gain methods in minor releases.

**Experimental** (may change or disappear in any release; tell the maintainers before depending on one):
- The replication apply API (`ApplyChange`, `ApplyChanges`, `AppliedLSN`, `SetAppliedLSN`, `RegistrySnapshot`, `IDSlotLease`, `SetIDSlotLease`, `Watch`, `g.SetReplicationSource`).
- `g.Tier()` and `sharded.Store`.
- The column readers: DocValues reader types (`types.NodeColumnReader` and siblings), typed column scans (`store.NodeColumnScanCapability`, `ColumnBatch`, `ColumnKind`, `ScanColumnsFromNodes`, `NodeColumnSource`, `ColumnScanBatchRows`, `ErrMixedNumericColumn` — the refusal is the part least likely to change), relationship column snapshots and `ScanRelColumns` / `RelColumnBatch`, typed chunks.
- Diagnostics: `ColumnExtendCount` / `ColumnRebuildCount` / `ColumnPatchCount`, `HistoryPresenceStats()` / `HistoryStampsStats()`, `store.PropertyTxMembershipStatsCapability`, `PropertyIndexStats` (the row's fields and the estimate's terms); the `*ForTest` exports on the memory, badger, tiered and sharded stores (test seams, no promise).
- `QueryOpts.IncludeEclipsed` (reserved no-op; may be removed in v5).

**Deprecated** (each godoc says "removed in v5.0.0"):
- `graph.ErrEventPropertyIndex` and `tiered.ErrEventPropertyIndex`: nothing returns them since v4.58.0, no replacement; drop the `errors.Is` match.
- `(*tiered.Store).SaveLabelRegistry` / `SaveRelTypeRegistry`: use `SaveRegistries`.

**Deprecation ritual.** A method or field whose behaviour or meaning will change gets a `// Deprecated:` godoc marker and a CHANGELOG `Deprecated` entry at least one minor release before the change, stating what and why, the replacement, and the release that changes or removes it:

```go
// Deprecated: SomeMethod is superseded by BetterMethod as of v4.11.0.
// This method will be removed in v5.0.0. Use BetterMethod instead.
func (g *Graph) SomeMethod() { ... }
```

- A changed **default** of a Config field that stays is announced by a CHANGELOG `Deprecated` entry and a godoc note one release before (no marker) and applies to new stores only; existing stores keep the setting they were created under.
- An **on-disk format change** raises the store marker in the release that first writes it; that release also reads it, every older release refuses the store at `New` with nothing written, and a rollback past it needs a copy made before the upgrade. Which release reads which marker: [persistence.md](persistence.md) "Upgrading a store".
- A bug fix that makes a door return what its documented contract already promises is not a behaviour change: it ships in a patch under CHANGELOG "Fixed". Past exceptions to the ritual are recorded in [CHANGELOG.md](CHANGELOG.md) (v4.46.0, v4.48.0, v4.51.2); there are no new ones.

Version numbering (fix = patch; new door, option or store marker = minor; a removed or changed public name, or a new module path `/vN`, = major; `make kind` decides) and the release checklist: [CONTRIBUTING.md](CONTRIBUTING.md) § Rules digest and § Release checklist.
