# API Documentation

## Core Types (`pkg/types`)

| Type | Purpose |
|------|---------|
| `Node` | Graph vertex with opaque `nodeID` (wraps `snowflake.ID`), primary + extra labels (`labelToken`), properties, version, temporal, integrity. `TxStamps() (txFrom, txTo, deletedAt Instant)` returns the transaction stamps without the copy `Temporal()` makes on a frozen row (0 allocs; zeros without temporal metadata) |
| `Relationship` | Directed edge with opaque `relID` (wraps `snowflake.ID`), type token (`relTypeToken`), start/end `nodeID`, properties, version, temporal, integrity; `TxStamps()` as on `Node` |
| `PropertySlice` | Sorted key-value store with binary search; recursive validation rejects `tkg_` prefix keys and values outside the exact hash/copy/wire allowlist at any nesting depth; depth-limited to 32 levels. `NewPropertySlice`, `PropertySlice.Set`, `Node.SetProperty`, and `Relationship.SetProperty` deep-copy accepted reference values and reject invalid post-copy custom values; `SetProperties` canonicalizes direct slices before installing them |
| `Instant` | Semantic wrapper for Unix-millisecond timestamps used by all temporal fields. Helpers: `InstantFromTime(time.Time) Instant` converts a `time.Time` (any zone, truncated to ms); `(Instant).Time() time.Time` converts back to UTC; `(Instant).String() string` renders the decimal millisecond value (e.g. `"1609459200000"`). `CoerceInstant(v any) (Instant, bool)` safely coerces `Instant`, `int64`, `int`, `float64` (integral only), `time.Time`, `*time.Time` to `Instant`; all others return `(0, false)` |
| `TemporalMetadata` | Temporal lifecycle metadata: `ValidFrom`, `ValidTo`, `TxFrom`, `TxTo`, `CreatedAt`, `UpdatedAt`, `DeletedAt` (all `Instant`), `CreatedBy`, `UpdatedBy` (`string`), `BaseEntityID` (`snowflake.ID`) |
| `NodeIntegrity` / `RelIntegrity` | Hash-chain integrity: `Hash`, `PrevHash` (`string`); `AuthorID` (`string`), `Signature` (`[]byte`) for caller-supplied provenance. `RelIntegrity` also carries `FromNodeHash` / `ToNodeHash` — hashes of the endpoint nodes at write time (not fed into `ComputeRelHash`) |
| `TimeGranularity` | 8-level granularity enum: `GranMillisecond`, `GranSecond`, `GranMinute`, `GranHour`, `GranDay`, `GranWeek`, `GranMonth`, `GranYear`. Functions: `TruncateInstant(t, gran)`, `RoundInstant(t, gran)`, `CeilInstant(t, gran)` |
| `AllenRelation` | Full 13-relation Allen's interval algebra: `Relate(aStart, aEnd, bStart, bEnd) (AllenRelation, error)`, `ComposeSets(rs1, rs2 AllenRelationSet) AllenRelationSet`. Constants: `Before`, `After`, `Meets`, `MetBy`, `Overlaps`, `OverlappedBy`, `Starts`, `StartedBy`, `During`, `Contains`, `Finishes`, `FinishedBy`, `Equals`. `AllenRelationSet` helpers mask out invalid relation bits |
| `RecurrencePattern` | Recurring time pattern: `Frequency` (`Daily`/`Weekly`/`Monthly`/`Yearly`), `Days` (`WeekdayMask`, bits Monday through Sunday only), `DayOfMonth` (1–28; 0 = last), `Month` (Yearly only; 0 defaults to January), `DayStart`/`DayEnd` (whole-millisecond durations from UTC midnight). `Validate()` rejects impossible calendar selectors and fractional-millisecond offsets; `Expand(from, to Instant) []Interval` emits concrete intervals within the window. Returns `types.ErrInvalidTimeRange` if `from >= to`, and `types.ErrRecurrenceSpanTooLarge` if `to - from` exceeds the maximum expansion span |
| `HashableValue` | Interface (`HashBytes() []byte`) that custom property struct types implement to participate in node/relationship integrity hashing. Register the type via `RegisterPropertyStructType(v any)` with a zero value or typed pointer; untyped nil returns `ErrUnsupportedValueType` because it carries no type to register. Registered custom values persist/export as a registered type name plus MsgPack payload, value-vs-pointer shape is preserved across `DeepCopyValue`, and the wire path rejects MsgPack round-trips that change `HashBytes`. Treat `HashBytes` like a wire format — once any property of the type has been written, you cannot change the encoding without breaking every existing hash chain that contains the value. List registered types via `RegisteredPropertyStructTypes() []string`. |
| `NodeID` / `RelID` / `EntityID` | Typed wrappers around `snowflake.ID` (`type NodeID snowflake.ID`, etc.). Boundary accessor: `(NodeID).SnowflakeID() snowflake.ID`. `(NodeID).MintInstant() Instant` / `(RelID).MintInstant()` return the ID's mint instant (the last fallback of a row's valid-from; see "Valid-time start (Config.UntimedValidStart)"). `EntityID` is the type-agnostic wrapper used by `Event.EntityID`, `BatchError.ID`, `QueryOpts.After`, and `TemporalMetadata.BaseEntityID`. Zero-value semantics: literal `0` is the universal sentinel for "unset" across the API. |

The table is a summary; the complete `pkg/types` surface is `go doc -all ./pkg/types`.

Nil `*Node` and `*Relationship` accessors return zero values, no-error mutators no-op, and error-returning mutators return `ErrNilNode` / `ErrNilRelationship`. Nil `*PropertySlice` pointer mutators return `ErrNilPropertySlice`; nil `*TemporalMetadata` helpers and nil integrity `DeepCopy` calls return zero/nil.

Two equalities, each with one owner. **Property equality** (`types.EqualIndexValues` / `EqualIndexKeys`, `types.PropertyEqual`, since v4.57.1) is the rule of every equality door: `ByLabelAndProperty` / `ByTypeAndProperty` (current and temporal), the named `*At` / `*During` doors, `ByLabelAndProperties`, the paged effective doors' `Filter`, `CountByLabelPropertyValue` / `CountByTypePropertyValue`, the expected value of `CompareAndSetProperty`, the unique constraints and `GetOrCreateByKey`, and the exact range count `RangeCardinalityAt`. A number equals every stored number of the same exact value in any width (3 = `int8(3)` = `uint(3)` = 3.0 = `float32(3)`; a `float32` as its `float64` widening, so `float32(0.1)` is not 0.1; -0.0 = 0; no rounding past 2^53: `int64(2^53+1)` is not `float64(2^53)`); NaN and nil equal nothing; a string, boolean or temporal value equals itself only; kinds never cross. Stored values keep their width: index keys, wire and hash tags are unchanged, and a door unites the (at most 12) keys an equal value can be stored under in one read (round 11: one index walk through the optional `store.PropertyKeysLookupCapability` / `RelPropertyKeysLookupCapability`, `NodesByLabelAndPropertyKeys` / `RelationshipsByTypeAndPropertyKeys`, and one membership-sidecar enumeration through `store.NodePropertyTxMemberKeysCapability` / `RelPropertyTxMemberKeysCapability` on tiered and sharded; a store without them is asked once per key, same rows; `ByLabelAndProperties` reads through the pair with the fewest forms and filters the others; it never combines forms). **Value identity** (`types.PropertyValueEqual`, `(*Node).PropertyValueEqual`, `(*Relationship).PropertyValueEqual`: exact type, NaN equal to NaN, also inside nested containers) decides whether an update is a no-op, so writing 3.0 over `int64(3)` stores the `float64`, and compares list and map values in CAS. The entity methods report existence plus identity without returning or copying the stored value.

Provenance and authorization shadow inputs accepted through props/updates are strict: `tkg_author_id` and `tkg_authorized_by` accept `string`, `tkg_signature` accepts `[]byte`, and `tkg_auth_level` accepts bounded signed/unsigned integer values plus whole-number `float32`/`float64` values. Non-nil values of the wrong type return an error before mutation. **Update-map provenance contract:** absence of a `tkg_author_id` / `tkg_signature` / `tkg_authorized_by` / `tkg_auth_level` key in an `Update` map preserves the corresponding stored value; presence overwrites it. A `nil` or zero-valued (`""`, `[]byte{}`, `0`) provenance value passed under a present key clears the stored field. There is no "absent" sentinel for these scalar fields — to leave provenance untouched, omit the key entirely. `UpdateInPlace`, label add/remove, property CAS, and `CloseVersion` do NOT accept provenance shadow keys (they reject every `tkg_` key via `ErrReservedPrefix`); existing provenance is always preserved on those paths.

Temporal shadow inputs accepted through props (`tkg_valid_from`, `tkg_valid_to`, `tkg_created_at`) accept `types.Instant`, signed integer milliseconds, unsigned integer milliseconds that fit in `int64`, and whole-number `float32`/`float64` milliseconds inside each float type's contiguous exact integer range.
- **On the legacy axis (`UntimedFromTxFrom` / `UntimedUnbounded`), `tkg_valid_from = 0` is "unset"**, not "valid since the epoch": an explicit 0 on any create door stores the same row as omitting the key, and the row is valid from its `TxFrom`; no refusal (stability policy). Only the shadow resolver reports the raw stored 0. Contract, doors and consequences: "Valid-time start (Config.UntimedValidStart)" below. Pinned by `TestZeroValidFromIsUnsetInEveryDoor`.
- **The instant 0 (round 11).** On a store with the legacy valid axis (`UntimedFromTxFrom`, `UntimedUnbounded`) a stored 0 means "no claim" / "open", so the instant 0 cannot be recorded: `tkg_valid_from` or `tkg_valid_to` = `types.ExplicitInstant(0)` (the explicit spelling of a claim of 0) is refused with `ErrZeroInstantLegacyAxis` (wraps `ErrInvalidTimeRange`), writing nothing; a non-zero `ExplicitInstant` is the plain number's claim. On an `UntimedWholeAxis` store every value is the instant it names, 0 included (a plain 0 and `ExplicitInstant(0)` are the same claim; omit the key to make none). Other reserved keys refuse an `ExplicitInstant` (`ErrInvalidTimeRange`). See "The valid axis" below.

## Graph Layer (`pkg/graph`) — sub-API surface

`*graph.Graph` is a thin façade. Package-level constructors: `New(Config) (*Graph, error)`, `Open(dir string, opts ...Option) (*Graph, error)` / `OpenInMemory(opts ...Option)` (convenience over `New`; `Option`s `WithSnowflakeNodeID(id)`, `WithValidation(v)`, `WithProfileSmall()` / `WithProfileServer()` / `WithProfileBulkLoad()`, later wins), `RestoreInto(cfg, dir)` (see IO), `NewBatchBuilder(g) (*BatchBuilder, error)` (= `g.Batch().New()`), and the pure helpers `DecomposeNodeID` / `DecomposeRelID`. Its direct methods are `Close() error`, `SetReplicationSource(store.ReplicationSource)`, the column scans `ScanNodeColumns` / `ScanRelColumns` / `ScanRelSegments` (see Reads), and 16 nil-safe sub-API accessor methods. Every sub-API is reached through its accessor method (v4.2.0 converted these from exported fields to methods):

Nil or zero-value graph façade entry points return nil for the sub-API (no panic). Calling a sub-API method on that nil receiver returns `ErrNilGraph` from error-returning methods and zero values from no-error helpers. Construct operational graphs with `graph.New`.

**Consumer-ergonomics aliases (v4.2.1/v4.2.2)**: `graph.QueryOpts = store.QueryOpts`, `graph.ShardDepth = store.ShardDepth`, `graph.DistanceMetric = store.DistanceMetric`; the entity-conflict sentinels `graph.ErrNodeExists` / `graph.ErrRelExists` and the index-existence sentinels `graph.ErrIndexExists` / `graph.ErrIndexNotFound` / `graph.ErrTemporalIndexExists` / `graph.ErrTemporalIndexNotFound` are all aliased on `pkg/graph` so consumers can avoid a dual `pkg/graph/store` import for `QueryOpts` configuration and `errors.Is` checks on the conflict and existence sentinels. `graph.DistanceCosine` / `graph.DistanceEuclidean` re-export the `store.DistanceMetric` constant values (same identity as the store-canonical constants) next to the `DistanceMetric` alias, closing the one gap where the alias existed but its values did not — a caller can now call `g.Index().CreateVector(...)`/`SearchNearest(...)` with graph-qualified constants only. `graph.ShardDepth`'s `Depth*` constants deliberately stay `storepkg`-qualified only (tiered-store-specific knobs, not part of the ergonomics re-export).

`Store` / `memory.Store` / `badger.Store` / `tiered.Store` types live in `pkg/graph/store{,/memory,/badger,/tiered}`. The Store interface is composed from capability sub-interfaces in `pkg/graph/store/capabilities.go` — the graph layer depends on `MandatoryStore` (Lifecycle, NodeCRUD, RelCRUD, Adjacency, BulkRead, Batch, History, Stats, Iteration). Delete batch methods coalesce duplicate IDs before validation and mutation. Lifecycle calls on nil concrete in-tree store receivers return `ErrNilStore` from `Close` and `Clear`; `graph.ErrNilStore` aliases the same store-layer sentinel. Iteration callbacks must be non-nil; open stores return `ErrInvalidStoreMutation` for nil `ForEach*ID` callbacks, while closed stores return `ErrStoreClosed` first. Non-nil `ForEach*ID` callbacks run outside backend locks and Tiered shard checkouts, so callbacks may call Store methods; Badger history iterators page IDs, overlay pending truncation deletes before async flush, and stop at the start high-water mark so callback-created higher history IDs do not extend the active iterator. Badger/Tiered registry save/load APIs reject nil registry pointers with `ErrInvalidStoreMutation` on open stores, while closed stores still return `ErrStoreClosed` first; `tiered.Store.SetLabelRegistry(nil)` is a no-op. Tiered `registry.msgpack` loads validate label and relationship-type slices before returning metadata, so deprecated single-registry save APIs cannot preserve a corrupt other half. Successful graph operations that allocate label or relationship-type tokens persist the updated registries to Badger/Tiered stores before returning, and import or mutation-bearing transaction rollback persists restored registry snapshots. Batch post-write registry checkpoint failures surface through `BatchResult.Errors`; rows that were already written keep their finalized caller-visible node/relationship state. Transaction create/import methods record any row that already committed for rollback even when the method returns the checkpoint error, and `GraphTx.Commit` retries a dirty registry checkpoint before making the transaction irreversible while clean read-only commits skip it. `tiered.MigrateFromBadger(src, dst)` loads source registries itself, requires an empty destination, preflights migrated entity tokens and relationship endpoints, rolls back inserted destination entities and restores the previous destination registry file on failure, rejects nil stores, non-empty destinations, or missing source registry metadata for non-empty data with `ErrInvalidStoreMutation`, and returns `ErrStoreClosed` for closed source or destination stores. Optional capabilities (`DepthHistoryIterationCapability`, `DeletedIterationCapability`, `DepthDeletedIterationCapability`, `PropertyIndexCapability`, `TemporalIndexCapability`, `VectorIndexCapability`, `HighFrequencyIndexCapability`, `FilteredVectorSearchCapability`, and since v4.44–v4.49 `DurableFlushCapability`, `HistoryPresenceCapability`, `HistoryStampsCapability`, `NodePropertyTxMembershipCapability`, `RelPropertyTxMembershipCapability`, `PropertyTxMembershipStatsCapability`, and (v4.51.0) `LabelTxMemberLookupCapability` / `RelTypeTxMemberLookupCapability` (the point form of the K1 label / type membership sidecar: `LabelTxMembersOf(token, ids, fn)` / `RelTypeTxMembersOf`, memory and badger), among ~80) are type-asserted at the call sites that need them; the complete list is `pkg/graph/store/capabilities.go` (`go doc -all ./pkg/graph/store`). The graph layer falls back to label-scan + property filter for `g.Nodes().ByLabelAndProperty` when `PropertyIndexCapability` is absent (correctness, not just acceleration). `ExAdjacencyCapability` (per node and direction, the relationships that named the node in a row its live adjacency no longer holds — deleted ones and earlier lives of re-imported ones; kept by the store with every delete and every history row with other endpoints; backlog 50) is used by the adjacency fold of `g.Temporal().OutgoingRelsAt`/`IncomingRelsAt`/`NeighborsAt`/`ForEachRelEffectiveAtNodes` and `g.Rels().*ForNodesAtPin`/`*ForNodesAtTx`/`ForEachAdjacent*At`: the fold costs O(the seed's ever-degree) instead of O(total history); stores that omit it transparently fall back to the wider history scan (correctness identical). `DeletedIterationCapability` (IDs with history rows but no current row) remains for the store's own sweeps.

`Config.Store` may be omitted to select the default memory or configured Badger backend. If supplied, it must be a non-nil concrete Store value; typed nil Store interfaces are rejected by `graph.New` with `ErrNilStore`.

Store explicit entity IDs must be positive. Write methods reject non-positive entity identities with `ErrInvalidStoreMutation`: `PutNode`, `ReplaceNode`, and `PutNodesBatch` reject zero or negative node IDs; `PutRelationship`, `ReplaceRelationship`, and `PutRelationshipsBatch` reject zero or negative relationship IDs and zero or negative start/end node IDs before endpoint lookup or partial mutation. Direct read methods that take caller-provided entity IDs (`GetNode`, `GetRelationship`, `Get*ByIDs`, adjacency reads, `Get*Version`, `Get*History`, and `Truncate*History`) also reject zero or negative IDs with `ErrInvalidStoreMutation` before not-found, empty-history, or successful no-op handling; adjacency `typeToken == 0` is reserved only for "all relationship types". Badger split relationship helpers validate the same positive relationship ID/type/endpoint tuple before partial writes or deletes, and repair-only helpers (`PurgeOrphanRelationshipIndexes`, `DeleteIncomingByRelID`, `ScanAndDeleteIncoming`) reject zero or negative IDs before scanning or no-op cleanup. Atomic history replacements reject nil current/history payloads before dereference or marshaling. Store replacement methods preserve indexed identity. Changing a node's label tokens through `ReplaceNode` or `ReplaceNodeWithHistory` returns `ErrInvalidStoreMutation`; use label-token mutation methods for label changes. Plain Store `DeleteNode` and `DeleteNodesBatch` remove only unconnected node rows and return `ErrInvalidStoreMutation` without changing rows when any target node still has connected relationships; `DeleteNodeCascade` and `DeleteNodeWithHistory` are the connected-delete surfaces. Tiered `DeleteNodeCascade`, `DeleteNodesBatch`, and `DeleteRelationshipsBatch` restore earlier accepted relationship or node deletes when a later connected relationship delete, node bucket, same-shard relationship bucket, or cross-shard relationship split delete fails while the node row still exists. Tiered `DeleteNodeCascade` also purges stale adjacency entries whose relationship row is already missing while deleting the node. Label-token mutation methods validate that the supplied current node adds or removes exactly the requested token before changing label indexes or history. Changing a relationship's type token, start node, or end node through `ReplaceRelationship`, `ReplaceRelWithHistory`, `DeleteRelWithHistory`, or cascade tombstones returns `ErrInvalidStoreMutation`; relationship tombstones supplied to `DeleteNodeWithHistory` must cover every live connected relationship exactly once and must not include unrelated relationships. History snapshots must also carry the same entity ID as their storage key.

`memory.Store` has a usable zero value. Direct callers may use `var ms memory.Store`; reads return empty/not-found results, and writes, index creation, and history writes lazily initialize the internal maps before mutation. Zero-value `badger.Store` and `tiered.Store` are not operational backends, but lifecycle and checked read/write entry points return `ErrStoreClosed` instead of panicking on nil internal handles.

Badger fixed-width key scans are exact-length only. Restart rebuild, history ID scans, pending history overlays, per-entity history reads, and history truncation ignore overlong entity, index, adjacency, or history keys with valid prefixes instead of parsing the fixed prefix bytes into live IDs or history entries.

Badger delete methods prefetch cache-miss rows before taking the global index write lock, then re-read the current cached row under the lock before cleaning label, type, property, temporal, high-frequency, vector, and adjacency indexes. This keeps ordinary disk reads outside `idxMu.Lock` without using stale indexed metadata for cleanup.

In `SyncWrites` mode, Badger metadata and split relationship helper writeOps are part of the synchronous durability contract. Property, temporal, high-frequency, and vector index create/drop methods flush their queued definition update after releasing `idxMu`, and split relationship entity/out plus incoming-index helper methods flush before returning too.

Store index methods reject reserved label token 0 with `ErrInvalidStoreMutation`. This applies to property, temporal, high-frequency, and vector index create/drop/search operations, plus persisted Badger/Tiered index definitions loaded on open. Property/vector index targets and `NodesByLabelAndProperty` also reject reserved `tkg_` property keys with `types.ErrReservedPrefix`, because shadow properties are resolved by the graph layer and are not stored in `PropertySlice`. Tiered vector definition files are map-shaped by `(label, property)`: identical duplicate records are deduplicated, while conflicting duplicates return `ErrVectorIndexExists`. During phased Badger/Tiered index creates, the in-memory placeholder is visible only to concurrent write maintenance: Badger property, temporal, and high-frequency query fast paths ignore building placeholders and fall back to complete scans, while Badger/Tiered vector search returns `ErrVectorIndexNotFound` until vector create finalization. On `memory.Store`, public read/write/history/index/count/iteration operations return `ErrStoreClosed` after `Store.Close`, including empty fast paths; exported test-only tampering helpers return no data or no-op. On `badger.Store`, public read/write/history/index/metadata operations return `ErrStoreClosed` after `Store.Close`, including cache-hit reads, counters, empty fast paths, public `Flush`, and split relationship helpers. On `tiered.Store`, valid index create/drop/search calls, direct read/count/bulk/history APIs, empty batch/history write edges, and public admin/metadata operations return `ErrStoreClosed` after `Store.Close` starts before touching shard handles, store-level vector metadata, reference-shard read state, catalog metadata, or registry files. In-tree vector search paths also re-check close state after vector index scans/filter callbacks before returning empty or raw-ID results.

Tiered catalog loads validate persisted topology before reopening shard handles. Duplicate shard names, multiple hot event shards, invalid kind/tier combinations, unsafe relative paths, negative stats, and zero or inverted event windows are load errors.

Internal no-error index helpers are defensive at their own boundary: zero-value property indexes and high-frequency indexes lazily initialize their maps on first `Add`, zero-value LRU caches lazily initialize as minimum-capacity caches, and nil property, temporal, high-frequency, and vector cleanup/read helpers no-op or return zero/nil values. Nil vector writes/searches return `ErrInvalidVectorIndexConfig` because those paths have an error channel.

### Entity management

- `g.Nodes().Add(ctx, labels, props)` / `g.Nodes().Import(ctx, id, labels, props)` (caller-supplied ID; `0` returns `ErrZeroID`, negative IDs return `ErrInvalidID`) / `g.Nodes().AddByIDIfAbsent(ctx, id, labels, props) (*types.Node, bool, error)` — the idempotent counterpart of `Import`: an existing ID returns that node with `created=false` and no error instead of `ErrNodeExists`. API 4.0: the previous separate `Add(labels, props)` and `Add(ctx, …)` collapsed into a single context-aware method.
- `g.Rels().Add(ctx, typeName, start, end, props)` / `AddByID(ctx, typeName, startID, endID, props)` / `AddByIDIfAbsent(ctx, typeName, startID, endID, props)` / `Import(ctx, id, typeName, start, end, props)`. Same `*WithContext` collapse applies (caller-supplied relationship import IDs use the same `ErrZeroID`/`ErrInvalidID` split).
- **Re-importing a deleted ID continues its chain** (`Nodes().Import`, `Nodes().AddByIDIfAbsent`, `Rels().Import`, `GraphTx.ImportNodeWithID` / `ImportRelationshipWithID`; backlog 38). The ID's history is kept: the new row's `Version()` is one above the highest version stored for the ID (0 for an ID without history), its `Integrity().PrevHash` is that row's hash (`Verify*Chain` verifies across lives), and it is recorded after every `TxFrom` / `TxTo` / `DeletedAt` of the ID's history — the plain door stamps the row at the clock, or one past them when they lie ahead of the clock (a delete of a row whose valid start lies ahead), on that row only — the commit clock is not moved; a `tkg_tx_from` at or below one is refused with `ErrTxOrder` (wraps `ErrInvalidTxFrom`) and writes nothing. An ID whose rows a retention purge removed after a history compaction continues above the compaction stub's trimmed versions. Every door reads the lives in order: the earlier life ends at its delete, the new one starts at its own valid start. A `GraphTx` rollback of the re-import restores the earlier life's rows exactly. Chains stored by v4.43–v4.47, where the re-import restarted at version 0, are read as before (their overwritten rows are not recovered).
- Cross-machine (foreign-endpoint) edges (ADR-0010, partitioned/sharded stores only — every other backend returns `ErrForeignEndpointUnsupported`): `g.Rels().AddByIDForeignEnd(ctx, typeName, startID, foreignEnd store.ForeignEndpoint, props)` creates a relationship whose END node lives on a slot owned by another machine — the caller resolves that endpoint out-of-band and supplies its attested hash and provenance (a malformed descriptor returns `ErrInvalidForeignEndpoint`; a configured temporal constraint returns `ErrForeignEndpointConstraint`, since the foreign end is not locally available to check). The local start endpoint is locked and hashed normally and the rel is minted in the start's slot. A foreign START is not supported — run that create on the start's own machine. `g.Rels().RecordForeignIncoming(ctx, edge store.ForeignIncomingEdge)` is its counterpart on the END node's machine: it records the incoming half-edge STUB (Model A) so `Incoming(END)` is locally complete.
- `g.Nodes().AddWithTx(ctx, labels, props, txFrom)` / `g.Rels().AddWithTx(ctx, typeName, start, end, props, txFrom)` (§4.1 transaction-time backfill). Creates the entity exactly like `Add` but stamps the caller-supplied `txFrom` as its `TxFrom` (Erkenntniszeit / knowledge time) instead of the system clock, so a re-ingest reproduces a documented historical state addressable via `AS OF SYSTEM TIME`. Requires the graph to be opened with `Config.AllowTxBackfill` — otherwise `ErrTxBackfillDisabled`; `txFrom` must be a positive instant not in the future (`ErrInvalidTxFrom` — a knowledge time cannot exceed wall-clock at write). Equivalent to passing the reserved `tkg_tx_from` property to any create door (node/rel `Add`/`Import`, batch create) under the gate. The plain `Update`/`Delete` doors keep the monotonic system `TxFrom`; a supersession or an ending at a caller instant goes through `UpdateWithTx` / `DeleteWithTx` (next item), under the same gate. `TxFrom`/`TxTo` are not hashed, so a backfilled row still passes `Verify*Chain` and replicates verbatim.
- `g.Nodes().DeleteWithTx(ctx, id, txTo)` / `g.Rels().DeleteWithTx(ctx, id, txTo)` (legacy axis; on `UntimedWholeAxis` use `EndValidity`) and `g.Nodes().UpdateWithTx(ctx, id, updates, txFrom)` / `g.Rels().UpdateWithTx(ctx, id, updates, txFrom)` — end or supersede belief at a caller transaction instant `t` (a replay or stream whose records carry their own knowledge time). `DeleteWithTx`: the tombstone carries `TxTo = DeletedAt = t` (`ValidTo` clamped to `t` only when open); a node delete stamps the one instant `t` on the node and on every relationship it cascades. `UpdateWithTx`: the superseded version gets `TxTo = t`, the new version `TxFrom = UpdatedAt = t`. A read pinned before `t` (`TxPin`, `TxAt`, `NodeAsOf`/`RelAsOf`, `*AsOf`) sees the old belief; a read pinned at or after `t` the new one. Checks, in order: `t <= 0` or in the future → `ErrInvalidTxFrom`; gate off → `ErrTxBackfillDisabled`; then, under the entity lock, the **ordering rule** — `t` must be after every `TxFrom` and `TxTo` recorded on the chain (history and current: `TxFrom` is not co-monotonic with the version) and after the current version's start (its `UpdatedAt`; for a delete also the effective valid-from, so the tombstone cannot invert the valid interval), on the node and on every cascaded relationship — otherwise `ErrTxOrder` (wraps `ErrInvalidTxFrom`; the message names the binding stamp) and nothing is written. A caller-instant delete also refuses a **recorded close at or after `t`** (`ValidTo >= t` on any row it would tombstone) with `ErrTxOrder` ("recorded close at or after t", both instants named): one tombstone row cannot both end belief at `t` and keep a close that pins before `t` believed (the plain `Delete` moves its own instant past a colliding close instead; a caller's `t` is never moved). An update that changes nothing refuses with `ErrTxOrder` (there is no version to stamp at `t`); an update of a closed entity returns `ErrAlreadyClosed`; the reserved `tkg_tx_from`/`tkg_tx_to` stay rejected as properties. A second delete returns `ErrNodeNotFound`/`ErrRelNotFound`; the same `t` twice returns `ErrTxOrder`. The commit clock is not advanced by `t`, so `NowTx` stays above every clock-stamped write. Replays pass `tkg_valid_from` on creates and updates: a derived valid-from is the mint or update time, and a later `t` before it refuses. The as-of column cache is invalidated after the write; replicas reproduce the stamps from the change feed (upgrade replicas before a writer uses these doors). Twins with the same rules: `GraphTx.DeleteNodeWithTx` / `UpdateNodeWithTx` / `DeleteRelationshipWithTx` / `UpdateRelationshipWithTx`, and the `BatchBuilder` / ingest `Session` queue doors of the same names (see Batch operations).
- `g.Nodes().Retract(ctx, id)` / `g.Rels().Retract(ctx, id)` and `g.Nodes().RetractWithTx(ctx, id, txTo)` / `g.Rels().RetractWithTx(ctx, id, txTo)` — say "this was never true" (backlog 43). **`Delete` ends validity, `Retract` ends belief:** after `Delete` at `D` a read pinned at or after `D` still finds the entity at its past valid times (only valid time from `D` on is gone); after `Retract` at `T` a read pinned at or after `T` finds it at **no valid time at all** — state doors (`NodeAt` / `NodeAtTx` / `NodesAtTx` / `*DuringTx` / `*Relating` / `ByLabel` / `ByType` / `All` with `ValidAt` or `ValidStart`/`ValidEnd` and `TxAt`, the property lookups, the adjacency doors, `Snapshot` / `Diff`, the column scans, `CountByLabelAt` / `CountByTypeAt`), record doors (`NodeAsOf` / `NodesAsOf` / `TxPin` scans: absent, as after a delete), and the effective timelines (empty; the scan forms leave the entity out). A read pinned before `T` answers byte for byte as before the retraction. A node retraction cascades exactly like a node delete: one instant `T` on the node's tombstone and on every relationship it has, all written in one store call, all retracted. The tombstone is `Delete`'s (`TxTo = DeletedAt = T`, `ValidTo` clamped as for a delete) with `Temporal().Retracted == true` (`types.TemporalMetadata.Retracted`; `false` on a plain delete's tombstone): `History` returns it, `HasHistory` stays true, `LatestStamps` reports `deleted` with `txTo = T`; current-state reads (`Get`, plain scans, counters, adjacency) lose the entity as after a delete; `UniqueCurrent` frees the value and `UniqueForever` keeps the claim, as after a delete. The retracted life is the rows since the entity's previous delete (or its creation): an earlier life ended by a `Delete` keeps answering, and it answers as it did before the retracted life was recorded (a retracted life also stops superseding or bounding it). A re-import of a retracted ID starts a new, visible life (versions continue). `RetractWithTx` takes `DeleteWithTx`'s contract unchanged: `ErrInvalidTxFrom` (`t <= 0` or in the future), then `ErrTxBackfillDisabled` (gate `Config.AllowTxBackfill`), then under the entity locks `ErrTxOrder` against the whole chain of the node and of every cascaded relationship and for a recorded close at or after `t`; the commit clock is not advanced by `t`. Errors of every retraction door: an ID that never existed is `ErrNodeNotFound` / `ErrRelNotFound`; an ID already deleted or retracted is refused with an error matching **both** `ErrEntityDeleted` and the not-found sentinel (a delete's tombstone is not turned into a retraction), and nothing is written. Twins: `GraphTx.RetractNode` / `RetractNodeWithTx` / `RetractRelationship` / `RetractRelationshipWithTx` (rollback restores the rows exactly), and the `BatchBuilder` / ingest `Session` queue doors of the same names (a `*WithTx` retraction is pre-flighted with the unit and must be its only op on the entity and its cascaded relationships; a plain retraction fails on its own like a plain delete). Events: the delete events. Upgrade every reader of the data (replicas, importers, a badger directory opened by another binary) before any writer uses a retraction door: an older binary skips the marker and answers the retraction as a delete.
- `g.Nodes().EndValidity(ctx, id)` / `g.Rels().EndValidity(ctx, id)` and the GraphTx twins `EndNodeValidity(id)` / `EndRelValidity(id)` — the delete that ends validity at its instant `T` and **keeps the valid past on every valid axis**: the tombstone is the legacy axis's `Delete` tombstone (`DeletedAt = TxTo = T`, `ValidTo = T` where the row was open, `Retracted == false`, `DeleteWroteValidTo()` true), and the node door cascades it to every relationship of the node in one store call. Current-state reads lose the entity; state doors at a valid instant before `T` keep answering it at pins at or after `T`; reads pinned before `T` answer as before. On a legacy-axis graph it writes exactly `Delete`'s rows; on an `UntimedWholeAxis` graph, whose `Delete` is a retraction (an untimed delete makes no valid-time claim), it is the delete that keeps the past. Errors as `Delete`. No `*WithTx`, batch or ingest twin yet (backlog 78).
- `g.Nodes().Update(ctx, id, updates)` / `g.Rels().Update(ctx, …)`. Update maps accept provenance/authorization shadow keys, reject other `tkg_` keys, and validate malformed keys/values before entity locks or transaction rollback snapshots.
- `g.Nodes().UpdateInPlace(ctx, id, updates)` and rel mirror. In-place updates mutate without a version bump or history entry — for correcting metadata.
- `g.Nodes().Delete(ctx, id)` (cascade). Node delete uses a two-phase lock: it reads adjacency, locks the node and connected relationships, re-reads the node plus adjacency under that full lock, then writes tombstone history through `DeleteNodeWithHistory`. Cascaded relationship rows count toward relationship delete stats and emit `EventRelDelete` before the final `EventNodeDelete`. `g.Rels().Delete(ctx, id)`.
- `g.Nodes().AddLabel(ctx, id, label)` / `RemoveLabel(ctx, id, label)` (`ErrLastLabel` if it is the only label, `ErrLabelNotFound` if not present). Empty, whitespace-only, or overlong label names return `ErrEmptyName`/`ErrNameTooLong` before node lookup, registry lookup, or transaction snapshots. `AddLabel` checks `MaxLabelsPerNode` before creating a token for a previously unseen label. Node create/import/add-label paths restore newly allocated label tokens when the final Store write fails.
- Relationship creation (`g.Rels().Add`, `AddByID`, and `AddByIDIfAbsent`) rejects empty, whitespace-only, or overlong type names before endpoint lookup or property validation. Direct create paths fetch live endpoints under endpoint locks, capture `FromNodeHash`/`ToNodeHash`, run temporal constraints before allocating a token for a previously unseen relationship type, and restore newly allocated type tokens when the final Store write fails. `g.Rels().AddByID*` only changes the endpoint input form; it does not weaken endpoint verification or integrity metadata.
- Batch creation validates at queue time but defers new label/type token allocation until `Execute`. Returned node/relationship pointers use non-zero probe tokens for unseen names and are retokenized in place before persistence. Batch update queues deep-copy caller update maps. Failed or panicking node/relationship writes restore newly allocated registry entries and queue-time pointer state.
- Versioned mutation overflow: node/relationship updates, node label add/remove, node/relationship property CAS, transaction updates, and batch updates return `ErrVersionOverflow` if the current entity version is already `math.MaxUint32`; no history entry or wrapped version is written.

### Properties

- `g.Nodes().SetProperty(ctx, id, key, value)` / `DeleteProperty(ctx, id, key)` / `g.Rels().SetProperty(...)` / `DeleteProperty`. Setters deep-copy accepted reference values before storing them.
- `g.Nodes().CompareAndSetProperty(ctx, id, key, expected, newVal)` and `g.Rels().CompareAndSetProperty(...)` — atomic CAS. Returns `(true, nil)` on match+update, `(false, nil)` on mismatch, `(false, error)` on real error. `expected == nil` means "must not exist"; `newVal == nil` means "delete". A numeric `expected` compares under the property equality (`int64(42)` matches a stored `int(42)`; a NaN matches nothing), any other under value identity (lists and maps, NaN inside them matching NaN), without returning or copying stored reference values. Matched mutations recheck `MaxPropertiesPerEntity` before persistence; successful CAS bumps version, writes history, updates temporal metadata.

### Reads

- Single-entity: `g.Nodes().Get(ctx, id)` / `g.Rels().Get(ctx, id)`.
- Single-entity without a copy (since v4.41): `g.Nodes().Lend(ctx, id)` / `g.Rels().Lend(ctx, id)` return the store's own FROZEN current row instead of `Get`'s mutable copy (memory, badger, tiered: no copy, no allocation; any other store or a wrapper: a frozen copy, so the contract is the same). Lifetime: the store never writes a row after lending it (a write stores a new row), so a lent row may be held and read from any goroutine indefinitely; it is the entity at the read and does not follow later writes — re-check `NodeMutationEpoch` / `RelMutationEpoch` to know whether held rows are still current. Mutation: error-returning mutators fail with `types.ErrFrozenNode` / `ErrFrozenRelationship`, the others panic, `DeepCopy` thaws. Errors as `Get`. Store contract: optional `store.EntityLendCapability` (`LendNode`, `LendRelationship`). Memory, 4-property node: `Get` ~95 ns / 4 allocations, `Lend` ~16 ns / 0 (badger cache hit ~26 ns / 0).
- Many entities without a copy: `LendByIDs`; exact equality counts; ordered walks without the row; per-type degree counts: see "Lending, exact counts and ordered walks".
- Dense ordinals (since v4.41): `n.Ordinal()` / `r.Ordinal()` is a store-assigned integer, 1, 2, 3, … in the order the store first held the entity, on every row a read hands out (point reads, `Lend`, scans, adjacency, history rows of a live entity); `g.Nodes().MaxOrdinal()` / `g.Rels().MaxOrdinal()` return `(max, ok, err)` for sizing an ordinal-indexed array (`max+1`). Guarantees within one open store (`store.OrdinalCapability`): stable while the entity has a current row, never handed to a second entity (a deleted entity's ordinal is retired; a held one goes stale, never aliases), dense (deletes leave holes), assigned under the write lock before the row is visible. Not persisted: not stable across a reopen (badger renumbers the stored entities 1..N in ID order on open), between a primary and a replica, or between stores; not in the wire, the hash, the change log or exports. Backends: memory (in the row, no map; relationships of a declared segment type carry 0), badger (RAM ID → ordinal maps; a history row of a deleted entity carries 0; `badger.Config.DisableOrdinals` turns it off), sharded (one allocator for all slots); tiered assigns none (`ok=false`, every row 0) because a cold shard that idle-closes and reopens would renumber its entities while the store stays open. Rows returned by create doors carry no ordinal (read the entity to get it). Cost: `Node` stays in its 96 B size class; `Relationship` moves from 80 B to the 96 B class, +16 B per relationship row on the memory store.
- Scans restricted to an ordinal bitset (round 8 request 4, dynamic filters): `g.Nodes().ForEachByLabelOrdinals(label, set []uint64, opts, fn)` / `g.Rels().ForEachByTypeOrdinals(typeName, set, opts, fn)` stream the rows `ForEachByLabel` / `ForEachByType` stream under `opts` (current or any temporal coordinate), kept for the entities whose current ordinal is in `set` (bit k of `set[k/64]` = ordinal k; size from `MaxOrdinal`), ascending ID order, `After` / `Limit` as for the scan, `fn` false stops. An entity without a current row has no ordinal and is never selected, at a pin too. Where the store tells ordinals from RAM (`store.OrdinalLookupCapability`: memory, badger) and lists a label's members (badger, sharded), only the selected rows are lent and, at a coordinate, only the selected candidates resolved; otherwise the scan filters its rows. 100,000 nodes, 1% selected: badger current 95 ms -> 11 ms, badger `TxPin` 360-404 ms -> 18 ms, memory `TxPin` 43 ms -> 21 ms, memory current unchanged (1.0 ms). `store.ErrCapabilityNotSupported` on a store without ordinals (tiered, badger `DisableOrdinals`). Test: `TestForEachByOrdinals`.
- Endpoint ordinals on the row (since v4.43): `r.StartOrdinal()` / `r.EndOrdinal()` are the dense ordinals of the relationship's endpoints, equal to `g.Nodes().Lend(start/end).Ordinal()`, on the current rows a store keeps and hands out (point reads, `Lend`, scans, adjacency). 0 on a history row, where the store numbers none (tiered, badger `DisableOrdinals`), on a declared segment type's rows, for an endpoint the store holds no current row for, and on rows returned by create doors. Memory sets them when it stores the row (from the endpoints' rows); badger at every decode and cache fill from its RAM ID → ordinal maps; sharded resolves an endpoint on another slot through that slot (`badger.Config.ForeignNodeOrdinal`). Not persisted, hashed or exported. Cost: none per row — `Relationship` grows from 88 B to 96 B, the size class it already allocated.

Direct read counters include scalar `Get`, transaction `Get*`, and bulk `GetByIDs` rows returned. Mutation counters include successful batch creates and successful temporal `CloseVersion` writes.
- `QueryOpts{Limit, After, ValidAt, ValidStart, ValidEnd, ValidAtSet, ValidWindowSet, TxAt, TxPin, TxAtSet, TxPinSet, IncludeEclipsed, Depth, NoSort}`: cursor pagination, temporal push-down, and shard-depth filtering. Zero values mean "all". `TxAt` is the combined bitemporal transaction-time filter (pair it with a valid-time coordinate; on its own it valid-filters at now — the later of the wall clock and the transaction clock, so no version the graph recorded starts after it — see the RT-2 footgun warning in the `TxAt` godoc). `TxPin` is the pure knowledge-time belief-state pin (identical to `NodesAsOf`, NO valid-time filter) and is mutually exclusive with the valid-time filters and with `TxAt` (`ErrConflictingTemporalOpts`). `Limit` must be non-negative; negative values return `ErrInvalidQueryLimit`. `After` accepts `0` for the first page or a non-negative `types.EntityID` cursor; negative cursors return `ErrInvalidQueryCursor`. `ValidAt != 0` is a point-in-time temporal filter; `ValidStart`/`ValidEnd` form an interval filter `[ValidStart, ValidEnd)` only when both are set, and active intervals must satisfy `ValidStart < ValidEnd` or return `ErrInvalidTimeRange`. `0` is the only unset value: a negative instant is a real bound, so `{ValidStart: types.UnboundedValidFrom, ValidEnd: math.MaxInt64}` is "any valid time" and reaches rows valid only before the epoch (an untimed row under `UntimedUnbounded` closed at `tkg_valid_to` 1, an explicit `[-5000, -4000)`). Explicit presence (since v4.59.0): `ValidAtSet`, `ValidWindowSet`, `TxAtSet`, `TxPinSet` make their filter present at any instant, so 0 is an ordinary instant — `{ValidAtSet: true}` is AT TIME 0, `{ValidWindowSet: true, ValidStart: x}` is `[x, 0)` (BETWEEN x AND 0, end exclusive), `{TxAtSet: true}` / `{TxPinSet: true}` pin transaction time 0 (nothing is recorded by then: every belief has a positive `TxFrom`, so those reads are empty); an unset flag keeps the zero-means-unset reading, and precedence (ValidAt over the window) and the `TxPin` conflict are unchanged. One rule for every door and store: `QueryOpts.HasValidAt()` / `HasValidInterval()` / `HasValidTimeFilter()` / `HasTxAt()` / `HasTxPin()`, with `HasValidBound()` / `HasTimeCoordinate()` for the current-value doors that decline any time coordinate (an unflagged lone bound included) (v4.58.1, presence v4.59.0; before v4.58.1 a bound `<= 0` silently disabled the interval). `temporal.Pin` (the effective-page doors) has the same `ValidAtSet` / `ValidWindowSet`, read through the same methods (its point and window stay exclusive, an unflagged lone `ValidStart` is `[start, inf)`, `Tx` stays required > 0). `Depth` must be `DepthAll`/`DepthHot`/`DepthWarm`; unknown values return `ErrInvalidShardDepth` from MemoryStore, BadgerStore, TieredStore, and graph-level query methods before empty label/type/index shortcuts. Valid non-default depth selectors are equivalent to all data on single-shard stores. Node, relationship, ID-only, property, type, and vector queries compose temporal filters with `Depth` before pagination. Badger temporal entity-returning pages apply `After` by sorted ID first but consume `Limit` only after cache-miss rows have been fetched and verified against temporal metadata. `NoSort` drops the O(n log n) node-ID sort a label scan applies before materialization — for order-independent consumers (aggregation, count, an unordered `RETURN`); it is HONOURED ONLY when `After == 0`, since keyset pagination requires sorted order. The streaming `ForEachByLabel` / `ForEachByType` need no per-scan sort at all since v4.41 (memory and badger with the RAM label index): they walk the label's (type's) kept ascending member list, sorted once when the first scan builds it and extended in place by inserts, so their order is ascending with or without `NoSort` and a scan that stops early costs the rows it read (20,000 members, stop after 3: 1.31 ms sorted / 118 µs `NoSort` → 0.6 µs). An insert of an ID below the list's last member (an older node acquiring the label, an import reusing an ID) drops the list, and more than half of it going stale through removals drops it too; the next scan rebuilds it at the old cost. `LabelIndexOnDisk` keeps collecting from the keyspace; a declared segment type (ADR-0011) collects its refs; tiered and sharded take the materializing path as before. A temporal-filter `ForEachByLabel` / `ForEachByType` streams as well (round 6 request 12, every backend): the `ByLabel` / `ByType` answers in ascending ID order with or without `NoSort`, resolved 1,024 candidates per hold of the graph read lock and handed to `fn` with no lock held, so an early stop resolves no further; an entity without history rows (`store.HistoryPresenceCapability`) is answered under a pure valid-time filter from the row the label (type) scan read instead of a second read and a chain resolve (also in `ByLabel`, `ByType`, `CountByLabelAt`, `CountByTypeAt`). `IncludeEclipsed` is a reserved no-op, kept for API compatibility; one-tick rows are ordinary spans — consumers must not set it; see stability.md's Experimental Surfaces.
- Scan order statement: `g.Nodes().ScanKeepsOrder(label) (bool, error)` / `g.Rels().ScanKeepsOrder(typeName)` report whether a current-state `ForEachByLabel` / `ForEachByType` scan walks a member list the store keeps in ascending ID order (no per-scan collect or sort; the first scan after the list was dropped sorts it once): true on memory (not for a declared segment type) and badger (labels: not with `LabelIndexOnDisk`), false on tiered, sharded and external stores and for a scan with a temporal filter. - Read costs: `g.Stats().ReadCosts() (store.ReadCosts, ok bool, error)` states what the read doors cost through the graph per backend, in nominal nanoseconds per row (medians of `BenchmarkReadCosts`, one CPU, M4 Max): a `Lend`, a streaming scan row and an adjacency relationship, each for a row held decoded in RAM and one read from the backing store, plus `HeldRows` (-1 every row, 0 a byte budget governs, n per kind / per shard). - Columnar reads (DocValues) — `g.Nodes().ForEachDocValues`, `ForEachDocValuesMulti`, `DocValuesSnapshot`, `DocValuesSnapshotAsOf`, `ForEachDocValuesAsOf`, plus the staleness gates `NodeMutationEpoch()` and the per-label `NodeLabelMutationEpoch(label)`. A snapshot also reads by position: type-assert `types.NodeColumnRowReader` (`Len()`, `RowAt(i, vals, present) NodeID`; memory, badger, tiered, sharded) to split one label's column into ranges read by several workers at once; positions are ascending by ID on memory and badger, a tiered snapshot concatenates its shards, a sharded one its slots in slot order (its streams too; its `Row` goes straight to the ID's slot). Backends with the current-state doors: memory, badger, tiered and (since v4.43) sharded; the as-of doors work on every backend, and a `txAt` at or below 0 reads no member (nothing recorded by then; round 11, it was `ErrInvalidTimeRange`). `g.Nodes().DocValuesColumn(label, key) (store.DocValuesColumn, ok bool, error)` states without building what these doors build for a key — `DocValuesNumeric`, `DocValuesString` or `DocValuesNone` (mixed or unsupported values, an empty or over-cap label, no column path) — from the exact value-class counters (`store.DocValuesColumnOf` is the rule); valid until the next node write; `ok=false` where the store keeps no class counters (badger `DisablePlannerStats`). **Experimental surface** — the reader types and their shape are explicitly NOT covered by the v4 stability promise; see stability.md before depending on them.
- Typed column scans (`store.NodeColumnScanCapability`) — an OPTIONAL store capability delivering node rows as TYPED columns (`ColumnBatch`: `IDs`, `ValidFrom`, `ValidTo`, `Kinds`, and per-column `Ints`/`Flts`/`Strs`/`Bools`/`Null`/`Other`, one slot per row) instead of `[]*types.Node`. `Other[c][k]` (since backlog 48, the meaning of `SegmentColumnValues.Other`); a `store.RelColumnSource` reports it only when it also implements the optional `store.RelColumnOtherSource` marks a row that holds the property but not as a `Kinds[c]` value — a list, a map, a struct, another scalar kind — read it from the row; such a cell is also `Null` with a zero slot, and `Other` is nil on a batch without one. `RelColumnBatch` fills it identically. A consumer reading scalars through `GetProperty` gets `any`, so a value stored as `Instant`/`int`/`int32` costs a heap box on the way to `int64` (every integer width is an `int64` column, a `uint`/`uint64` past `MaxInt64` a `float64` one, as in the DocValues snapshot); the scan converts inside the store where the type is still known, so no box is created. Implemented by the memory and badger backends; consumers type-assert and fall back to `NodesByLabel`. Through `g.ScanNodeColumns(label, props, opts, fn)` a temporal `QueryOpts` (`ValidAt`, `ValidStart`+`ValidEnd`, `TxAt`, `TxPin`) is answered exactly as `g.Nodes().ByLabel(label, opts)` answers it — each node's version under opts, history included, `ValidFrom`/`ValidTo` of that version, same validation (`ErrConflictingTemporalOpts`) — never from the current rows (since v4.44; before, the scan filtered current rows by valid time and ignored `TxAt`/`TxPin`). With `TxAt` (and `ValidAt`) the rows come from the label's state cut (see `CountByLabelAt`; the requested keys are kept as classified cells, 9 B per row and key, and a key the cut lacks rebuilds it for the union), replayed through `store.ScanColumnsFromNodeSource` (`store.NodeColumnSource`), the row driver's rules; `fn` then runs without graph locks (under the read lock when the fold answers: the first ask of a pin, a build that failed or did not fit, writes in flight at the pin) (100 K nodes: 2 ms against 210 ms memory / 1.05 s badger for the fold). At every temporal opt the batches carry no ordinals (`Ordinals` 0, since backlog 28): a winning row's stored ordinal changed when a later write moved or deleted it, so the answer at a pin changed. State cuts share the as-of column set's invalidation (a history rewrite at or below a cached pin, an `UpdateInPlace`, a delete that clamps a scheduled close; other forward writes keep them; one build per key, a failed or oversized build not repeated at that epoch) and one LRU byte budget per graph (256 MiB; node 40 B, relationship 56 B per segment plus the cells); a cut is cached only once every write stamped at or below its pin has landed. **REFUSES rather than widens** a column holding both integral and floating values (`graph.ErrMixedNumericColumn`): promoting it to `float64` is lossless for the values and not for the caller, because a consumer deciding something from OBSERVING a mixed column would see a uniform one. **Experimental surface** — see stability.md.
- Relationship columns (badger AND memory) — `RelColumnSnapshot(typeToken, propKeys)` returns a columnar snapshot per RELATIONSHIP TYPE, carrying `tkg_rel_start` / `tkg_rel_end` endpoint columns alongside any requested properties. Endpoints are always built (they are structure, not an optional column), so a traversal aggregation reads `(start, end, weight)` as three aligned typed arrays with no `*types.Relationship` materialised. Freshness is `RelMutationEpochForType(typeToken)`. **The two backends invalidate at different granularity**: badger stripes per type, so a write to one relationship type does not invalidate another's columns (inserts and updates know their type; deletes and bulk purges over-invalidate, the safe direction). The memory store keeps ONE store-wide epoch, so a write to any type invalidates every type — striping buys nothing when the rebuild walks an in-memory map. Treat the stamp as a freshness token, never as a change count, and never assume per-type isolation portable across backends. **Experimental surface** — see stability.md.
- Relationship column scan (badger AND memory) — `g.ScanRelColumns(relType, props, opts, fn)` streams relationships of a type as typed column batches, the sibling of `ScanNodeColumns`. `RelColumnBatch` carries `StartIDs` / `EndIDs` as their own arrays, so a traversal aggregation reads `(start, end, weight)` as three aligned typed slices with no `*types.Relationship` materialised. Both batches carry `Ordinals` parallel to `IDs` (each row's dense ordinal, `types.Node.Ordinal` / `types.Relationship.Ordinal`; 0 where the store numbers none: tiered, badger `DisableOrdinals`, a declared segment type), and `RelColumnBatch` carries `StartOrdinals` / `EndOrdinals` (the endpoints' ordinals, `StartOrdinal` / `EndOrdinal`), so a consumer numbering entities needs no read per row; badger reads a snapshot's ordinals once and keeps them with the snapshot. Badger serves it from the columnar snapshot and falls back to the row path for anything the snapshot cannot answer (non-temporal `QueryOpts`, a mixed-numeric column); memory uses the row path. `ok=false` means the backend has no column scan; an unknown relationship type is `ok=true` with zero rows. An empty type name (since v4.43) reads every relationship type, type by type in type-token order (each type's batches in ID order), and every batch names its type in `RelColumnBatch.RelType`. A temporal `QueryOpts` is answered exactly as `g.Rels().ByType(relType, opts)` answers it (each relationship's version under opts, history included, for the empty type name too; since v4.44 — before, current rows only and `TxAt`/`TxPin` ignored); with `TxAt` (and `ValidAt`) from each type's state cut (see `ScanNodeColumns`), and with no `Ordinals` / `StartOrdinals` / `EndOrdinals` at any temporal opt. Refuses a mixed int/float column with `ErrMixedNumericColumn` rather than widening, identically to the node scan — the rules are shared code, not a second implementation. The callback MUST NOT retain the batch. **Experimental surface** — see stability.md.
- `badger.Config.ColumnsOnDisk` (default OFF; a badger store option, not a `graph.Config` field) persists built columnar snapshots so a cold read decodes a blob instead of re-reading every entity (measured 41x at 50,000 nodes). A persisted column is a REBUILD ACCELERATOR and never a read authority: a stale epoch stamp, an unreadable blob or a missing chunk all mean "rebuild", so enabling it changes nothing observable except latency, and needs no migration. Blobs are chunked at 512 KiB because badger refuses a value over 1 MiB.

- `types.Relationship.ValidRange() (from, to types.Instant, ok bool)` is the relationship counterpart of the node accessor below, with the same rationale.
- `types.Node.ValidRange() (from, to types.Instant, ok bool)` returns an entity's validity bounds without the copy `Temporal()` must make for a frozen entity (its fields are exported, so a shared pointer is a write escape hatch, and every entity a store scan returns is frozen). ### Lending, exact counts and ordered walks

Purpose: read paths for planners and parallel scans that avoid per-entity transactions and row decodes. All are read-only and cost nothing on writes (sigma-tkgd round 7).

**Many rows without a copy.** `g.Nodes().LendByIDs(ctx, ids, fn(i, row) bool) error` / `g.Rels().LendByIDs(ctx, ids, fn)` lend each ID's current row as `Lend` does and call `fn` with the ID's position `i` in `ids`. An ID naming no entity is skipped, duplicates are lent once per position, calls come in ascending ID order (equal IDs in `ids` order), `fn` returning false stops, and `fn` runs with no lock held. A non-positive ID fails with `ErrInvalidStoreMutation` before any read; the context is checked per chunk. IDs are read in chunks of 4,096, each under one read: badger serves a chunk's cache misses through one re-pinning snapshot in key order without filling the cache, memory takes one store lock, tiered, sharded and external stores lend per ID. Safe for concurrent calls. Optional capability `store.EntityLendBatchCapability`. Cost (300,000 nodes, batches of 4,096, `BenchmarkLendByIDs`): badger `Lend` 2.85 / 1.73 / 1.63 us per node at 1 / 4 / 16 goroutines, `LendByIDs` 1.12 / 0.38 / 0.24 us.

**Exact equality counts.** `g.Nodes().CountByLabelPropertyValue(label, key, value, opts) (count int64, exact bool, err error)` / `g.Rels().CountByTypePropertyValue(...)` count the current entities whose value equals `value` under the property equality (top of this file), so the count is `len(ByLabelAndProperty)`: summed from the index's per-value sets of the value's equal keys (`PropertyIndex.EqualCount`), reading no row and no ID. `exact=false` with no error is the decline a planner probes per (label, key): no property index, tiered or external store, badger `PropertyIndexOnDisk` (nodes), an index being built, an Elements index, a temporal value, a list or map, an unknown label or type, any temporal opts. Memory, badger, sharded (sum over slots). Cost: 0.28-0.29 us against 0.32 ms (memory) / 7.8-10.2 ms (badger) for counting 3,000 matches among 300,000 (`BenchmarkCountByPropertyValue`).

**Ordered walks without the row.** `g.Nodes().ForEachIDByLabelPropertyRangeOrdered(ctx, label, key, min, max, inclMin, inclMax, desc, opts, fn(id, value) bool)`, the string twin `ForEachIDByLabelPropertyPrefix(ctx, label, key, prefix, desc, opts, fn)` and the `Rels()` mirrors (`ForEachIDByTypePropertyRangeOrdered` / `ForEachIDByTypePropertyPrefix`) stream `(ID, stored value)` in value order (descending when `desc`), ties by ID ascending, from the property index alone (`RangeOrderedValuePage` / `PrefixOrderedValuePage`). The bounds apply exactly (no re-check); the value keeps its stored type (int64 3 and float64 3.0 share a position). Pages of 256 under the store's read lock, `fn` with no lock held, context checked every 4,096 entries. Every unsupported case is `ErrIndexNotFound`, never a slower walk: temporal opts (use the row doors), tiered, sharded and external stores, badger `PropertyIndexOnDisk` (nodes), no index, an Elements index, an index being built, an integer past 2^53. Memory and badger. Cost: badger 2.8 us per node through the ordered row door, 0.09 us here (`BenchmarkForEachIDOrdered`).

**Per-type degree counts.** `g.Stats().TrackRelTypeDegrees(type)` / `UntrackRelTypeDegrees(type)` opt a type into maintained counts: `RelTypeDegreeStats` then keeps the per-node out- and in-counts after its first count and applies the relationships created since (Add, AddByID, AddByIDIfAbsent, Import, their transaction mirrors, `AddRelationships`, Batch), instead of recounting the type after each write to it. Sound by an accounting identity checked under the graph's write lock: the type's mutation stamp moved by exactly the number of recorded creates; any other change (delete, update, rollback, another door, a type sharing the stamp's stripe) fails it and the type is counted again, as before. Cost, tracked types only: two per-node maps (about 40-50 B per distinct endpoint), up to 65,536 recorded creates between reads, a short lock per create; untracked graphs pay one atomic load per create. A write plus a read at 100,000 relationships of the type: 2.3-6.6 us tracked against 12-16 ms recounted. Tiered, sharded and external stores (no per-type stamp) count as before. Optional capability `store.RelTypeDegreeCountsCapability` (badger). Tests: `TestTrackRelTypeDegrees`, `TestCountByPropertyValue`, `TestForEachIDOrdered`, `TestLendByIDs`.

**Numeric bounds per label and type.** `g.Stats().PropertyBounds(label, key, opts)` / `RelPropertyBounds(type, key, opts)` return `(store.PropertyBounds{Min, Max, MinValue, MaxValue, Classes}, ok, err)`: the smallest and largest numeric value of the key over the current entities (the property index's first and last numeric key; NaN left out, a float32 by its shortest decimal rendering, a stored value at each with the type preference float64, float32, then integers widest first) and the exact type-class partition with `Missing`, so `NumericOnly()` (NaN counts as a number) and `NullFree()`. All parts are read under one store lock and agree under concurrent writers; O(1), no walk. `ok=false` with no error where the bounds cannot be stated exactly: no index on the pair, an index being built, an Elements index, an integer past 2^53 in the index, badger `PropertyIndexOnDisk` (nodes), planner statistics disabled, external stores (sharded and tiered fold their parts' bounds since sigma round 10, any part declining declines), an unknown label or type, temporal opts. Every in-tree backend (`store.NodePropertyBoundsCapability`, `store.RelPropertyBoundsCapability`; sharded and tiered fold their parts; a configuration without bounds reports so through `store.PropertyBoundsStatedCapability`). Read-only: no write cost. Test: `TestPropertyBounds`.

**Member time statistics per label and type.** `g.Stats().LabelTimeStats(label)` / `RelTypeTimeStats(type)` return `(store.MemberTimeStats{Members, ExplicitValid, LastEnded}, exact, err)`: the current members, those whose row carries an explicit valid time (`tkg_valid_from` or `tkg_valid_to`), and `LastEnded`, the latest `TxTo` / `DeletedAt` over the history rows of the entities whose rows ever carried the label (type). `HistoryAfter(pin)` (= `LastEnded > pin`) says whether a read pinned at `pin` may see a version that is not the member's current row; `Eternal()` is neither explicit valid time nor an ended row, so a source can declare its rows eternal at bind without scanning them. "Eternal" means no explicit valid time and no ended row (a start at -inf, `types.UnboundedValidFrom`, without an end counts as none); under `UntimedFromTxFrom` each member is still valid from its `TxFrom` (backlog 62), so a valid-time read at t equals a transaction-time read pinned at t — keep the valid-time filter; under `UntimedUnbounded` each such member is valid at every instant. No write cost (memory: one atomic add per history row write or removal): the explicit count is counted on the first call after a write to the label (one pass over its current rows) and then served in O(1) against the label's mutation epoch; `LastEnded` is O(1) on a store without history rows of the kind, else computed once per history change (memory and badger keep a history generation, `HistoryGeneration()`) over the ever-members with history (RAM presence check and stamps, no row read). Cached reads 120-280 ns; after a write to a 100,000-node label 23-75 ms memory / 110-220 ms badger. `exact=false` when writers kept moving the epoch across three counts or the store keeps no epoch (counted per call). An unknown label is zero stats. Test: `TestMemberTimeStats`.


**Ranges over any version recorded at a pin** (sigma-tkgd round 9 R9-1). `g.Nodes().ForEachByLabelPropertyRangeAnyVersion(label, key, min, max, inclMin, inclMax, pin, fn)` / `g.Rels().ForEachByTypePropertyRangeAnyVersion(type, ...)` visit, once each in ascending ID order, the entities of which some row recorded at `pin` (every valid-time version known at the pin, those of entities deleted before it included, retracted lives dropped) carries the label (type) and a numeric value of `key` within the bounds per the flags (a float32 widened, NaN never in range): the union over every value `v` in range of `ByLabelAndProperty(label, key, v, {ValidStart: types.UnboundedValidFrom, ValidEnd: MaxInt64, TxAt: pin})`. `fn` gets the newest such row (the caller resolves the effective timeline), false stops. `RangeCardinalityAnyVersion(...) (store.RangeAnyVersionCount{Entities, Rows}, exact, err)` counts those entities and their rows in range (a value in range on two versions: one entity, two rows). `pin <= 0` or a NaN bound visit nothing (count 0, exact). The resolved-version range doors (`ForEachByLabelPropertyRange` under temporal opts, `RangeCardinalityAt`) are unchanged (backlog 16). Served from the declared index's membership sidecar (range candidates pruned by the pin, each candidate's chain tested row by row; no label fold). Errors: `ErrIndexNotFound` without an index on the pair or while it is built, `store.ErrCapabilityNotSupported` where the sidecar range cannot serve (tiered, sharded, external stores, an Elements index); the count declines (`exact=false`) instead; a pin below a retention watermark fails closed like the equality door (`ErrRetentionExpired`; the relationship doors check the type's `PurgeExpiredRels` watermark). ### Iterators (Go 1.23+ range-over-func)

`g.Nodes().Iter(ctx, opts)` / `g.Rels().Iter(ctx, opts)` return `iter.Seq2[*types.Node, error]` / `iter.Seq2[*types.Relationship, error]` for `for n, err := range g.Nodes().Iter(ctx, opts)` — a thin wrapper over `ForEach` (no new scan machinery): same row set, same order, and the same temporal/paginated fallback to `All` that `ForEach` itself takes for the given `opts`. `g.Nodes().IterByLabel(ctx, label, opts)` is the label-scoped form (wrapping `ForEachByLabel`, so it rides the same bulk/parallel decode substrate as `ByLabel` at O(1) peak memory), and `g.Rels().OutgoingIter(ctx, nodeID, typeName)` / `IncomingIter(...)` are the adjacency counterparts, wrapping `ForEachOutgoing`/`ForEachIncoming`. Differences from `ForEach`: `ctx` is checked once per row (non-blocking) — on cancellation the iterator yields `(nil, ctx.Err())` exactly once and stops; an internal scan error yields `(nil, err)` exactly once and stops; breaking out of the range loop stops the underlying scan immediately (no further rows are fetched). Row ownership mirrors `ForEach` exactly and is **not uniform across `opts`**: a plain current-state, unpaginated scan (`ForEach`'s fast path) hands back an independent, already-mutable copy per row, while a temporal filter or `Limit`/`After` pagination (the fallback to `All`) hands back shared FROZEN rows on a trusted backend — call `DeepCopy` before mutating in that case (`OutgoingIter`/`IncomingIter` always yield the frozen-row contract, matching `ForEachOutgoing`/`ForEachIncoming`). A nil/zero-value API yields a single `(nil, ErrNilGraph)`.

### Batch operations

`g.Batch().New()` returns a `(*BatchBuilder, error)` (`ErrNilGraph` / `ErrGraphClosed`) that queues operations with eager validation; `g.Batch().Run(fn)` / `RunContext(ctx, fn)` are the closure-style equivalents (build, execute, return the `*BatchResult`). Queue methods: `AddNode(labels, props)`, `AddNodes(labels, props, count) error` (write-only bulk create, no skeletons returned), `AddRelationship(typeName, start, end, props)`, `UpdateNode(id, updates)`, `UpdateRelationship(id, updates)`, `DeleteNode(id)`, `DeleteRelationship(id)`, and the caller-instant doors `UpdateNodeWithTx(id, updates, txFrom)`, `UpdateRelationshipWithTx(id, updates, txFrom)`, `DeleteNodeWithTx(id, txTo)`, `DeleteRelationshipWithTx(id, txTo)` (semantics under Entity management; the ingest `Session` has the same four), the retractions `RetractNode(id)`, `RetractRelationship(id)`, `RetractNodeWithTx(id, txTo)`, `RetractRelationshipWithTx(id, txTo)` (the `*WithTx` pair follows the caller-instant rules below; the ingest `Session` has the same four), and the valid-interval corrections `SetNodeVersionInterval(id, validFrom, validTo, props)` / `SetRelVersionInterval(...)` (see Temporal queries). The instant and the gate are checked at queue time (an empty update map refuses there with `ErrTxOrder`); the ordering, close and no-op rules run at `Execute` in one pre-flight over the whole unit before any write, so one refused caller-instant op refuses the whole batch (`ErrBatchFailed` ⊃ `BatchError` ⊃ `ErrTxOrder`, nothing written). A caller-instant op must be the only op of the unit on its entity — creates, plain and caller-instant updates and deletes, and the relationships a node delete in the unit cascades all count — otherwise `ErrTxOrder`: `Execute` applies creates, then updates, then deletes, and a plain op stamps the clock above any `t`, so successive writes on one entity go in successive units. Batch update queues share standalone update-map validation, including provenance/authorization shadow-key extraction, and snapshot the caller's update map so later caller mutations do not affect `Execute`. Empty queued updates check entity existence at execute time, but successful empty updates do not increment `Updated` or publish update events. Successful batch creates increment `g.Stats().Get().NodesAdded`/`RelsAdded` in the same units as `BatchResult.Created`; `BatchResult.Deleted` counts removed rows, so a queued cascade node delete includes the node plus any cascaded relationships. New relationship-type tokens are allocated during `Execute` after endpoint and temporal constraint checks pass; the relationship pointer returned from `AddRelationship` is updated in place before persistence and restored to queue-time `TxFrom`, endpoint hashes, and type token if the create fails. Call `Execute()` to persist all queued operations in order (creates → updates → deletes). Mutation events are buffered during replay and dispatched after graph and builder locks are released with one `Publisher.PublishBatch` call, preserving async priority ordering across the full batch. Queue methods are serialized internally. `Execute` is one-shot: once replay begins, later queue calls or repeat `Execute` calls return `ErrBatchDone`.

`Execute()` is **per-operation reporting, not all-or-nothing**: it returns `*BatchResult{Created, Updated, Deleted, Failed, Errors []BatchError, Duration time.Duration, CommittedLSN uint64}` (`CommittedLSN` is the MAX change-log LSN this commit assigned — a read-your-writes write bookmark; `0` when the batch emitted no change-log records). If any queued operation fails, `Execute` returns that result plus an error wrapping `ErrBatchFailed`; `result.Errors` carries per-operation detail. The endpoint-lock window for relationship creation is panic-safe via a defer-backed UnlockTwo (R2-F3). Under `Config.DurableCommit`, `Execute` returns only after the group is flushed and fsynced (`ErrCommitNotDurable` when that fails; see Transactions).

### Ingest pipeline (`g.Ingest`)

The ingest pipeline (ADR-0006 stage 1, Lanes:1) is a **prepare-parallel / apply-sequential** write door for insert-dominated throughput, sitting beside the interactive `g.Tx()` door on the same core. `g.Ingest().NewSession(IngestOptions)` returns a `*Session`; its prepare methods (`AddNode(labels, props)`, `AddNodes(labels, props, count)` (write-only bulk create, skips the per-node skeleton copy), `AddRelationship(typeName, start, end, props)`, `UpdateNode(id, updates)`, `UpdateRelationship(id, updates)`, `DeleteNode(id)`, `DeleteRelationship(id)`, and the append-only valid-interval corrections `SetNodeVersionInterval(id, validFrom, validTo, props)` / `SetRelVersionInterval(id, validFrom, validTo, props)` — the queue twins of `Temporal().Set*VersionInterval`: reads pinned before the apply keep the old interval, `Get` keeps the head row, an unknown id fails its own group, the retractions `RetractNode` / `RetractRelationship`, and the caller-instant `UpdateNodeWithTx` / `UpdateRelationshipWithTx` / `DeleteNodeWithTx` / `DeleteRelationshipWithTx` / `RetractNodeWithTx` / `RetractRelationshipWithTx` with the batch rules — whole-group pre-flight, one op per entity per group; a strong-mode group carrying one is applied in a commit unit of its own, never coalesced, so its refusal fails that group only) validate, build property slices, precompute content hashes, and mint snowflake IDs **on the caller thread** — fully parallel across sessions. `Submit()` hands the accumulated prepared intents to a **single applier goroutine** (started lazily on the first session, stopped at `Close`) that drains intents in **commit groups** and applies each group through the tested batch machinery: one `c.txMu` + `c.mu.Lock` acquisition (Lanes:1 strong mode, group-atomic against readers), one `TxFrom` stamp from the shared monotonic clock, one co-committed change-log LSN run, one buffered `PublishBatch`, one `flush()` per group. The applier reuses the replica-apply-shaped store doors rather than a second write path.

`IngestOptions`: `Sync bool` — the freshness contract. When `true`, `Submit` blocks until the group is applied and visible (**ack ⇒ any subsequent read on any goroutine observes the write**) and returns that group's own apply error if it was rejected; when `false`, `Submit` returns immediately with a `SubmitToken{Lane, Seq}` watermark, and a reader achieves read-your-writes via `g.Ingest().WaitApplied(token)` or by comparing `g.Ingest().AppliedSeq()` against `token.Seq`. **`WaitApplied` is the async failure truth channel**: `AppliedSeq() ≥ token.Seq` means the group was *processed* (the watermark advances even for a rejected intent so it never wedges later waiters), **not** necessarily committed — `WaitApplied(token)` returns nil on success or the intent's real apply error (e.g. `ErrUniqueViolation`) if it was rejected, pruned on read. `DeclareLabels` / `DeclareRelTypes` pre-register an ingestion job's vocabulary up front so prepare is lookup-only (undeclared names still work via the probe-token fallback). `QueueBound` bounds the prepare→apply queue; at the bound `Submit` **blocks the producer** (synchronous stall — entity writes are never dropped). A `Submit` racing `Graph.Close` is either applied or rejected cleanly with `ErrIngestClosed` — never accepted-then-dropped, never hung. `Session.Pending() int` counts prepared, unsubmitted intents. `Session.Close()` submits any accumulated intents and releases the session (the shared applier lives with the graph, stopped by `Graph.Close`).

Fresh-snowflake-ID inserts are conflict-free by construction, so the pipeline needs no OCC/2PL; updates are chain-ordered and lane-local, and unique-constrained creates are arbitrated by the same value-stripe / batch pre-check the standalone doors use. The pipeline is intended for the throughput door; keep `g.Tx()` for read-modify-write logic (MERGE, velocity read-then-write). Pipeline-written graphs verify (`Verify*Chain`), carry correct bitemporal metadata (as-of reads reflect the belief state at a pin), mint gapless LSNs, and replicate byte-exact to a read-only replica.

**Concurrent mode (`IngestOptions.Concurrent: true` — the Lanes:N write door, ADR-0006 §14).** The session SELF-APPLIES each submitted group on the caller thread under the standalone concurrency discipline (shared read lock + entity locks + value stripes), so N sessions apply genuinely in parallel — the scaling door for fast storage / in-memory workloads (measured ~1.7x the single-threaded standalone rate at 8 sessions on badger-in-memory, where the strong-mode single applier is the ceiling). Semantics differences: `Submit` is always synchronous and returns the group's apply outcome directly (`Sync` implied; the returned token has a nonzero `Lane` and `WaitApplied` on it returns nil — it is already resolved); a group is NOT atomic against concurrent readers (per-entity atomicity only); `QueueBound` is ignored; the caller-instant pre-flight runs under the shared lock, so a racing standalone write can still make the write itself refuse that one op afterwards (`ErrTxOrder`, nothing stamped below its predecessor). Unseen labels/rel-types are declared-on-prepare (registered and persisted during `AddNode`/`AddRelationship`). Change-log feeds stay gapless and replicas converge byte-exact from a concurrent-mode primary. On fsync-bound durable ingest (`SyncWrites`), prefer the default strong mode — its single applier amortizes the group flush.

**Change-log-enabled `g.Tx()` mutations defeat Lanes:N throughput for their duration (BACKLOG 11f, documented/intentional).** When a per-tx change-log scope is active, `GraphTx`'s mutation lock (`lockActiveCoreWrite`) takes `c.mu.Lock()` — the FULL exclusive graph lock — instead of its normal `RLock()`, so that no concurrent write's change-log record can be misrouted into the tx's buffer (see AGENTS.md's Concurrency section, `c.txMu`). This lock is acquired and released PER MUTATION CALL, not once for the tx's lifetime, so it does not deadlock — but for every mutation the tx makes, it fully excludes every concurrent standalone writer AND every concurrent-mode (Lanes:N) ingest session for that call's duration, completely defeating ADR-0007's per-shard `RLockShard` striping win while it holds it. A change-log-enabled interactive tx doing many mutations concurrently with Lanes:N ingest is therefore a real throughput cliff, not a corner case — size interactive-tx batch counts accordingly, or route bulk writes through `g.Ingest()` instead of `g.Tx()` when change-log is enabled and Lanes:N throughput matters.

### Temporal queries (`g.Temporal`)

- Point-in-time: `g.Temporal().NodeAt(id, t)`, `RelAt(id, t)`, `NodesAt(t)`, `RelsAt(t)`, `NodesByLabelAt(label, t)`, `RelsByTypeAt(relType, t)`, `NeighborsAt(nodeID, t)`, `NodesByLabelPropertyAt(label, key, value, t)`, `RelsByTypePropertyAt(relType, key, value, t)`, `OutgoingRelsAt(nodeID, t)` / `IncomingRelsAt(nodeID, t)` (deleted relationships and the earlier life of one re-imported with other endpoints included, through the node's ex-adjacency).
- Interval: `NodesDuring(start, end)`, `RelsDuring(start, end)`, `NodesByLabelPropertyDuring(label, key, value, start, end)`, `RelsByTypePropertyDuring(relType, key, value, start, end)`. `end == 0` is open-ended; otherwise `start < end` is required.
- Allen-predicate interval (OPT10): `NodesRelating(from, to, rels)`, `RelsRelating(from, to, rels)` — every entity having a version whose valid-interval `[vStart,vEnd)` has an Allen relation in the `types.AllenRelationSet` `rels` to the query interval `[from,to)`. History-aware and **predicate-anywhere** (a match on ANY version of the chain counts), so — unlike `NodesDuring` (overlap only) — these surface the NON-overlapping relations too (`{Before}` finds an entity whose interval ended before the window; `{Meets}` finds one that abuts it). `to == 0` is an OPEN query interval (+∞), classified exactly (not resolved to a "now+" bound). An empty `rels` set yields an empty result. `from == 0` (unset; a negative `from`, `types.UnboundedValidFrom` included, is a real start), or `from >= to` when `to` is a closed bound, returns `ErrInvalidTimeRange`. Build the set from the constants: e.g. `types.Before.Set().Add(types.Meets)`, or `types.AllRelations()` for all 13.
- Current transaction-time pin: `NowTx() (types.Instant, error)`. Returns the graph's current transaction instant — the pin for the AS-OF reads (`QueryOpts.TxAt` / `NodeAtTx` / `NodesAsOf`) or to name via `TagAsOf`, snapshotting everything committed so far: every committed entity has `TxFrom <= NowTx()` and every later mutation is stamped strictly greater. Reading it ADVANCES the commit clock by one tick (reserving the instant) via the wall-dominated `Core.now()`, so it is correct across a `Close`/reopen — a session-local high-water mark resets to 0 on reopen, and `TxAt == 0` means "no filter", which would silently include future writes. Errors on a nil/closed graph. **Reading "now" after a write:** an update without `tkg_valid_from` is valid from its own `TxFrom`, and the transaction clock runs ahead of the wall clock whenever several stamps fall in one millisecond, so `time.Now()` taken after the update can land on either side of `TxFrom`. Take the coordinate from `g.Temporal().NowTx()` (or `CommittedTx()`), never from the wall clock: a read at valid time `TxFrom-1` answers the earlier version and a read at `TxFrom` the update, on every backend and through every door (label read, point read, count). Pinned by `TestLabelReadAtTheUpdatesTxBoundary`.
- Committed-state pin: `CommittedTx() (types.Instant, error)` (since v4.43): the open transaction's `StartInstant` while a `GraphTx` is open, else a fresh `NowTx`. A read pinned there (`QueryOpts.TxPin`, or `TxAt` with a valid time) sees no uncommitted transaction write — transactions are write-through, and every write of an open transaction is stamped after its start — and is repeatable while transactions commit, roll back or start (a history rewrite below the pin excepted). A batch or ingest group in progress is waited for. Not covered: a privileged backfill (`AllowTxBackfill`) and a standalone (non-transaction) mutation in flight when the pin is taken. Transaction isolation itself is unchanged (see architecture.md "Transaction isolation — what v4 actually guarantees"); this is a pin for readers that must not see a partial transaction. ~100–230 ns.
- Bitemporal (transaction time): `NodeAsOf(id, txTime)`, `RelAsOf(id, txTime)`, `NodesAsOf(txTime)`, `RelsAsOf(txTime)`: the newest row recorded by `txTime` (highest version with `TxFrom <= txTime`); absent when that row was superseded or deleted by `txTime`, or when the row holding the current slot was hard-deleted after it and by `txTime`. The live current row answers unless a row with a higher version was recorded at or after it — the rows a bounded `Set*VersionInterval` appends while the current row keeps its slot (a correction whose resumption is bounded by a later version, or on a closed current row); the answer at a pin never changes after a later write. Returns `ErrNoVersionAsOf` if no version was committed at or before `txTime`.
- Bitemporal point/scan doors (a valid-time coordinate AND a knowledge-time pin): `NodeAtTx(id, validAt, txAt)` / `RelAtTx(...)`, `NodesAtTx(validAt, txAt)` / `RelsAtTx(...)`, `NodesDuringTx(from, to, txAt)` / `RelsDuringTx(...)` — the `*At` / `*During` families with the chain additionally restricted to versions recorded by `txAt`.
- **Batched point read** (backlog 57): `NodesAtTxByIDs(ids, validAt, txAt)` / `RelsAtTxByIDs(...)` answer many IDs in one call, for a consumer that looks up a known set of IDs at one coordinate (a join side, a shared pinned read). Result: a slice aligned to `ids` (same length and order, a repeated ID answered at each position) holding the row `NodeAtTx` / `RelAtTx` returns for that ID, nil where the per-ID door answers not-found or `ErrNoVersionValidAt`. - **Per-entity point doors with explicit presence** (round 11): `g.Temporal().NodeAtOpts(id, opts)` / `RelAtOpts(id, opts)` and the batched `NodesAtOptsByIDs(ids, opts)` / `RelsAtOptsByIDs(ids, opts)` take the point form of `store.QueryOpts`, read through its `Has*` helpers like every generic door: `ValidAt` (+`ValidAtSet`) is the valid instant (absent: now), `TxAt` (+`TxAtSet`) the transaction-time pin. - Record door vs state door. `NodeAsOf(id, pin)` / `RelAsOf` (and `QueryOpts.TxPin`) are RECORD doors: they answer the newest row recorded by the pin, whatever valid time it covers. `NodeAtTx(id, t, pin)` / `RelAtTx` and the effective timeline below are STATE doors: the entity's state at valid time `t` as recorded at the pin. After a bounded correction `[2000,3000)` the record door answers the correction row at every valid time; the state door answers it only inside `[2000,3000)`.
- Effective timeline (the state door's interval form): `g.Temporal().NodeEffectiveTimeline(id, pin) ([]temporal.NodeSegment, error)` / `RelEffectiveTimeline(id, pin) ([]temporal.RelSegment, error)`; `temporal.NodeSegment{ValidFrom, ValidTo types.Instant; Node *types.Node}` (`RelSegment` with `Rel`). Segments ascend by `ValidFrom`, never overlap, are half-open `[ValidFrom, ValidTo)` (`ValidTo == 0`: open-ended), omit gaps, and adjacent segments hold different rows (a segment names the stored record that answers it: two distinct rows with equal property content, e.g. a burst grown by `SetRelVersionInterval` with identical props, are NEVER merged into one segment; merge on content in the consumer if one interval is wanted; only pieces of the SAME row are joined); for every valid instant `t` the segment containing `t` holds the row `NodeAtTx(id, t, pin)` returns, and none contains `t` where `NodeAtTx` answers `ErrNoVersionValidAt`. `ValidFrom` is the effective start, never 0: a row without a recorded valid-from starts at its `TxFrom`, an unbounded first version at `types.UnboundedValidFrom` ("Valid-time start (Config.UntimedValidStart)"). A deleted entity's last segment ends at the delete instant; an entity created after the pin returns nil, nil. Rows are shared frozen pointers (DeepCopy to mutate). A pin at or below 0 is an ordinary pin before every recorded row (every `TxFrom` is positive): nil, nil, and the scan, window, page and by-ID forms stream nothing (round 11; it was `ErrInvalidTimeRange`); the gates below still apply. Errors: a pin above the commit clock (`PeekTx`) → `ErrTxPinTooNew`; below compacted knowledge or a retention watermark → `ErrHistoryCompacted` / `ErrRetentionExpired` (as `NodeAtTx`); unknown ID → `ErrNodeNotFound` / `ErrRelNotFound`; invalid ID → `ErrInvalidStoreMutation`; closed graph `ErrGraphClosed`; nil graph `ErrNilGraph`. One call reads the current row and the history presence bit for an entity without history; with history it reads per-version temporal skeletons (badger) and decodes only the rows that answer. At a head pin (at or above the entity's newest `TxFrom`, e.g. `CommittedTx`) on a store with `store.HistoryEpochCapability` (memory, badger, sharded, tiered) the answer is kept per entity and reused while the entity's history token and current row are unchanged, and a `SetNodeVersionInterval` / excise correction extends it: such a read costs the current row, the token and one point read per segment, independent of the number of history versions (backlog 68, sigma R10); any other pin, an entity with a delete in its chain, or a store without the capability folds the chain as before. Answers are identical either way.

- Clock: `NowTx()` (above) reserves an instant and returns it; `PeekTx()` reads the current transaction-clock value WITHOUT reserving one — the observability-only sibling for metrics/polling loops that would otherwise inflate the commit clock, and NOT a sound as-of pin (it can coincide with a concurrent write's stamp); `AdvanceClock(to)` raises the clock FLOOR to at least `to` and returns the resulting floor (never moves backward; a `to` not ahead is a no-op) — the HLC merge seam for a distributed deployment. `ErrInvalidClockAdvance` when the target lands implausibly far ahead of wall-clock (the ~10-year skew guard against a unit/scale mixup poisoning the clock permanently).
- Version-interval correction: `SetNodeVersionInterval(ctx, id, validFrom, validTo, props) (*types.Node, error)` / `SetRelVersionInterval(ctx, id, validFrom, validTo, props) (*types.Relationship, error)` — record a valid-time correction over `[validFrom, validTo)` (`validTo == 0` is open-ended): `props` is a PATCH (a nil value deletes the key) applied to the state valid at each instant of the interval as believed before the call (unnamed properties keep their then-valid values); returns the appended version covering `validFrom`. Append-only: pins before the call see the uncorrected belief. Unique constraints judge the patch like an update (see Constraints). A hard-deleted entity is refused with `ErrEntityDeleted` (which also matches `ErrNodeNotFound` / `ErrRelNotFound`; an ID that never existed returns only the not-found sentinel), through every door: `GraphTx`, `BatchBuilder` and ingest `Session` twins included. Rows a correction appends carry no retraction (`TxTo` and `DeletedAt` 0) and take versions above every stored row; the row that takes the current slot gets the highest of them. **Over a gap:** a correction whose interval is disjoint from every existing piece appends one new piece for it and leaves the earlier pieces untouched (no re-stamp, no close, no resumption row after `validTo`, the piece does not take the current slot); at every pin `[old)` still answers the old props, the gap answers nothing before the correction's `TxFrom` and the new props from it, and `History` holds both pieces, also after a reopen. - Version-interval correction at a caller instant: `SetNodeVersionIntervalWithTx(ctx, id, validFrom, validTo, props, txFrom)` / `SetRelVersionIntervalWithTx(...)` — the same correction recorded at `txFrom` (a replay whose records carry their own knowledge time, e.g. a burst growing `[vs,ve) -> [vs,ve')`): every appended row (pieces, resumption, the row taking the current slot) carries `TxFrom = UpdatedAt = txFrom`. All temporal queries are history-aware (include deleted entities via lazy ForEach iterators). `TemporalMetadata.ValidFrom == 0` means unset and the row starts at its `TxFrom` ("Valid-time start (Config.UntimedValidStart)"); only a legacy row without a `TxFrom` falls back to the ID's mint instant, which `types.NodeID.MintInstant()` / `types.RelID.MintInstant()` return as a `types.Instant` (Unix milliseconds, floored from the 48-bit microsecond time field; the same function the resolver uses, so a consumer reading a row without its derived start — an unpinned read, a column scan — applies the identical rule without decoding snowflake bits). Node and relationship IDs yield the same instant for the same time bits; the result depends only on the ID and the package-level epoch/layout shared by every graph (not on any `Config`); a zero or negative ID, which no generator mints, returns 0 (unset); it never panics and does not allocate. Explicit finite validity ranges are half-open and must satisfy `ValidFrom < ValidTo`; graph create/import/batch inputs and direct Store write boundaries reject equal or reversed finite ranges. `g.Temporal().NeighborsAt` validates the target node at the queried instant, but still traverses relationship history when that node has no current row. `g.Temporal().NodesByLabelAt` and temporal stored-property helpers reject malformed labels/types before treating a target as unregistered. Temporal stored-property queries reject reserved `tkg_` keys with `types.ErrReservedPrefix`; use `g.Resolve` for shadow metadata.

### Version chain navigation

- `g.Nodes().History(id)` / `g.Rels().History(id)` — full version chain; zero/negative IDs return `ErrInvalidStoreMutation`.
- `g.Nodes().HasHistory(id)` / `g.Rels().HasHistory(id) (bool, error)` — whether the entity has at least one history row (updated, relabelled, cascaded, closed or deleted, history still held), equal to `len(History(id)) > 0` at every moment without reading a row; false for a plain entity or an unknown ID; zero/negative IDs return `ErrInvalidStoreMutation`, a closed graph `ErrGraphClosed`, a nil graph `ErrNilGraph`. Optional `store.HistoryPresenceCapability` (memory: its history map; badger: a RAM set of the IDs with history rows and the highest history version of each (the bulk `NodesAsOf` / `RelsAsOf` use it to skip a key read), a columnar open-addressing table of 16-26 B per ID (v4.51.4's map: 24-38 B), built by one key-only scan on the first call and maintained where every history key enters the write buffer, `badger.Store.HistoryPresenceStats()` reports it; sharded: the owning slot; tiered: the shards `History` reads, cold shards answering by a per-ID key probe); a store without it is answered from `History`. Badger on disk, reopened, set built: 9-18 ns and 0 allocs for a hit or a miss at 1 M IDs with history (v4.51.4's map: 24-27 ns, same loaded machine) at 200 K and 1 M entities with history on 0.1 % or 1 % of them; the first call's build costs 0.29 s at 1 M IDs with history (v4.51.4: 0.69 s). `Clear` drops the set; the next call rebuilds it.
- `g.Nodes().LatestStamps(id)` / `g.Rels().LatestStamps(id) (txFrom, txTo types.Instant, deleted bool, err error)` — the entity's newest transaction stamps over ALL its rows (current row, every history row incl. the rows a correction appends after the current row's `TxFrom`, the delete tombstone) without reading the history: `txFrom` = largest `TxFrom`, `txTo` = largest `TxTo` or `DeletedAt` (0 when no row was ended), `deleted` = rows but no current row (a re-imported ID whose newest life is live: false); equals the fold of `Get` + `History` at every moment. An ID without any row returns `ErrNodeNotFound` / `ErrRelNotFound`, zero/negative IDs `ErrInvalidStoreMutation`, a closed graph `ErrGraphClosed`, a nil graph `ErrNilGraph`. The current-row half is the optional `store.CurrentStampsCapability` (`NodeCurrentStamps` / `RelCurrentStamps` -> `store.RowStamps`, equal to the stamps and version of the row `GetNode` / `GetRelationship` returns, same not-found and error sentinels; memory: the held row; badger: the entity cache, on a miss one key read and only the row's temporal block decoded, no cache fill; sharded: the owner slot; tiered: the shard the lend door reads; a store without it, or a wrapper that only inherits it, is answered from the current row); the history half is the optional `store.HistoryStampsCapability` (`NodeHistoryStamps` / `RelHistoryStamps`, the fold `store.FoldTxStamps` of `Get*History`; memory: a per-ID cache checked against the row count; badger: a RAM sidecar beside the presence set, built on the first call by one scan of the history values' temporal fields, 37-61 B per ID with history (v4.51.4's map: 52-85 B), `badger.Store.HistoryStampsStats()`; sharded: the owning slot; tiered: the shards `History` reads, cold shards per ID, folding `History` itself when two or more shards hold rows, since it keeps one copy per version); a store without it is folded from `History`. Badger decodes only each history row's temporal block: a row whose temporal block fails to decode reports the error, a row whose body is corrupt but whose temporal block decodes is answered while `History` fails (as for `HasHistory`). Cost: one ID in a hot loop 31-83 ns and 0 allocs on memory and badger at 0-10,000 versions (the `History` fold: 6.4 ms / 36.4 ms at 10,000); rotating IDs with every current row cached 43-55 ns (memory) and 75-100 ns (badger), 0 allocs; tiered and sharded allocate per call (8-12 allocs, 0.7-0.8 KB: routing, and sharded copies the current row), 0.45-1.6 us; a badger current row outside the entity cache adds one key read of its temporal block (bench `LatestStamps/<backend>/rotating-cache-miss`, 2,000 rels over a 64-entry cache: badger 0.9-1.3 us and 7 allocs, sharded 1.0-1.2 us and 7 allocs, tiered 2.3-2.7 us and 19 allocs; v4.50.1: 2.3-2.7 us / 24, 3.0-3.3 us / 32, 3.2-3.8 us / 36).
- `g.Nodes().VersionBefore(id, version)` / `VersionAfter(id, version)` and rel mirrors. Missing explicit IDs return `ErrNodeNotFound` / `ErrRelNotFound`. Known entities return `nil, nil` when the neighboring version does not exist. `VersionAfter(id, math.MaxUint32)` returns `nil, nil` for known entities; successor lookup never wraps to genesis version `0`.
- `g.Nodes().CloseVersion(ctx, id, t)` / `g.Rels().CloseVersion(ctx, id, t)` end the current version at `t`; an update that sets only `tkg_valid_to` does the same. See "Closing a version".
- Store history truncation (`TruncateNodeHistory`, `TruncateRelHistory`) keeps the N most recent versions. `keepVersions == 0` is the explicit clear-all request; negative retention returns `ErrInvalidStoreMutation` and leaves existing history untouched.

Direct Store history writes validate history/tombstone payload shape before
accepting snapshots: node labels, relationship type/endpoints, payload ID/key
agreement, and explicit temporal ranges must all be valid. Readable node delete
tombstones must preserve the stored node's labels.

Direct Store label/type query and count methods reject token `0` with
`ErrInvalidStoreMutation`; the zero token is the registry sentinel, not an empty
label or relationship type.

Node label add/remove, node/relationship property CAS, and node/relationship in-place updates also recompute hash-chain fields without accepting provenance shadow keys; those paths preserve existing non-hash integrity metadata instead of clearing it.

### Valid-time start (Config.UntimedValidStart)

Purpose: one place decides where a row without a valid-from begins in valid time, so every door answers alike and one instant sees one write burst in commit order.

Contract. A row's start is `storeutil.EntityValidFrom`: the explicit `tkg_valid_from`, else the row's `TxFrom`, else (a legacy row without one) its `UpdatedAt`, else the ID's mint instant. `Config.UntimedValidStart` (backlog 73) decides what a create stores for an entity's FIRST version without a valid-from (a generated ID, or an imported ID without an earlier life):

| Mode | First version without a valid-from | Later version without a valid-from |
|------|------------------------------------|-------------------------------------|
| `graph.UntimedDefault` (zero value) | an existing store keeps the mode it was written under; a new store is `UntimedUnbounded` (v4.57.0; was `UntimedFromTxFrom` up to v4.56.x) | valid from its `TxFrom` |
| `graph.UntimedFromTxFrom` | stores `ValidFrom` 0: valid from its `TxFrom` (backlog 62) | valid from its `TxFrom` |
| `graph.UntimedUnbounded` | stores `ValidFrom = types.UnboundedValidFrom` (`math.MinInt64`): valid from -inf | valid from its `TxFrom` |
| `graph.UntimedWholeAxis` (round 11, opt-in; the default for new stores in a later minor, held after v4.66.0) | the whole axis: `ValidFrom = types.UnboundedValidFrom`, `ValidTo = types.InfiniteValidTo` | no valid-time claim: the write applies to every valid-time segment (below) |

**The valid axis** (round 11, `types.ValidAxis`). How a store's rows record valid time is a property of the store, fixed when it opens from its persisted mode, never of a row: `types.LegacyValidAxis` (`UntimedFromTxFrom`, `UntimedUnbounded`; the zero value): a stored `ValidFrom` of 0 makes no claim (the row starts at its `TxFrom`), a stored `ValidTo` of 0 is the open end; `types.LiteralValidAxis` (`UntimedWholeAxis`): every stored value is the instant it names, the open end is `types.InfiniteValidTo` (`math.MaxInt64`), an untimed start `types.UnboundedValidFrom` (`math.MinInt64`). The axis's two ends are the one remaining convention, deliberate: `UnboundedValidFrom` and `InfiniteValidTo` are -inf and +inf and cannot be claimed as instants (a start of +inf or an end of -inf is `ErrInvalidTimeRange` on the literal axis). `g.Admin().ValidAxis()` answers the axis; read raw rows (`History()`, `ValidRange()`, column batches, timeline segments, the shadow resolver) through it: `axis.NodeStart(n)` / `RelStart(r)`, `axis.Open(vt)` / `End(vt)`, `axis.ValidToAtTxTime(tm, pin)`, `axis.Relate`. `types.Node.EffectiveValidFrom()` and `TemporalMetadata.EffectiveValidFrom` / `ValidToAtTxTime` are the legacy axis's rules. On the literal axis write bounds are literal too: a positional `validTo` of 0 (`SetNodeVersionInterval`, the excise doors, `CloseVersion`) is the instant 0, `types.InfiniteValidTo` the open end. Query parameters keep their documented conventions on both axes (a `NodesDuring` end of 0 is open, a `QueryOpts` bound needs its presence flag). The store learns the axis at open from its own persisted mode (tiered and sharded from the reference / anchor shard) and from the graph for a new or empty store (`store.ValidAxisCapability`; memory, badger, tiered and sharded implement it). No row carries a flag or a format version for it: rows are byte-identical to v4.62.0's for the same stored values.

**`UntimedWholeAxis`** (round 11; round 11's first cut called it `UntimedAtemporal`; René and Markus: transaction time is not valid time). Opt-in in this release and fixed at store creation (the default for new stores in a later minor, held after v4.66.0, CHANGELOG Unreleased): persisted like the other modes (key byte 3, store marker 7); an existing store with rows of another mode refuses it, a store created under it refuses every other explicit mode (`ErrUntimedModeMismatch`), `UntimedDefault` reopens it under it, `Admin().SetUntimedValidStart` neither names it (`ErrInvalidUntimedValidStart`) nor leaves it (`ErrUntimedModeMismatch`), an export carries it (header `ua`, export format version 4, which a release before it refuses) and an empty importer adopts it; it needs a store implementing `store.ValidAxisCapability` with MetaKV (`ErrCapabilityNotSupported`). Its rows are on the literal valid axis (above): the instant 0 is an ordinary start and end for every write. A write without a valid time makes no valid-time claim, by SQL:2011's rule for an UPDATE of an application-time period table without `FOR PORTION OF` (ISO/IEC 9075-2:2011): an untimed update (`Update`, `UpdateWithTx`, the `GraphTx`, `Batch()` and ingest twins) applies to EVERY valid-time segment of the entity and keeps the segment boundaries: each segment gets a new version in the new belief with the named properties changed and the others kept per segment (a segment that already holds the change gets none; an update changing nothing writes nothing); the old versions end in transaction time only (a read pinned before the update sees them at every valid time); existence does not change (no version where none was valid, no new start). A pure whole-axis entity is one whole-axis segment, so the update is one new whole-axis version, planned from the current row in O(1) (backlog 67); an entity with explicit valid-time segments costs O(segments) plus its history read (a stated cost). An untimed delete ends the entity in transaction time only: its tombstones are retractions (at pins after it the entity is valid nowhere, before it everywhere); `EndValidity` is the delete that keeps the valid past. An untimed label change (`Nodes().AddLabel` / `RemoveLabel`, the GraphTx `AddNodeLabel` / `RemoveNodeLabel`) follows the untimed update's rule: on a whole-axis node one new version over the whole axis, on a node with explicit segments (or a close) a new version per segment that does not already hold the change, boundaries kept, the old versions ended in transaction time only; the current label index follows the current row (the store's label door writes it). Its refusals are per segment: `ErrTooManyLabels` when a segment would exceed the limit, `ErrLastLabel` when a segment would be left without a label, `ErrLabelNotFound` when no segment carries the removed label; a change every segment already holds writes nothing. `CompareAndSetProperty` (node and relationship) applies to a whole-axis entity the same way (the new version holds over the whole axis); on an entity whose valid time is not one whole-axis segment it is refused with `ErrUntimedModeMismatch` before its compare (a per-segment compare has no one value to compare). The `GraphTx` doors and the caller-instant pre-flight of `Batch()` / ingest decide "changes nothing" over every segment, as the kernel does. Writes with a valid time keep their rules (a timed write splits the whole-axis segment, `FOR PORTION OF`). Rows carry their bounds as literal instants, so every valid-time door (point, scans, timelines, count timeline, hulls, envelopes, column filters) reads them through the store's axis without a per-row branch. `UpdateInPlace` writes no version and is unchanged.

Every create door applies the mode: `Nodes().Add` / `AddWithTx` / `GetOrCreateByKey` / `Import` / `AddByIDIfAbsent`, `AddNodes`, the `GraphTx` twins, `Batch()` and ingest `Session` creates (stamped at queue and re-checked at commit), the relationship mirrors, `Constraints().DryRunValidate`. Because the decision is stored in the row, every reader takes it from the row without knowing the mode: `NodeAt` / `RelAt`, `NodeAtTx` / `RelAtTx`, `NodesAt[Tx]`, `NodesDuring`, `ByLabel` / `ByType` with `ValidAt`, `CountByLabelAt`, the range reads at a pin, `NodeInterval` / `RelInterval` (`RelateNodes` / `RelateRels`), `NodeMatchesValidTime` / `RelMatchesValidTime`, the effective timelines, their scans, pages and head cache, the correction kernel, the column scans' valid-time filter, the DocValues start column, the temporal index envelopes (RAM, the `0x0B` keyspace, the open image, every tiered shard) and a replica, export or restore of the rows. `UnboundedValidFrom` is an ordinary explicit start: a caller may pass it as `tkg_valid_from` under either mode. An explicit `tkg_valid_from = 0` is "unset", the same row as omitting the key; only `g.Resolve().NodeProperty(n, "tkg_valid_from")` reports the raw stored value. A later version (`Update`, `UpdateInPlace`, a label change) starts at its `TxFrom` in both modes; a close keeps its version's start (under `UntimedUnbounded` a closed first version covers `(-inf, ValidTo)`). `Stats().LabelTimeStats` counts a start at -inf without an end as no explicit valid time, so a label of untimed identities stays `Eternal()`.

Persistence. The mode is stored with the store (MetaKV key `untimed_valid_start`, durable on tiered and sharded, kept across `Admin().Reset()`); an `UntimedUnbounded` store also raises the store format marker to 7, so v4.55.3 and earlier refuse it (persistence.md "Upgrading a store"). `New` fails with `ErrUntimedModeMismatch` when an explicitly configured mode (`UntimedFromTxFrom`, `UntimedUnbounded`) differs from the store's; `UntimedDefault` opens a store under its own mode. An empty store takes the configured mode (`UntimedDefault`: `UntimedUnbounded`). A store with rows and no key (written before this option existed: v4.54.0+ started untimed rows at `TxFrom`, older releases at the mint instant, and both are read as `TxFrom` rows since v4.54.0) is an `UntimedFromTxFrom` store. A store without stable storage follows the configuration (`UntimedDefault`: `UntimedUnbounded`); a store without MetaKV cannot persist the mode, so under `UntimedDefault` it stays `UntimedFromTxFrom` in every session (no session can tell it was new). An `IO().Import` adopting a TxFrom export into a store whose first open persisted `UntimedUnbounded` logs the switch as a `ChangeMeta` record. `Config.UntimedValidStart` out of range is `ErrInvalidUntimedValidStart`.

Asking the mode. `g.Admin().UntimedValidStart() (mode, complete, err)` (round 11) answers the mode the store's rows are written under, on every backend: `UntimedFromTxFrom`, `UntimedUnbounded` or `UntimedWholeAxis` as persisted in the store (never `UntimedDefault`, which a Config resolves at open; a reopen under `UntimedDefault` answers the persisted mode), `complete = false` while a conversion is unfinished (rows of both rules; `mode` is the target, `UntimedUnbounded`), `ErrGraphClosed` on a closed graph. A replica answers its own open-time mode until the primary's mode record arrives in the feed (a conversion, or the mode an import adopted); a `UntimedFromTxFrom` primary emits none, so open its replica with `UntimedFromTxFrom` (a replica opened under `UntimedDefault` on an empty store answers `UntimedUnbounded`). After `Admin().Reset()` during an unfinished conversion the empty store answers `UntimedFromTxFrom`, complete. A consumer whose answer depends on where an untimed entity starts (-inf or its `TxFrom`: the window doors, a valid-time read at an instant before a create) asks it by this call instead of assuming the default.

Conversion. `g.Admin().SetUntimedValidStart(ctx, graph.UntimedUnbounded)` converts an existing store once, one way (`UntimedDefault` is `ErrInvalidUntimedValidStart`: a conversion names its target): it marks the store "converting" durably, rewrites every untimed first version (current or history, node and relationship) to `UnboundedValidFrom` through the store doors that keep every index current, persists `UntimedUnbounded` and writes later creates under it (the store's format marker becomes 7 when the conversion starts); reopen with `Config.UntimedValidStart = graph.UntimedUnbounded` or `UntimedDefault`. Rows with a valid-from and later versions are untouched. The graph is locked meanwhile (one read per entity, one write per converted row). A conversion cut short (ctx cancelled, a store error) stays marked: until it finishes, `IO().Export` / `ExportSince` / `Import` / `ImportMerge` and every create of an untimed first version fail with `ErrUntimedModeMismatch` (creates with a valid-from, updates and reads go on); a reopen under `UntimedFromTxFrom` fails with `ErrUntimedModeMismatch`, a reopen under `UntimedUnbounded` or `UntimedDefault` (or a second call) finishes it. The call is idempotent on an unbounded store (it converts rows copied in verbatim since, e.g. by a restore); `UntimedFromTxFrom` is a no-op on a `TxFrom` store and `ErrUntimedModeMismatch` on an unbounded one. The rewritten rows are flushed durably on every shard before the final mode is written, so a crash leaves the store marked "converting", never claiming the mode over unconverted rows. A sharded store also stamps its Model-A incoming stubs of untimed first versions (they carry the START machine's edge, which that machine's conversion stamps).

Replication, export, import. Setting or converting to `UntimedUnbounded` emits a `ChangeMeta` change-log record (the mode key); a replica applies and persists it, and a read-only replica opens a store marked "converting" under `UntimedUnbounded` and lets the feed finish it. Once the primary converted, a replica configured `UntimedFromTxFrom` fails its next restart with `ErrUntimedModeMismatch`: switch the replica's `Config.UntimedValidStart` to `UntimedUnbounded` (or `UntimedDefault`). A primary in `UntimedFromTxFrom` emits no `ChangeMeta`, so a NEW replica store bootstrapped from the feed alone under `UntimedDefault` would take `UntimedUnbounded`: configure such a replica `UntimedFromTxFrom` explicitly (an `IO().Import` bootstrap adopts the export's mode). Upgrade every replica, reader and importer to v4.56.0 before converting a primary; an older replica stops with `unknown change tag 9`. A full export's header carries the mode (`uu`, omitted for `UntimedFromTxFrom`); `IO().Import` into an empty store adopts and persists it, into a store with rows under the other mode fails with `ErrUntimedModeMismatch` before any record is written; `IO().ImportMerge` refuses a delta of the other mode (re-bootstrap from a full export). An export without the field is a `UntimedFromTxFrom` export.

Constraints. Under `ConstraintRelWithinEndpoints` a relationship is bounded by where its endpoint's current life starts, in both modes: the start of the endpoint's first version since its last delete (a re-imported ID's earlier life does not count), not its current row's start. So after an update at `tx1` a relationship starting before `tx1` is admitted where `NodeAt` answers the endpoint, and an endpoint whose first version is unbounded admits a relationship from -inf; a relationship before that life starts is refused (`ErrRelBeforeStartNode` / `ErrRelBeforeEndNode`).

Default change (v4.57.0, announced as Deprecated in v4.56.0): the zero value is `UntimedDefault`. A NEW store (empty at its first open) under it is an `UntimedUnbounded` store; an existing store keeps the mode it was written under (its persisted key, or `UntimedFromTxFrom` for rows without a key), so a store created under v4.56.x defaults goes on starting untimed first versions at their `TxFrom`. Set `Config.UntimedValidStart = graph.UntimedFromTxFrom` to keep the old rule for new stores. The constant values moved (`UntimedDefault` 0, `UntimedFromTxFrom` 1, `UntimedUnbounded` 2); code that names the constants is unaffected, the persisted key bytes are unchanged (0 TxFrom, 1 unbounded, 2 converting). Test: `TestUntimedDefaultFlip`.

Usage.

```go
g, _ := graph.New(graph.Config{BadgerDir: dir, UntimedValidStart: graph.UntimedUnbounded})
n, _ := g.Nodes().Add(ctx, []string{"Host"}, nil) // valid at every instant until its first change
// an existing TxFrom store, once:
err := g.Admin().SetUntimedValidStart(ctx, graph.UntimedUnbounded)
```

Consequences a caller can see under `UntimedFromTxFrom`: (1) a read at wall-clock "now" right after a create can miss it, because the commit clock runs ahead of the snowflake wall clock under bursts: read at `Temporal().NowTx()` or at the write's `TxFrom`; (2) an `Update` whose `tkg_valid_from` is at or before the current version's `TxFrom` is `ErrValidFromBeforePrevious`; (3) a temporal constraint compares against an endpoint's `TxFrom`; (4) a consumer detects an untimed create by "first effective segment `ValidFrom` == the first version's `TxFrom`" (`TxStamps`), not by `MintInstant()`. Under `UntimedUnbounded`: the row's `ValidFrom` and the first effective segment's `ValidFrom` read `types.UnboundedValidFrom`; a temporal constraint sees the entity valid since -inf; a create after an update of another entity is valid before that update (the unbounded start ignores commit order). `types.NodeID.MintInstant()` / `RelID.MintInstant()` stay as the pure ID function (Unix ms of the mint time) and are only the last fallback. Cost: none on reads or writes. Tests: `TestUntimedValidStartModes`, `TestUntimedRowsStartAtTxFrom`, `TestOneBurstReadsConsistentlyAtOneInstant`, `TestZeroValidFromIsUnsetInEveryDoor`.

### Closing a version

Purpose: end the current version's valid time without losing the row.

`g.Nodes().CloseVersion(ctx, id, t)` / `g.Rels().CloseVersion(ctx, id, t)` end the current version at `t`. The open row moves to history at its own version and the current row becomes a new version that keeps the version's start (stamped as its `ValidFrom`), with `ValidTo = t` and `TxFrom` = the close instant; its `PrevHash` chains to the open row's hash, and existing provenance, signature, authorization and relationship endpoint-hash metadata are kept. It adds a history row, counts as an update (`NodesUpdated` / `RelsUpdated`) and publishes the update event. Errors: `ErrInvalidTimeRange` for `t == 0` or `t` at or before the version's start (nothing written), `ErrAlreadyClosed` if `ValidTo` is already set (counters unchanged). The check is one helper (`checkNodeClose` / `checkRelClose` + `stampClose`: version open, end after start, temporal constraints hold).

An `Update` that sets only `tkg_valid_to` (every update door: `GraphTx.UpdateNode` / `UpdateRelationship`, batch, ingest, `*WithTx`) closes the version the same way, with the same errors; this is also the close inside a transaction (`GraphTx` has no `CloseVersion`). `UpdateInPlace` refuses an end at or before the row's start. A batch or ingest unit with one refused close writes nothing. Side effect: a closed untimed version carries its start as a stored `ValidFrom`, so `ValidRange()` and `ColumnBatch.ValidFrom` of such a row read that start instead of 0. An external store without `MetaKVCapability` never runs the bitemporal migration; there a close whose explicit valid-from equals its predecessor's is read by the legacy inherited-valid-from heuristic as inherited (every in-tree store migrates). Tests: `TestUpdateValidToClosesTheVersion`, `TestTxUpdateValidToClosesLikeCloseVersion`.

### Excise (valid-time)

Purpose: say "the entity was not valid during `[a, b)`" without deleting it or rewriting history.

```go
err := g.Temporal().ExciseNodeValidity(ctx, id, a, b) // 0 < a < b
_, err = g.Temporal().NodeAt(ctx, id, a)              // ErrNoVersionValidAt
_, err = g.Temporal().NodeAt(ctx, id, b)              // the version resumes at b
```

Contract. `ExciseNodeValidity(ctx, id, a, b)` / `ExciseRelValidity` end the entity's validity over `[a, b)` and keep it outside. Reads with a valid instant in `[a, b)` answer `ErrNoVersionValidAt` (`NodeAt` / `NodeAtTx`, the label, property and `ValidAt` scan doors, the effective timelines); the interval doors (`NodesDuring`, `ValidStart` / `ValidEnd`, Allen relations) no longer see the entity inside `[a, b)`; reads outside keep their answers; pins before the call see the unsplit version. It splits whichever versions were valid there (the current one, open or closed, a historical one, or several) and is append-only: void pieces (`types.TemporalMetadata.Void`) over the parts of `[a, b)` where a version was valid, plus the resumption from `b`, all at one transaction instant under the entity lock. A later `SetNodeVersionInterval` over the hole fills it again. No existing mechanism modelled bounded absence (a retraction ends a whole life, a delete tombstone ends it at its instant, `CloseVersion` closes only the open row), so the flag is new.

Void rows. A void row never holds the current slot and never answers `NodeAsOf` / `RelAsOf` / `TxPin`. `Nodes().History()` / `Rels().History()` return the pieces marked (`Temporal().Void`): a consumer reading raw History intervals must skip them (they assert absence, not a state). The effective timelines never return them. Format: row `fv` 5 and store marker 6 (persistence.md "Format versions and markers"); a release before v4.54.0 refuses such a store and fails such a row closed in an export, feed or replica rather than reading the piece as a valid version.

Twins. `ExciseNodeValidityWithTx(ctx, id, a, b, txFrom)` / `ExciseRelValidityWithTx` record it at a caller instant with the rules of `SetNodeVersionIntervalWithTx` (`Config.AllowTxBackfill`). `GraphTx.ExciseNodeValidity[WithTx]` / `ExciseRelValidity[WithTx]` (Rollback removes the rows; a refusal leaves the transaction open) and `BatchBuilder` doors of the same names (interval checked at queue time; a refused `*WithTx` refuses the whole unit and must be the only op of its unit on the entity).

Errors, nothing written: `b == 0` (an open tail is `CloseVersion`'s), `a == 0` or `a >= b` `ErrInvalidTimeRange` (a negative `a`, `types.UnboundedValidFrom` included, is a real start since sigma round 10); no version valid in `[a, b)` (also the hole itself) `ErrNoVersionValidAt`; unknown `ErrNodeNotFound` / `ErrRelNotFound`; hard-deleted `ErrEntityDeleted`. Cost: one entity-lock write of the versions overlapping `[a, b)` plus one. Tests: `TestExciseNodeValidity` / `TestExciseRelValidity` (memory, badger, tiered, sharded with reopen), `TestVoidRow_FormatVersion5`, the bitemporal oracle harness.

### Events (`g.Events`)

- Sync bus: `bus := events.NewEventBus()` or `var bus events.EventBus` with `g.Events().SetSync(&bus) error`, `g.Events().GetSync()`. `SetSync(nil)` detaches on open graphs. Post-close `SetSync` returns `ErrGraphClosed` and leaves the installed publisher unchanged. `bus.Subscribe(handler)` returns an idempotent unsubscribe. Nil handlers and nil bus receivers are ignored with no-op behavior. Handlers run synchronously after each successful store write, outside the bus lock.
- Async bus: `bus := events.NewAsyncEventBus(AsyncEventBusConfig{Workers, QueueSize, Backpressure, OnDrop})` or `var bus events.AsyncEventBus` with default lazy-start config, `g.Events().SetAsync(&bus) error`, `g.Events().GetAsync()`. `SetAsync(nil)` detaches on open graphs. Post-close `SetAsync` returns `ErrGraphClosed` and leaves the installed publisher unchanged. Nil handlers are ignored with a no-op unsubscribe and do not start a zero-value async bus; nil bus receivers no-op for `Subscribe`, `Publish`, `PublishBatch`, and `Close`. Three backpressure strategies: `BackpressureBlock`, `BackpressureDropOldest`, `BackpressureDropLatest`; unknown strategy values normalize to `BackpressureBlock`. `OnDrop func(Event)` is the drop-observability hook: when non-nil it is invoked once per event shed under `BackpressureDropOldest` (the OLD event evicted from the queue head) or `BackpressureDropLatest` (the NEW event being rejected) — never under `BackpressureBlock`, which never drops. Nil (the default) is zero cost. The callback always runs OUTSIDE the bus locks, so it may safely re-enter the bus; ordering is guaranteed only within a single `Publish`/`PublishBatch` call, not globally across concurrent producers. `Workers` is accepted for compatibility but capped at one dispatcher so `PublishBatch` drains in Critical→High→Normal→Low→Deferred priority order, including during `Close`. `bus.Close()` marks the bus closing, closes the stop signal to unblock `BackpressureBlock` publishers waiting on full queues, waits for active publishers, drains accepted events, then stops the dispatcher. `Subscribe` after close returns a no-op unsubscribe. `bus.QueueDepth() int` / `QueueDepths()` (per priority level) are point-in-time snapshots of the buffered events; 0 for a nil or not-yet-started bus.
- Six event types: `EventNodeCreate`, `EventNodeUpdate`, `EventNodeDelete`, `EventRelCreate`, `EventRelUpdate`, `EventRelDelete`. Internal priorities: creates → `PriorityHigh`, deletes → `PriorityCritical`, updates → `PriorityNormal`. Cascade node deletes publish one `EventRelDelete` per removed relationship before the `EventNodeDelete`. Five priority levels (zero value = `PriorityNormal`).

### Hash chain verification (`g.Hash`)

- `g.Hash().VerifyNodeChain(id) (bool, error)` / `VerifyRelChain(id) (bool, error)`. Tolerates deleted entities (verifies history alone when current entity is gone).
- `Config.UntimedValidStart` (default `UntimedDefault`: the store's own mode, `UntimedUnbounded` for a new store since v4.57.0): where an entity's first version without a valid-from starts; `UntimedFromTxFrom` at its `TxFrom`, `UntimedUnbounded` at -inf. Persisted with the store, `ErrUntimedModeMismatch` on a reopen under the other explicit mode, `Admin().SetUntimedValidStart` converts once. See "Valid-time start (Config.UntimedValidStart)".
- `Config.DisableIntegrityHashes` (default `false` = hashes on): off computes and stores no integrity hash, so `Integrity().Hash`, `PrevHash`, `FromNodeHash`, `ToNodeHash` and the `tkg_hash` shadows stay empty and both Verify doors (and `g.Tier().VerifyShard`) return `ErrIntegrityDisabled`; `Config.RelSegments` with hashes off fails `New` with `ErrIntegrityDisabled`; reopening a store under the other setting fails with `ErrIntegrityModeMismatch`. Stored hashes are handed out as 64-character lowercase hex strings whatever the row holds. For development and quick tests. Contract and cost: persistence.md "Integrity hashes".

### Transactions (`g.Tx`) and the imperative tx surface

- Functional form: `g.Tx().Run(func(tx *graph.GraphTx) error { ... })` / `g.Tx().RunContext(ctx, fn)` / `g.Tx().RunWithLSN(fn) (uint64, error)` (same as `Run`, plus the commit's change-log LSN as a read-your-writes write bookmark). Panic-safe — a panic inside fn rolls the tx back via defer and propagates the panic; rollback errors are joined with the caller's error via `errors.Join`. Nil callbacks return `ErrNilTxCallback` before opening a transaction; nil contexts return `ErrNilContext`. A transaction that uses only read doors and has no previously failed registry checkpoint commits without calling the store's registry persistence APIs; `RunWithLSN` returns `0`. Any mutation-capable door preserves the final registry checkpoint, including no-op or rejected calls that reached the write seam, and a globally dirty checkpoint is retried even by an otherwise-read-only commit.
- Imperative form: `tx, err := g.Tx().Begin()`. Methods on `*GraphTx`:
  - Mutations: `AddNode`, `AddNodes(labels, props []map[string]any) ([]*types.Node, error)` (one node per element, same labels; AddNode's checks, IDs, hash chain, strictly increasing transaction times, events and rollback tracking per node, with the labels resolved once and one store batch write; all-or-nothing: a bad element or a failed write leaves no node; with a unique constraint or under a scoped write token it runs AddNode per element, an error then stops at that element with the earlier nodes kept for the rollback; ~10–16 % less per node than `AddNode` in a loop), `AddRelationship`, `AddRelationshipByID`, `AddRelationships(typeName, rels []graph.RelCreate) ([]*types.Relationship, error)` (one relationship of the type per element `{StartID, EndID, Props}`; AddRelationshipByID's checks, IDs, hashes, endpoint hashes, strictly increasing transaction times, events and rollback tracking per relationship, with the type resolved once, the endpoints locked once and one store batch write; all-or-nothing: a bad element, an endpoint without a current row or a failed write leaves no relationship; not so on tiered for cross-shard relationships and, with `tiered.Config.RelsByMint`, for relationships between two reference nodes: these are written one store write at a time and a failed write undoes the earlier ones by compensating deletes (each in the change feed), so a crash or a failed undo midway can leave them; with temporal constraints or under a scoped write token it runs AddRelationshipByID per element, an error then stops at that element with the earlier relationships kept for the rollback), `AddRelationshipByIDIfAbsent` (returns `(rel, created, err)`), `UpdateNode`, `UpdateRelationship`, `SetNodeProperty`, `DeleteNodeProperty`, `SetRelationshipProperty`, `DeleteRelationshipProperty`, `AddNodeLabel`, `RemoveNodeLabel`, `DeleteNode` (cascade), `DeleteRelationship`, `EndNodeValidity` (cascade) / `EndRelValidity` (the delete that keeps the valid past on every axis, see Entity management), `ImportNodeWithID(ctx, id, labels, props)` / `ImportRelationshipWithID(ctx, id, typeName, start, end, props)`, `GetOrCreateByKey(label, propertyKey, value, extraProps)`, `GetOrCreateByKeyOpts(label, propertyKey, value, extraProps, opts)` (lookup bounded by `opts.Depth`), `SetNodeVersionInterval` / `SetRelVersionInterval` (returning the appended row), `RetractNode` / `RetractRelationship`, and the caller-instant `UpdateNodeWithTx`, `UpdateRelationshipWithTx`, `DeleteNodeWithTx`, `DeleteRelationshipWithTx`, `RetractNodeWithTx`, `RetractRelationshipWithTx` (semantics under Entity management; the instant and the gate are checked before the tx lock, the ordering and close rules under the entity lock; a refused call writes nothing).
  - Reads: `GetNode(id)`, `GetRelationship(id)` (safe inside tx — tx holds the write lock), `GetNodesByIDs` / `GetRelsByIDs`, `NodesByLabel` / `RelsByType` / `NodesByLabelAndProperty` / `AllNodes` / `AllRels` (with `QueryOpts`), `OutgoingRels` / `IncomingRels` / `*RelsForNodes`, the temporal mirrors (`NodeAt`, `NodesAt`, `NodeAsOf`, `NodesAsOf`, `NodesDuring`, `NodesByLabelAt`, `NodesByLabelProperty{At,During}`, `NeighborsAt`, `OutgoingRelsAt` / `IncomingRelsAt`, `Snapshot` and rel twins), counts and `Stats()`, `SearchNearest` / `SearchNearestScored`, and the name/shadow helpers; the full method set is `go doc -all ./pkg/graph/internal/core` (type `GraphTx`, aliased as `graph.GraphTx`). Successful tx-scoped reads increment the same read counters as standalone reads; rollback restores the `BeginTx` counter snapshot.
  - Lifecycle: `Commit()` releases the lock and dispatches buffered events. With `Config.DurableCommit` (default false) `Commit` (and so `Run` / `RunContext` / `RunWithLSN`), `Batch.Execute` and the strong ingest applier flush and fsync the group through `store.DurableFlushCapability` before returning; a failed flush returns `ErrCommitNotDurable` (the group is committed in memory and stays pending for the next flush). Not covered: standalone mutations and concurrent-mode ingest. `New` refuses the flag with `ErrCapabilityNotSupported` on a store without stable storage (memory, `BadgerInMemory`, in-memory tiered or sharded). `Rollback()` restores deleted node rows before deleted relationships, restores pre-transaction version history, restores multi-step node label changes and label indexes to the pre-transaction label sequence, then reverts other updates and deletes created entities; node and relationship snapshots are tracked separately even when caller-supplied IDs share the same underlying snowflake value. Buffered events are discarded and the operation-counter snapshot from `BeginTx` is restored after successful rollback. A read-only rollback takes the lifecycle-only fast path: it restores counters and discards the change-log scope without registry persistence, entity/history work, or AS-OF column invalidation. Sentinel: `ErrTxDone`.
  - Inspection: `CreatedNodeIDs()`, `CreatedRelIDs()`, `CommittedLSN()` (after `Commit`; 0 without change-log records), `StartInstant()` (since v4.41: the transaction-time instant `Begin` reserved on the commit clock, as `Temporal().NowTx` does; every write of the transaction is stamped strictly after it and every stamp reserved before `Begin` strictly before it, so it is an as-of pin of the graph the transaction found and a consumer's transaction clock; fixed for the transaction's life, readable after `Commit`/`Rollback`, `0` for a nil transaction).

### Indexes (`g.Index`)

- Composite (multi-key equality): `g.Index().CreateComposite(label, keys)` / `DeleteComposite(label, keys)` (2–4 declared, order-preserving keys; a different key ORDER of the same set is a distinct definition) with the planner introspection doors `HasComposite(label, keys) (bool, error)` — ORDER-INSENSITIVE key-SET match, exactly the routing rule `g.Nodes().ByLabelAndProperties` uses, so a planner can prove the accelerated path exists before choosing that door — and `ListComposites(label) ([][]string, error)` (declared orders, caller-owned copies; unregistered labels return empty). O(definitions on the label) per call; a cached answer is revalidated with `InventoryEpoch()` (below). Tiered builds them on every shard; wrapper stores without the capability return `ErrCapabilityNotSupported`.
- Property index options (round 4 R2, opt-in per index): `g.Index().CreatePropertyWithOptions(label, propertyKey, graph.PropertyIndexOptions{RangeCounts: true})` / `CreateRelPropertyWithOptions(typeName, propertyKey, opts)`, read back with `PropertyOptions(label, propertyKey)` / `RelPropertyOptions(typeName, propertyKey) (PropertyIndexOptions, ok bool, error)`. `RangeCounts` keeps each numeric value's multiplicity and per-chunk prefix sums in the index, so `RangeCardinality` on it is two prefix sums instead of a walk; cost about 42 ns more per index add or remove of a numeric value (+34 % in `BenchmarkPropertyIndexAddRemove`) and 8 B per distinct value. Without it an index is exactly the plain index (same structure, same write cost, same `RangeCardinality` walk). Zero options are `CreateProperty`. Fixed at creation; persisted with the definition on badger (key `rc`, written only when set; an older binary skips it and loads the index plain) and on every sharded slot; memory keeps it for the process. Index DDL is not replicated, as before. Refused with `ErrCapabilityNotSupported`, nothing created: tiered (no range count there), badger with `PropertyIndexOnDisk`, wrapper stores without `store.PropertyIndexOptionsCapability`.
#### Elements index

Purpose: a list-valued property queried by membership (`PropertyIndexOptions{Elements: true}`; `ByLabelAndProperty(label, key, x, opts)` means "the list contains x"). Example: `g.Index().CreatePropertyWithOptions("Host", "tags", graph.PropertyIndexOptions{Elements: true})`, then `ByLabelAndProperty("Host", "tags", "prod", opts)`.
  - *Meaning.* The index keys each scalar element of a list value, so `ByLabelAndProperty` / `ByTypeAndProperty` on it (current, `TxPin`, `TxAt`, `ValidAt`, interval reads and the named `*At` / `*During` doors) match when the list contains the query value. A non-list value is a one-element list; duplicates count once; an empty list, nil and non-scalar elements (nested lists, maps) add nothing; each element follows the property equality (int 101 matches int64 101); `[]byte` is a blob, not a list; a list query value matches nothing. History reads take candidates from the membership sidecar per element, so an element an update removed matches at an earlier pin and not after. The index keeps no ordered view: the range, prefix and `RangeCardinality` doors decline on it as without an index (`ErrIndexNotFound`, `exact=false`).
  - *Refused with `ErrElementsIndexUnsupported`* (nothing created): `Elements` with `RangeCounts`; an Elements index on a key under a unique constraint; `CreateUnique` and `GetOrCreateByKey` on an Elements-indexed key; `ByLabelAndProperties` and `CreateComposite` over one. Refused with `ErrCapabilityNotSupported`: badger with `PropertyIndexOnDisk`, at create and at open (the shared disk keyspace keys scalars only).
  - *Backends.* Node and relationship indexes on memory, badger, sharded and tiered. Tiered builds it on every shard like any property index (below); a shard whose copy is missing or stale answers the same "contains" match by a scan.
  - *Persistence.* Badger stores it with the definition (key `el`) and in the open image. A directory that persists an Elements definition is stamped store format 5 and never lowered, so an older binary refuses it (`ErrWireFormatVersionUnsupported`) instead of loading the index plain: persistence.md "Format versions and markers". Write cost of a row with 5 supports: memory 33 vs 22 allocs against a plain index; badger 68 vs 57 (`BenchmarkPropertyIndexElementsWrite`).
- Property: `g.Index().CreateProperty(label, propertyKey)` / `DeleteProperty(label, propertyKey)` / `HasProperty(label, propertyKey) (bool, error)` (the planner-introspection sibling of `HasComposite`). Create validates the label/property key, rejects reserved `tkg_` keys, creates the label token when needed, and installs an index that also covers future matching nodes. Delete validates the same label/key inputs and returns `ErrIndexNotFound` if the label or index is absent. `g.Nodes().ByLabelAndProperty(label, key, value, opts)` rejects reserved `tkg_` keys, uses the index when present, and falls back to label scan + property filter otherwise (R2-F4).
- Relationship property (K3b): `g.Index().CreateRelProperty(typeName, propertyKey)` / `DeleteRelProperty(typeName, propertyKey)` / `HasRelProperty(typeName, propertyKey) (bool, error)` — the relationship mirror of the node property index, keyed by rel-type token. Create validates the type/property key, rejects reserved `tkg_` keys, creates the rel-type token when needed, and installs an index covering future matching relationships (backed by `store.RelPropertyIndexCapability`). `g.Rels().ByTypeAndProperty(typeName, key, value, opts)` uses the index when present and falls back to a type-scan + property filter otherwise, so the query works on every backend; temporal opts fold current + history versions. `g.Rels().ForEachByTypePropertyRange(typeName, propKey, min, max, inclMin, inclMax, opts, fn)` streams numeric-range candidates from the index's ordered view (over-selecting by design — fn re-checks the predicate with exact comparison), returning `ErrIndexNotFound` when no usable index exists so callers fall back to a scan. A temporal `QueryOpts` is served on every backend by a fold over `ByType(typeName, opts)` (the value of each relationship's version under opts, ID order, no index needed), as `g.Nodes().ForEachByLabelPropertyRange` does over `ByLabel` (since v4.44; before, both filtered current rows and ignored `TxAt`/`TxPin`). Under `ValidStart`+`ValidEnd` both range doors (and the ordered siblings) test the range on the one version `ByType` / `ByLabel` resolves (the most recent overlapping one), while `ByTypeAndProperty` / `ByLabelAndProperty` match a value held anywhere in the interval (backlog item 16). RAM-only v1 on memory and badger: badger persists only the DEFINITIONS and rebuilds the value maps from current relationships at open (there is no on-disk value keyspace; a 0x0C disk mode mirroring the node 0x0A `PropertyIndexOnDisk` mode is a documented follow-up). Tiered (since v4.58.0, sigma row 59): node property indexes on every label and relationship property indexes are built per shard on the reference shard, the archive and every event shard (closed cold shards are opened for the DDL; a hot shard a later rotation opens, the archive and a lazily opened cold shard copy the definitions, and store open repairs every open shard). The reference shard anchors the definition with its options: create reaches it last, drop leaves it last, a failed shard step undoes the others. A lookup folds the shards; a shard whose copy is missing or has other options answers the anchor's match by a scan. The history doors (`TxPin`, `TxAt`, `ValidAt`, intervals, the named `*At` / `*During` doors) take their candidates from the union of every shard's membership sidecar, so a keyed pinned read loads no type or label scan; while any shard lacks the anchor's index (DDL in flight, a stale cold shard) they fall back to the history fold with the same answers. Options: `Elements` yes, `RangeCounts` refused (`ErrCapabilityNotSupported`). Cost: each shard indexes its own rows (badger's per-index RAM, see query-planners.md), a lookup touches every shard in the depth. Capability query: `store.CapabilitiesOf(s).IndexAcceleration.RelPropertyIndex` (and `.PropertyIndex`) equals "a plain create succeeds" on every in-tree backend (`TestCapabilitiesOf_MatchesCreate`). `ErrRelPropertyIndexUnsupported` stays the sentinel such a backend returns; no in-tree backend returns it.
- Temporal interval: `g.Index().CreateTemporal(label)` / `DeleteTemporal(label)` / `HasTemporal(label) (bool, error)`. Listing: `g.Index().ListTemporal()` / `ListRelTemporal()` return the labels / relationship types carrying a temporal interval index, sorted by name (a high-frequency index is not listed), and `HasRelTemporal(typeName)` mirrors `HasTemporal`; store contract `store.TemporalIndexListingCapability`. On badger both kinds survive a reopen (the definitions are persisted, the data rebuilt on open). Create validates the label and creates the label token when needed. Delete validates the label and returns `ErrTemporalIndexNotFound` if the label or index is absent. Accelerates `g.Nodes().ByLabel(label, opts)` when a temporal filter is set. `g.Index().CreateRelTemporal(typeName)` / `DeleteRelTemporal(typeName)` are the relationship mirrors, keyed by rel-type token.
- High-frequency temporal: `g.Index().CreateHighFrequency(label, bucketSize)` / `DeleteHighFrequency(label)`. Create validates the label, requires `bucketSize` to be a positive whole millisecond, creates the label token when needed, and returns `ErrInvalidTemporalIndexConfig` otherwise. Delete validates the label and returns `ErrTemporalIndexNotFound` if the label or index is absent. Time-bucketed alternative for high-write-rate event labels. Only one temporal index type per label at a time. MemoryStore and BadgerStore backfill matching current nodes when the index is created and maintain buckets on later node writes. Badger persists HFI definitions and rebuilds buckets on open; creation fails closed on corrupt existing node rows. In `tiered.Store`, persisted tracked HFI definitions are restored on restart, applied to rotated hot shards and lazily opened archives, and later-shard backfill or metadata persistence failures roll back earlier shard-local creates.
- Vector: `g.Index().CreateVector(label, propertyKey, dims, metric)` / `DeleteVector(label, propertyKey)`. Create validates the label/property key, rejects reserved `tkg_` keys, creates the label token when needed, and installs an index that also covers future matching nodes. Delete validates the same label/key inputs and returns `ErrVectorIndexNotFound` if the label or index is absent. `dims` must be greater than zero and `metric` must be `DistanceCosine` or `DistanceEuclidean`; invalid config returns `ErrInvalidVectorIndexConfig`. `CreateVector` returns `ErrDimensionMismatch` if an existing matching vector property has a length different from `dims`; creation removes only its own placeholder index on that failure. Once the index exists, node writes touching a matching vector property also return `ErrDimensionMismatch` before changing store state when the value length differs from `dims`. `g.Index().SearchNearest(label, propertyKey, query []float32, k int, opts)` validates the label/property key, rejects reserved `tkg_` keys, reports unknown labels before the `k <= 0` empty-result shortcut, returns `ErrVectorIndexNotFound` for absent labels or indexes on positive-k searches, and otherwise returns the top-k nearest nodes. The in-memory heap capacity is capped by the number of indexed entries, so an oversized `k` returns available entries without allocating proportional to `k`. Under temporal filters, the graph pre-filters when the backend implements `FilteredVectorSearchCapability`; otherwise iterative over-fetch escalates k until k eligible results are accumulated or the backend is exhausted (R2-F5), with the graph-level resolved-candidate buffer capped by the same over-fetch ceiling. Direct Store-level `SearchNearestNodes` applies temporal `QueryOpts` before heap selection and applies `After`/`Limit` over distance-ranked order; graph-level search strips cursor opts from the backend call and paginates the final current/history-resolved slice once. On `tiered.Store`, `DepthHot`/`DepthWarm` are applied before vector heap selection: live reference nodes remain eligible, `refArchive` is excluded, and event-shard candidates must belong to an included tier. `g.Index().VectorIndexInfo(label, propertyKey) (store.VectorIndexInfo, bool, error)` returns the declared configuration (dims, metric, engine, HNSW tuning) of an existing index, or `(zero, false, nil)` when there is none — so a planner can validate a query vector's dimensionality and pick the engine BEFORE issuing `SearchNearest` instead of discovering the mismatch as a runtime error. Errors: `ErrEmptyName`, `ErrKeyTooLong`, `types.ErrReservedPrefix`, `ErrInvalidVectorIndexConfig`, `ErrVectorIndexExists`, `ErrVectorIndexNotFound`, `ErrDimensionMismatch`; vector sentinels are canonical in `pkg/graph/store` and aliased by `pkg/graph` and `pkg/graph/index`.
- **Engine choice**: every vector index now runs an approximate pure-Go HNSW graph by default (M=16, EfConstruction=200, EfSearch=64) instead of brute-force linear scan; see CLAUDE.md "Vector Indexes" for the recall target, determinism, and tombstone/rebuild contract. `g.Index().CreateVectorWithOptions(label, propertyKey, dims, metric, storepkg.VectorIndexOptions{...})` is `CreateVector` plus the engine/tuning choice: `UseBruteForce bool` (the exact-recall escape hatch — reverts that one index to the pre-existing linear scan) and `M`/`EfConstruction`/`EfSearch` (zero = documented default). `CreateVector` is unchanged in signature and is now equivalent to `CreateVectorWithOptions(..., storepkg.VectorIndexOptions{})` (all-default HNSW). A backend implementing the new optional `store.VectorIndexOptionsCapability` (memory/badger/tiered all do) applies the options at creation; a backend that only implements the mandatory `VectorIndexCapability` silently falls back to plain `CreateVectorIndex` (opts unavailable) — the same "optional acceleration, correctness-preserving fallback" contract as `FilteredVectorSearchCapability`. `SearchNearest`'s existing signature and behavior (temporal pre-filter/over-fetch, pagination, `tiered.Store` depth gating) are unchanged regardless of engine — the engine choice only affects which internal search the store's `SearchNearestNodes`/`SearchNearestFiltered` doors delegate to.
- **Scored search + temporal-pin contract**: `g.Index().SearchNearestScored(label, propertyKey, query, k, opts) ([]index.VectorHit, error)` is `SearchNearest` with distances — the SAME nodes in the SAME order (identical validation, temporal eligibility, pagination), each paired as `index.VectorHit{Node, Distance}` with its distance from the query under the index's declared metric (1 − cosine similarity for `DistanceCosine`, Euclidean/L2 otherwise) — built for rerankers (e.g. GraphRAG) that need the score, not just the rank ordinal. `Distance` is computed against the node's CURRENT vector (the value the index ranked by) even when a temporal filter makes the returned `Node` a historical version — the documented latest-vector ranking caveat, now observable. Requires `store.VectorIndexIntrospectionCapability` for the metric (all in-tree backends); a tx-side mirror exists (`tx.SearchNearestScored`). Vector inputs accept `[]float32`, `[]float64` (elements narrowed to float32), and `[]any` of float32/float64 — a `[]float64` embedding is indexed, not silently skipped. `QueryOpts.TxPin` is REJECTED by both `SearchNearest` and `SearchNearestScored` with `ErrVectorSearchTxPinUnsupported`: the index holds only latest vectors and drops deleted nodes, so a belief-state (`AS OF SYSTEM TIME`) ranking would silently omit nodes deleted after the pin and rank by post-pin vectors — the door refuses loudly instead (TxPin combined with another temporal opt still surfaces the more specific `ErrConflictingTemporalOpts`).
- All graph-level index create variants restore a newly allocated label token if the backend create call fails; successful creates still materialize future-label indexes. Registry rollback guards use deferred cleanup so backend panics do not strand later registry writes. Multi-label node allocation restores partial suffixes if capacity is hit after an earlier label was created.
- Inventory epoch: `g.Index().InventoryEpoch() uint64` — advances after every index create or drop of every kind that reached the store (a unique constraint's implicit property index included; a failed one too, since its partial state may have been visible) and after `Admin().Reset` / a replica's applied clear; not for a refusal that changed nothing (`ErrIndexExists`, `ErrIndexNotFound` and their temporal/vector twins, `ErrRelPropertyIndexUnsupported`, `ErrCapabilityNotSupported`), validation failures, data writes or reads. One atomic load, identical on every backend. Read it BEFORE reading the inventory; while a later read returns the same value the cached view is current. Per Graph (0 at `New`, not persisted). IndexProvider registrations are not index inventory and do not move it.
- IndexProvider plugin: `g.Index().RegisterProvider(p)` / `UnregisterProvider(name)` / `Providers() []string`. Nil and typed nil providers are rejected before `Name()` is called; empty and whitespace-only provider names are rejected before registration or unregistration lookup. `Providers()` returns an empty list once graph close is visible, including callers that waited behind the lifecycle lock. Auto-creates a sync `events.EventBus` if none is attached; existing sync or async buses are both supported. If a provider implements `index.Initializable`, unregister and graph close wait for its in-flight `Init` callback before calling provider `Close()`. `OnEvent` errors are logged with provider/event context and do not abort already-committed mutations. Sentinels: `ErrIndexProviderExists`, `ErrIndexProviderNotFound`, `ErrIndexProviderEmptyName`.

### Constraints (`g.Constraints`)

- `g.Constraints().Add(c) error`, `Set(cs) error`, `Get() temporal.ConstraintSet` (`temporal.NewConstraintSet(cs...)`, `Add`, `Items`, `Len`, `ForEach`, `Validate`). `g.Constraints().DryRunValidate(ctx, constraints.DryRunFacts{Nodes, Rels}) ([]constraints.DryRunViolation, error)` checks a proposed fact set against the unique and temporal constraints without writing, minting or claiming (`DryRunViolation{Ref, Kind, Err}`; empty = accepted). `TemporalConstraint{Kind: ConstraintRelWithinEndpoints}` enforces that a relationship's validity is contained within both endpoint nodes' validity. Checked during relationship creation and import. Unknown constraint kinds, including the zero-value `TemporalConstraint{}`, are rejected by `Add`/`Set` with wrapped `ErrTemporalConstraint` and `ErrInvalidTemporalConstraint` before the configured set changes. Post-close `Add`/`Set` return `ErrGraphClosed`. `temporal.ConstraintSet.ForEach(nil)` returns `ErrInvalidTemporalConstraint` consistently. Other enforcement errors wrap `ErrTemporalConstraint` (sub-sentinels: `ErrRelBeforeStartNode`, `ErrRelAfterEndNode`, `ErrRelExceedsStartNodeValidity`, etc.).

#### Unique property constraints (ADR-0002)

- `g.Constraints().CreateUnique(ctx, label, propertyKey) error`, `CreateUniqueForever(ctx, label, propertyKey) error`, `DropUnique(ctx, label, propertyKey) error`, `ReleaseOwnership(ctx, label, propertyKey, value) error`, `UniqueConstraints() []constraints.UniqueConstraint`. A unique constraint forbids two CURRENT nodes carrying the same value for the constrained `(label, propertyKey)` (`UniqueCurrent`, the default scope). `CreateUniqueForever` installs a `UniqueForever` value-ownership constraint: the first entity to hold a value owns it permanently — only that entity (any later version) may ever hold it, and every other node is barred forever, across supersession, hard delete, and reopen (`UniqueValidOverlap` remains reserved and returns a not-yet-supported error). For `UniqueCurrent`, history may hold duplicates and a value freed by supersession or delete is immediately reusable; for `UniqueForever`, a released value is reusable only via `ReleaseOwnership`.
- `CreateUnique`/`CreateUniqueForever` validate existing data first (auto-ensuring a property index on `(label, propertyKey)`): if two current nodes already share a value the constraint is NOT installed and `ErrUniqueViolationExisting` is returned (up to five offender IDs). Float-typed keys/values are rejected with `ErrUniqueUnsupportedType` (integers, string, bool, temporal supported). Values compare under the property equality: integers of every width are one value, so a new `int64(3)` beside a stored `int(3)`, or a change into it, is `ErrUniqueViolation`. Width twins a constraint admitted before v4.57.1 stay readable (lesson 58: the write doors are strict, the load doors lenient): an import accepts them, an update that leaves the constrained value alone passes, and a `UniqueForever` value recorded under two widths for two owners is owned by the smaller owner ID (the other's claim is refused). The ownership registry persists each claim under the stored value's own width key, as before (no format change). A duplicate constraint returns `ErrUniqueConstraintExists`; `DropUnique` of an absent one returns `ErrUniqueConstraintNotFound`. `ReleaseOwnership` frees an owned `UniqueForever` value so a different entity may reclaim it (idempotent; `ErrUniqueConstraintNotFound` if no forever constraint on the pair).
- Persisted in MetaKV (durable across reopen, reaped by `Admin().Reset`, declines without MetaKV via `ErrCapabilityNotSupported`, rejected on a read-only replica; the `UniqueForever` ownership registry is a separate self-hashed MetaKV blob). **Enforcement covers the standalone node doors, batch, and tx** — `Add` / `AddWithTx` / `AddByIDIfAbsent` / `Update` / `UpdateInPlace` / `CompareAndSetProperty` / `AddLabel` (the label-add door binds a constraint without touching the property), `BatchBuilder.AddNode`/`UpdateNode` (a same-value create inside one batch/tx fails at op time; the batch pre-check also consults the `UniqueForever` ownership registry, so a batch create claiming a value owned forever by another entity is barred even with no current holder, and a fresh batch create claims ownership), `GraphTx.AddNode`/`UpdateNode`, and `SetNodeVersionInterval` on every door (`Temporal()`, `GraphTx`, `BatchBuilder`, ingest `Session`): its props patch is judged like an update — an open-ended call (`validTo == 0`) replaces the current row and is checked for both scopes (moving off a value frees it under `UniqueCurrent`), a bounded call leaves the current row's value and is checked against `UniqueForever` only (a past slice may repeat another node's value under `UniqueCurrent`, as history may); a refused patch appends nothing, and in a batch or session group it fails its own op while the other ops commit. A violating write returns `ErrUniqueViolation` (wrapped with the label, key, and winning entity ID). `g.IO().Import` validates the replayed current state and rolls back with `ErrUniqueViolation` on a duplicate (default-strict; `ImportOptions.SkipUniqueValidation` opts a trusted restore out). Replica apply reproduces rows verbatim and does NOT enforce. A `UniqueForever` claim made inside a rolled-back tx stays barred (`ReleaseOwnership` is the remedy). Since v4.49 every claiming door (also `Import`, `AddByIDIfAbsent`, `GetOrCreateByKey`, `UpdateWithTx`, the `GraphTx` / `BatchBuilder` twins incl. `ImportNodeWithID`, `UpdateNodeWithTx`, `AddNodes`, and the ingest `Session`) withdraws the claims its call made when the call fails (a failed store write, a failed second claim); a value owned before the call is never withdrawn. A crash between the claim's MetaKV write and the row write still leaves the claim.
- `g.Nodes().GetOrCreateByKey(ctx, label, propertyKey, value, extraProps) (*types.Node, bool, error)` atomically returns the current node holding `value` for `(label, propertyKey)` or creates one, under a single value lock so a storm of concurrent callers produces exactly one create (the bool reports whether THIS call created it). Works with or without an active constraint on the pair; `value` must be an indexable non-float scalar (else `ErrUniqueUnsupportedType`); `extraProps` seed a freshly created node (the keyed property wins) and are ignored on a hit; the returned node is a mutable copy (Get semantics). `g.Nodes().GetOrCreateByKeyOpts(ctx, label, propertyKey, value, extraProps, opts)` (and `GraphTx.GetOrCreateByKeyOpts`) bounds the lookup by `opts.Depth`: on tiered, `DepthWarm` reads the reference shard, its archive and the hot and warm event shards, so an event label's key that lives only on a cold shard does not open it and a new copy is minted on the hot shard (dedupe within the window; a `DepthAll` `ByLabelAndProperty` then returns every per-shard copy). The zero `QueryOpts` (`DepthAll`) is `GetOrCreateByKey`; any other `QueryOpts` field is refused with `ErrConflictingTemporalOpts`, an undefined depth with `ErrInvalidShardDepth`, before anything is written. A unique constraint on an event label stays refused.

### IO (`g.IO`)

- `g.IO().Export(w io.Writer) error` — length-prefixed msgpack record stream with 1-byte type tags. Unknown tags are rejected on import with `ErrCorruptExport`. Holds the graph write lock while streaming, so standalone mutations, tx/batch, and reset cannot interleave with Export's reads. Nil and typed nil writers return `ErrNilWriter`.
- `tx.Export(w io.Writer) error` — transaction-scoped export for code already running under `g.Tx`. Same wire format as `g.IO().Export`; nil and typed nil writers return `ErrNilWriter`.
- `g.IO().Import(r io.Reader, opts io.ImportOptions) error` — `ImportOptions{StagingDir, MaxStagedBytes, SkipUniqueValidation}`. Pass `ImportOptions{}` for the previous defaults (platform temp dir, no size cap). Nil and typed nil readers return `ErrNilReader` before staging-file creation. `MaxStagedBytes == 0` means unlimited; negative caps return `ErrImportSizeLimit` before staging-file creation. Phase-1 streaming memory is `O(maxExportRecordSize)` and the staging file is sized to match the export, then removed via defer at exit. Phase 2 tracks rollback snapshots and stream-identity sets for touched rows, so replay memory scales with imported entity IDs and history records. Phase-1 errors (read, staging-disk write, MaxStagedBytes exceeded) leave graph state unchanged. Phase-2 replay errors restore touched current rows, history rows, and registries to their pre-import state unless the underlying store also fails during rollback. Wire validation rejects missing header/registry records, unknown tags, header count mismatches, duplicate singleton/current/history-version records inside one stream, malformed MsgPack bodies, malformed entity IDs, versions, label/type tokens, property-slice invariants, and base-entity IDs with `ErrCorruptExport` before constructing entities. Sentinels: `ErrNilReader`, `ErrNilWriter`, `ErrIncompatibleExport`, `ErrIncompatibleRegistry`, `ErrImportSizeLimit`, `ErrCorruptExport`. Per-record allocations capped at 128 MiB.

**Delta backups (node-level incrementals).** Built on the change-log; require a change-log store (`graph.Config.ChangeLog` on badger, or an injected `memory.WithChangeLog()`; the tiered backend declines). The cursor is the change-log LSN, not valid/transaction time — a temporal diff would silently drop backdated/backfilled writes and cannot reconstruct label-token or cascade-delete primitives.

- `g.IO().Watermark() (io.Cursor, error)` — the graph's current change-log point. `io.Cursor{LSN, Epoch}` is opaque, value-comparable, and msgpack/JSON round-trippable. `Epoch` is a durable per-graph lineage id (`meta/graph_epoch`); a cursor from a different graph is rejected (`ErrCursorUnknown`) rather than producing a wrong delta. Declines with a wrapped `store.ErrCapabilityNotSupported` when no change-log is active.
- `g.IO().ExportSince(w io.Writer, since io.Cursor) error` — writes a DELTA stream (delta header, full token registry, then one verbatim change record per committed mutation after `since`), produced under the export write lock against one consistent point. `ErrCursorUnknown` when `since` is from another graph or ahead of the log (caller falls back to a full `Export`); `ErrNilWriter` on a nil writer.
- `g.IO().ImportMerge(r io.Reader, opts io.MergeOptions) error` — merges a delta onto a base, reproducing the source's rows VERBATIM through the replica-apply doors (per-record hash recompute-and-compare + full hash-chain verification of every touched entity; the registry is append-only merged). Does NOT require an empty target. Idempotent (re-applying the same or an overlapping delta is a no-op). `MergeOptions{StagingDir, MaxStagedBytes, ExpectBase, Strict}`: `ExpectBase` asserts the delta's `From` cursor (`ErrDeltaBaseMismatch` on disorder); `Strict` rejects an update/tombstone for an entity absent from the base (`ErrDeltaBaseMismatch`). Any failure rolls the touched subgraph back to its pre-merge state. Rejects a full (non-delta) stream with `ErrIncompatibleExport` (use `Import`).
- `io.HeaderOf(r io.Reader) (io.DeltaHeader, error)` — decodes only the leading header record (no entity/change records consumed). `DeltaHeader{Version, IsDelta, From, To, ExportedAt, NodeCount, RelCount}`. For a full export, `To = {SnapshotLSN, Epoch}` — the complete, gapless base cursor for the first delta in a chain. `ErrCorruptExport` if the first record is not a header; `ErrIncompatibleExport` on an unknown version.
- Restore-chain pattern: `Import` the base, then `ImportMerge` each delta in order with `ExpectBase` set to the previous stream's `To` cursor. New sentinels: `ErrCursorUnknown`, `ErrDeltaBaseMismatch` (also re-exported from `pkg/graph`).

**Backups (one-call ergonomics).** Filesystem orchestration over the same wire format — no new format; every backup file is byte-for-byte what `Export`/`ExportSince` produce and is a valid `Import` source on its own. See persistence.md's "Backups (one-call ergonomics)" for the naming and chain-validation rules.

- `g.IO().BackupTo(dir string) (io.Cursor, error)` — writes a full export to `dir/backup-<LSN>-full.tkg` (`<LSN>` = the stream's own `DeltaHeader.To.LSN`, zero-padded to 20 digits so a directory listing sorts in chain order), fsync'd before returning. Refuses to overwrite: an existing target filename returns `ErrBackupExists` and leaves `dir` untouched.
- `g.IO().BackupDeltaTo(dir string, since io.Cursor) (io.Cursor, error)` — the `ExportSince` counterpart, writing `dir/backup-<sinceLSN>-to-<toLSN>-delta.tkg`. An empty delta writes NO file and returns `since` unchanged; a backend with no active change-log declines exactly like `ExportSince` (wrapped `store.ErrCapabilityNotSupported`).
- `graph.RestoreInto(cfg Config, dir string) (*Graph, error)` (package-level, not on the sub-API) — opens a graph from `cfg`, discovers exactly one full backup plus zero or more deltas in `dir`, validates the WHOLE chain is gapless from the file headers alone before replaying anything, then replays `Import` + each `ImportMerge` oldest-first. A foreign lineage fails closed with a wrapped `ErrCursorUnknown`, an LSN gap with a wrapped `ErrDeltaBaseMismatch` — both naming the offending file. On any failure it closes what it opened.

### Admin & Tier (`g.Admin`, `g.Tier`; the shard-management methods below are `g.Tier()` and `tiered.Store`-only)

- `tiered.Config.AdjacencyIndexOnDisk` (default false; row 95): every shard (reference, archive, hot, warm, rotation-created, lazily opened cold) opens with `badger.Config.AdjacencyIndexOnDisk`, so adjacency reads come from the persisted out/in keys and an open shard keeps no per-node adjacency maps, builds none transiently at open and seeds no relationship revisions. Per-rel RAM maps of an open shard at one rel per endpoint: 566 → 47 B/rel (200 K rels; what remains is the relationship ID set and the type index, `BenchmarkR3OpenShardFootprint`). Read cost on the hot shard, `OutgoingRelationships` of a 10-rel node: 0.6 µs maps vs 2.3 µs with 0 pending writes, 10.5 µs at 1 K, 87 µs at 10 K, 1.6 ms at 99 K (the pending buffer is scanned per read; `BenchmarkR3HotAdjacencyReadPending`). A relationship's first replace or delete after open reads its row once. Fixed per open, not persisted: reopen without it to get the maps back.

- `g.Tier().Archive(id)` / `Restore(id)` — move a reference node between the reference shard and archive, migrating relationship placement for self-loop, ref-ref, and ref-event edges (under `g.mu.Lock`). Destination node and relationship placement collisions are rejected before the temporary destination node is written.
- `tiered.Config.RelsByMint` (opt-in, default off; row 94): a relationship whose endpoints both live on the reference shard is written, entity and both adjacency legs, to the event shard of its ID's mint instant, so a cold shard's close frees its edges from RAM. By-ID reads, history and the change log are unchanged (one record per rel); `ListShards` counts the rel under that shard. A cold mint shard places the rel on the reference shard instead, counted by `tiered.Store.RelsByMintFallbacks()`. The option steers writes per open; the first open with it sets a sticky marker on the reference shard, from then on adjacency reads of a reference or archive node (`Outgoing`/`Incoming`/`Degree`/`ForNodes`) unite the node shard's legs with the event shards' and honour `QueryOpts.Depth`: `DepthAll` (default) opens cold shards (within `MaxOpenColdShards`), `DepthWarm` reads hot + warm, `DepthHot` hot only. The depth reaches the store through `g.Rels().ForEachAdjacentRelAt` / `ForEachAdjacentEndpointAt` (`store.AdjacencyDepthCapability`: `Outgoing`/`IncomingRelationshipsByDepth`, `ForEachExAdjacentRelIDByDepth`; tiered also has `Outgoing`/`IncomingDegreeByDepth` and `…ForNodesByDepth`); the doors without `QueryOpts` read every tier. `DeleteNode` / `DeleteNodesBatch` refuse a node with such a rel on any tier (`ErrInvalidStoreMutation`), `DeleteNodeWithHistory` cascades over them. Enabling it on an existing store needs no migration; old rels stay on the reference shard.
- `g.Tier().ForceRotate()` — transactional hot-shard rotation: opens the new shard + temporal indexes, snapshots the catalog, mutates catalog in-memory, persists; on Save failure, restores the catalog snapshot, closes + removes the new shard, returns the error (R2-F2).
- `g.Tier().ListShards()` — `[]ShardInfo` with live counts (under `g.mu.RLock`).
- `g.Tier().RebuildCatalog()` — reconstruct the shard catalog from live state (under `g.mu.Lock`).
- `g.Tier().Repair()` — scan + fix cross-shard split-write inconsistencies (under `g.mu.Lock`, R2-F1).
- `g.Tier().VerifyShard(name)` — hash chain verification with immutable-shard caching under the graph write lock. `tx.VerifyShard(name)` is the transaction-scoped variant for code already running under `g.Tx`.
- `g.Admin().Reset()` — clears all entities, indexes, history, counters, named as-of tags, unique constraints, and the history-compaction watermark; preserves registries (and the external `id_slot_lease` hint) and checkpoints the preserved registry snapshot after the backing `store.Clear`. Works on every backend, but is GATED: the graph must be opened with `Config.AllowReset`, otherwise the call returns `ErrResetDisabled` without writing — a whole-graph destructive wipe must be explicitly opted into, mirroring `AllowRetentionPurge` (BACKLOG 13d).
- `g.Admin().ResolveExactErasure(ctx, admin.ExactErasureRequest{NodeIDs, RelationshipIDs, Bounds}) (admin.ExactErasureResolution, error)` and `g.Admin().ExactErase(...) (admin.ExactErasureReceipt, error)` — opt-in (`Config.AllowExactErasure`) plan/execute legal-erasure doors implemented by the native memory and Badger stores. Resolution canonicalizes the caller IDs and returns a canonical `Request` expanded with every relationship identity whose current row or any temporal version references a declared node. It separately returns `EndpointNodeIDs` and `RelationshipBindings` (resolved type, start/end identities, version, and integrity hash) so a semantic owner can classify source-owned versus shared/external historical endpoints without treating discovery as deletion. Explicit relationship-identity, globally scanned-version, and endpoint-identity bounds make that proof finite. The caller persists `resolution.Request` only after applying its own endpoint ownership policy. Execution recomputes the same historical relationship closure under backend write exclusion and fails before mutation if the sealed request omitted an identity (`ErrExactErasureRelationshipEscape`) or any bound is exhausted (`ErrExactErasureClosureLimit`); it never silently widens a stored receipt. It hard-removes current rows, complete node/relationship histories, every current secondary-index/temporal-membership/cache residue, UniqueForever ownership values, and per-entity compaction stubs without graph tombstones or change records. The SHA-256 request receipt and declared counts stay stable across idempotent retries. It also refuses if the change-log is enabled or any buffered/scoped/persisted record remains (`ErrExactErasureChangeLogRetained`), because change records contain complete historical payloads. The receipt covers the graph-store operation; external exports, backups, replicas, and storage-media sanitization remain the deployment's responsibility. Badger key deletion carries IDs only (no property payload), while obsolete encrypted/LSM media blocks follow the database's compaction and key-retirement lifecycle.
- `g.Admin().IsReferenceLabel(label string) (bool, error)` (row 99) — whether `label` is reference-class, i.e. whether a read bounded by `QueryOpts.Depth` (`DepthHot`, `DepthWarm`) still sees every node of it. On tiered it is the router's own classifier, the one that routes writes and decides unique-constraint support: the names in `tiered.Config.RefLabels` are true, every other label (seen or not, case-sensitive) is false, as its nodes live on time shards. On memory, badger and sharded it is true for every label: they have no time shards, so every depth sees every node. A blank label is `ErrEmptyName`, a closed graph `ErrGraphClosed`.
- `g.Admin().DecomposeNodeID(id types.NodeID)` / `g.Admin().DecomposeRelID(id types.RelID)` → `IDComponents{CreatedAt, NodeID, Sequence}` — works with any store type.

#### History retention & compaction (ADR-0001)

- `g.Admin().CompactHistoryNodes(ctx, policy RetentionPolicy) (CompactReport, error)` / `g.Admin().CompactHistoryRels(ctx, policy)` — trim an entity's OLDEST version-history rows, keeping the newest belief, and record a per-entity detached-anchor stub. `RetentionPolicy{KeepVersions int, KeepSince types.Instant}`: a history version is trimmable only when it fails BOTH bounds (neither among the newest `KeepVersions` nor recorded at/after `KeepSince`). The current row and the newest history version are never trimmable. `CompactReport{EntitiesCompacted, VersionsTrimmed, Watermark}`.
  - **Chain integrity**: the stub is a virtual predecessor — `VerifyNodeChain` / `VerifyRelChain` require the oldest kept version's `PrevHash` to equal the stub's `LastTrimmedHash`. The stub carries a self-hash (`SafeUnmarshal` on read, fail-closed on corruption or self-hash mismatch), so a forged truncation is caught. No stored row is ever mutated (append-only).
  - **Answerability**: a temporal read whose transaction-time pin falls before compacted knowledge returns `ErrHistoryCompacted`, never a silently-incomplete result. Point doors (`NodeAsOf` / `NodeAtTx` / rel mirrors) check per entity; scan doors (`NodesAsOf` / `ByLabel` / `ByType` with `TxAt` / `TxPin`) check the graph watermark (`CompactedThroughTx` = max over stubs, durable in MetaKV, reloaded at open) and fail the whole scan.
  - **Refusals** (no history trimmed): `ErrInvalidRetentionPolicy` (empty/negative policy), `ErrCompactionProtectedTag` (a registered as-of tag pins knowledge the policy would trim — remove the tag first), `ErrCompactionChangeLogEnabled` (compaction records / replica apply / delta interplay land later, so compaction is refused while the change-log is on). Rejected on a read-only replica; declines with `ErrCapabilityNotSupported` on the tiered backend (memory + badger only).

#### Retention purge (ADR-0008 R2)

- `g.Admin().PurgeExpiredNodes(ctx, policy PurgePolicy) (PurgeReport, error)` — hard-removes aged-out nodes of `policy.Label` below `policy.Before`, with each node's edges, indexes, and full history and NO tombstones. `PurgePolicy{Label string, Mode PurgeMode, Before types.Instant}`: `PurgeByAge` (the v1 default) purges by the node's IMMUTABLE snowflake mint-time — a contiguous key range, so a sequential scan-and-delete rather than N point lookups; `PurgeByValidTo` (R5) purges nodes whose current-version validity ENDED before `Before` (`ValidTo != 0 && ValidTo < Before`; an open interval is never purged, and because `ValidTo` is mutable the store re-confirms the predicate under its write lock per node). `PurgeReport{NodesPurged, RelsPurged, Watermark}`. Idempotent and resumable; chunked so the graph lock is never held across the whole range.
- Gated and fail-closed: requires `Config.AllowRetentionPurge` (`ErrRetentionPurgeDisabled` otherwise), refuses while the change-log is enabled unless the store can emit the `ChangeRangePurge` predicate record (`ErrRetentionPurgeChangeLogEnabled`), and rejects a policy missing `Label`, carrying a non-positive `Before`, or naming an unsupported `Mode` (`ErrInvalidPurgePolicy`). Backed by `store.RetentionPurgeCapability` — memory, badger, tiered, and sharded all implement it (BACKLOG 1 / ex-ADR-0008 R2–R5, including the tiered O(1) cold-shard-drop path).
- The purge advances a per-label retention watermark, so a later temporal read pinned below the boundary fails closed with `ErrRetentionExpired` instead of returning a silently-incomplete answer.
- The node purge waits for an open `GraphTx` before each chunk (a rollback restores the transaction's pre-images, so a node purged under it would make the rollback fail), and the as-of column cache is invalidated after the rows are removed, not before (backlog 21).

#### Relationship retention purge (backlog 21)

- `g.Admin().PurgeExpiredRels(ctx, policy RelPurgePolicy) (RelPurgeReport, error)` — hard-removes the relationships of `policy.Type` whose IMMUTABLE snowflake mint time is strictly before `policy.Before`, live AND ended (deleted, deleted at a caller instant, cascade-ended, retracted, re-imported lives): the row, both adjacency legs, the ex-adjacency legs of every row, the type/property/temporal index entries, the counters, the sidecars and the whole history including the tombstone, with NO tombstones written. Nodes are never touched (a node purge still removes its nodes' relationships). `RelPurgePolicy{Type string, Mode PurgeMode, Before types.Instant}`: only `PurgeByAge`; `PurgeByValidTo` is refused with `ErrInvalidPurgePolicy` in this cut. `RelPurgeReport{RelsPurged, Watermark}`: every relationship removed, live or ended, and the type's watermark after the run (0 for a type that was never registered).
- Same gates and order as `PurgeExpiredNodes`: `Config.AllowRetentionPurge` (`ErrRetentionPurgeDisabled`), not on a read-only replica (`ErrReadOnlyReplica`), a policy with a `Type`, a positive `Before` and `PurgeByAge` (`ErrInvalidPurgePolicy`), a store with `store.RelRetentionPurgeCapability` (`ErrCapabilityNotSupported`; memory, badger, sharded and tiered all implement it). An unknown type is a no-op that registers nothing. The type's watermark is written first, then ONE `ChangeRelRangePurge` record (tag 14) when the change-log is on, then 256-relationship chunks, each waiting for an open `GraphTx`; idempotent and resumable (a rerun finishes a cancelled or crashed purge). Do not call it while holding an open transaction in the same goroutine (like `Batch.Execute`, it would wait for that transaction).
- Per-type gate: the purge advances the watermark of its TYPE only (`retention_rel_watermark/<type token>`, max-monotonic, and `retention_rel_max_watermark`), never the node one. A read pinned below it fails closed with `ErrRetentionExpired` when it covers that type: `ByType` / `ForEachByType` / `ByTypeAndProperty` / the range and prefix doors / `CountByTypeAt` / `ScanRelColumns` / `ForEachRelEffectiveByType(From)` / the typed adjacency doors of that type; the all-types doors (`Rels().All` / `ForEach`, `RelsAsOf`, `ForEachRelEffective`, untyped adjacency) below the max over types; the point doors (`RelAsOf`, `RelAtTx`, `RelEffectiveTimeline`, `RelsEffectiveByIDs`) when the relationship's type was purged above the pin or the relationship is gone. Reads of other types and every node read are answered, so a purge of raw `EVENT` relationships never fails an `Overview` node or an `OV_PAIR` relationship read. The relationship doors that had no retention gate (`RelsAt`, `RelsDuring`, `RelsRelating`, `RelsByTypePropertyAt` / `During`, `RelsAtTx`, `RelsDuringTx`, `NeighborsAt`, `Outgoing` / `IncomingRelsAt`, `Snapshot`, `Diff` / `DiffCallback` with relationship handlers, `Outgoing` / `IncomingForNodesAtTx` / `AtPin`, and their `GraphTx` mirrors) now check the relationship watermarks; their node-purge behaviour is unchanged. `Admin().Reset` clears the relationship watermarks; an export carries both watermark families and an import (replica bootstrap) applies the relationship ones, and the node ones with the opt-in `ImportOptions.ApplyNodeRetention` (off by default: ignored, as before). A replica re-runs the tag-14 predicate on its own state, advances its own type watermark and emits nothing; an older binary stops at the unknown tag, so upgrade replicas first, and an older binary ignores the relationship watermarks, so do not downgrade after the first relationship purge.

Non-tiered backends return `ErrNotTieredStore` from the seven tiered-only methods.

### Migration

- `tiered.MigrateFromBadger(src *badger.Store, dst *tiered.Store) error` — copy all entities from a single badger.Store to an empty tiered.Store with automatic ontology-based routing. Source label and relationship-type registries are loaded from `src`; migrated entity tokens and relationship endpoints are preflighted against the source data; registries are saved to `dst` after a successful copy. Failures roll back inserted destination entities, restore the previous ontology registry, and restore or remove the destination registry file to match its pre-migration state. Nil stores, non-empty destinations, and missing source registry metadata for non-empty data return `ErrInvalidStoreMutation`; closed stores return `ErrStoreClosed`.
- `ontology.OntologyMapping` — nil receivers behave like an empty mapping: `ClassifyByName` / `ClassifyByToken` return `ClassEvent`, `SetLabelRegistry` returns nil, and `RefLabels` returns nil.

### Sharded store (EXPERIMENTAL — ADR-0007, `pkg/graph/store/sharded`)

- `sharded.New(sharded.Config) (*sharded.Store, error)` — a slot-topology `store.Store` over N `badger.Store` shards, one per snowflake SLOT, routing every entity by the slot in its ID's node field (`shardFor(id)`, an O(1) pure function — never by ontology class, that is tiered's job). `Config{Dir, InMemory, BaseSlot, SlotCount (1..32, BaseSlot+SlotCount<=32), ChangeLog, + per-shard badger passthroughs}`. Satisfies the full `store.MandatoryStore` contract plus S5 index/stats parity (property, rel-property, composite + introspection, temporal, high-frequency, vector + filtered/options, type-class + property-key stats, range-cardinality; since v4.43 DocValues columns — `ForEachDocValues`, `ForEachDocValuesMulti`, `DocValuesSnapshot` with `Len`/`RowAt`, `NodeLabelMutationEpoch` — and relationship type-class counts) by fanning DDL to every shard and folding per-shard results on read; the change-log (`Config.ChangeLog`, S3) is a store-global total LSN order with topology-independent replica convergence.
- **Slot claiming is the consumer's responsibility.** With the legacy dual-generator ID model (`Config.IngestLanes == 0`) nodes mint on slot `SnowflakeNodeID*2` and rels on `*2+1`, so a graph-level deployment must claim BOTH — e.g. `graph.New(Config{SnowflakeNodeID: 0, Store: sharded.New(sharded.Config{BaseSlot: 0, SlotCount: 2, ...})})`. With `IngestLanes > 0` (S4 concurrent-ingest parallelism), claim the interactive pair AND every lane slot (`SnowflakeNodeID=0` + `IngestLanes=4` → slots {0,1} interactive + {2,3,4,5} lanes → `BaseSlot:0, SlotCount:6`). An ID whose slot is unclaimed fails closed with `store.ErrSlotNotLocal`.
- **Fail-closed opens.** `ErrCatalogConflict` on a config/catalog mismatch (wrong `SlotCount`, missing mapped shard dir), `ErrCatalogCorrupt` on a tampered catalog blob. Batched doors are atomic per shard group and surface a typed `*sharded.PartialBatchError{Op, CommittedShards, FailedShard, Err}` on a mid-sequence failure (never a silent cross-shard partial); `sharded.Store.VerifyConsistency() (Report, error)` is a read-only no-repair scan for the dangling references a non-atomic cascade/split-write can leave (`AdjacencyOrphans`, `RelEndpointOrphans`, `ShardMismatches`; `Report.OK()`/`Total()`).
- **Declined-with-reason** (mirroring tiered): `TransactionTimeQuery`, `HistoryRollbackTrim`, `LabelTx`/`RelTypeTx` membership, and the depth-iteration accelerators return `ErrCapabilityNotSupported`. S1–S5 are implemented; the surface remains EXPERIMENTAL per `docs/stability.md`. See the ADR-0007 design block above `sharded.Config` in `pkg/graph/store/sharded/sharded.go` and the architecture.md `sharded.Store` section.

### Validation limits

- `Config.Validation` accepts `ValidationLimits{MaxLabelsPerNode, MaxPropertiesPerEntity, MaxPropertyKeyLength, MaxPropertyValueSize, MaxPropertyContainerLength, MaxNameLength, AllowSelfLoops}`. Defaults: 50 / 1000 / 256 / 65536 / 100000 / 256 / false. `MaxNameLength` is enforced by graph mutation/query/index/temporal target validation, by internal registry allocation on first use of a label or relationship type, and by `IO.Import` / graph construction before accepting registry mappings from serialized or persisted data; boolean lookup helpers (`Nodes.HasLabel`, `Rels.HasType`) fail closed for malformed names. `MaxPropertyValueSize` applies to every string nested inside supported property values (a top-level string, a `[]string` element, or a `map[string]string`/`map[string]any` key/string-value) — it does NOT bound a container's element count. `MaxPropertyContainerLength` bounds the aggregate element/entry count of a slice- or map-typed property value (`[]int`/`[]int64`/`[]float32`/`[]float64`/`[]bool`/`[]any`/`map[string]string`/`map[string]any`), or the byte length of a `[]byte` — a separate knob from `MaxPropertyValueSize` so a legitimate large numeric container (e.g. a vector-index embedding) isn't bound by a string-length-scaled limit; `[]string`'s own element count is intentionally NOT governed by this field (only its per-element string length, via `MaxPropertyValueSize`). `MaxPropertiesPerEntity` is enforced by create, update, import, and node/relationship property CAS paths after the final mutation shape is known. `AllowSelfLoops=false` causes `g.Rels().Add` and `g.Rels().Import` to reject self-loops with `ErrSelfLoop`. Zero values use defaults.

### Lifecycle

- `g.Close() error` — saves registries again (badger.Store / tiered.Store), then calls `store.Close()`. Successful token-creating operations already persist registries before returning; the close-time save is a final idempotent checkpoint. `tiered.Store.Close()` saves catalog and closes all event shards plus the reference shard and archive. Idempotent — safe to call multiple times. Nil concrete in-tree Store receivers return `ErrNilStore` from `Close` and `Clear`.
- After `Close`, error-returning sub-APIs that touch store, registry, index, IO, admin, stats, hash, tx, or batch state return `ErrGraphClosed`. No-error state mutators are no-ops after close; `Nodes.NextID` and `Rels.NextID` return `0`.
